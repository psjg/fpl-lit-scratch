The server is `01-bootstrap/ide/lsp.py` (pygls). It publishes the interpreter's own refusal as a
diagnostic and serves semantic tokens (function and parameter, declaration or use). The launcher
`01-bootstrap/ide/fpl-ls` needs only `uv`; it installs pygls on first use. Where the server comes
from and why it is thin: [editor tooling note](../02.04-explanation/inspiration/02.04.04-editor-tooling.md).

## Neovim 0.11 or newer (checked)

Checked with Neovim 0.12.5 headless: opening a file holding `[ 1 2` gives one diagnostic,
`[ never closed`, from source `fpl`. Put this in `init.lua` and use your own checkout path:

```lua
vim.filetype.add({ extension = { fpl = 'fpl' } })
vim.lsp.config('fpl', {
  cmd = { '/path/to/fpl/01-bootstrap/ide/fpl-ls' },
  filetypes = { 'fpl' },
  root_markers = { '.git' },
})
vim.lsp.enable('fpl')
```

Semantic tokens are on by default; give the groups `@lsp.type.function.fpl` and
`@lsp.type.parameter.fpl` colours in your scheme. Tree-sitter highlighting needs the parser built:
`tree-sitter generate` in `01-bootstrap/ide/tree-sitter-fpl`, then register that directory with
nvim-treesitter (not checked).

## VS Code (not checked here)

There is no settings-only way to start a stdio server, so `01-bootstrap/ide/vscode-fpl/` is a
fifteen-line extension: it registers the language, the TextMate grammar and a `LanguageClient`.

```bash
cd 01-bootstrap/ide/vscode-fpl && npm install && code --extensionDevelopmentPath=$PWD
```

Then set `fpl.server` in the settings to the absolute path of `fpl-ls` and open a `.fpl` file.
TextMate highlighting works without the server.

## What can be added, and what it costs

All of these are one function over the data `ide/analysis.py` already has (definitions with their
stack effect and block range, tokens, the parse). The browser playground already has hover,
go to definition, completion and rename over the same functions (`assets/fpl-service.js`); the
server does not yet expose them. Costs are estimates (priors), in agent-hours of work and
review.

| Feature | State | Cost |
| --- | --- | --- |
| Hover with the stack effect | done in the playground (`analysis.hover`) | 1 h to expose in pygls |
| Go to definition | done (`analysis.goto`): definitions and parameters | 1 h to expose |
| Completion of names in scope | done (`analysis.complete`); builtins missing | 1 h to expose; 2 h for builtins |
| Rename | done (`analysis.rename`), within the program | 1 h to expose; across files needs the mount tree, a day |
| Hover with the inferred type | needs `types.elaborate` per definition, returning its result by name | half a day |
| Fuel and cost inlay hints | needs `driver.stacks(..., spent=...)` per run line, which exists; the cost is running the program on every edit, so debounce and a fuel cap | half a day |
| Code lens "run this cell" | a lens per run line, the command calls `driver.run` on the prefix | half a day |
| Keep symbols after a parse error | today a refusal empties hover and completion; cache the last good analysis per document | 2 h |
| Incremental parsing | needs the tree-sitter parser behind the server instead of Lark | a day, and a second parser to keep in step |
