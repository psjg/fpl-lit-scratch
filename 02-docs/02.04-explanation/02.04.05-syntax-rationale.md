# 02.04.05 2026-09-27 — Why the syntax is the way it is

The surface is a postfix language whose one carrier is the nested array, whose one composition
operator is catenation `,`, and whose one quotation operator is enclose `⊂`; evaluation is a fold
of `apply` over a token array with the stack as accumulator. It fills an empty cell in the
parsimony taxonomy: concatenative, array-oriented and homoiconic at once, which no existing
language has together. The substrate ([substrate](02.04.04-substrate.md)) was designed without a
syntax and the syntax without a type-theoretic core; each answers open questions the other left.
This page records the points where they coincide, where they conflict, what the combination
yielded, and the verdicts that fixed the notation. The grammar itself is in
[grammar](../02.03-reference/02.03.02-grammar.md); the on-disk and exchange formats are
[FON](../02.03-reference/02.03.03-fon.md), [FML](../02.03-reference/02.03.04-fml.md) and
[SHAR](../02.03-reference/02.03.05-shar.md); how it feels to type and read is
[UI](02.04.06-ui.md).

Conventions: *core* is the polarised call-by-push-value calculus with grades and capabilities;
*surface* the postfix notation; *frame* and *saturation* are the syntax's terms; a *tier* is a
rung of the integration ladder (types and proofs; tests on the same definitions; data through the
document; files on disk).

## 1 The syntax in one page

| Construct | Rule | Consequence |
| --- | --- | --- |
| Line | a flat postfix program, left to right | juxtaposition is composition |
| Indented block | a quotation pushed *before* its head line runs (post-order) | the off-side rule is the only nesting delimiter; `[ ]` is the inline form |
| Frame (`\|`-segment or indented block) | runs on its own local stack; only literals strand inside it, names never | `1 \| 1 2 3 +` gives `2 3 4` |
| Saturation | a frame with no missing argument is evaluated and its value pushed; an unsaturated frame is pushed as a quotation | value vs function decided by arity, statically (fixed valence per glyph makes arity a running sum) |
| Underflow | a word missing an argument suspends the frame into a section, never errors | `1 -` is x ↦ x−1 |
| `:` head | defines a word, inlines its body lines, takes the rest of the line as the stack effect `xs -- ys` | every other head word receives its children as quotations |
| `→x` | pops into a lexical local; the off-side tree is the scope | the only binder; hygiene reduces to gensym for `→x` |
| `_` | a hole with an unknown stack effect solved from both sides | elaboration reports the missing effect |
| `∈`, `⊢`, `⊨` | ascription (types and refinements), proof lines as tactic scripts, run-time contracts | three verification rungs in one notation |
| `( )` | reader op: rotate the head to the end, bar-separate the arguments, fixed arity | temporary prefix, spliced, no quotation |
| Paths `a/b/c` | a strand of keys walked by deep indexing; the dictionary is a directory (`mean/doc`, `mean/effect`, `mean/proof`); a head line ending in `/` mounts its children; `bind` union-mounts | mention is use: `mean` runs, `mean/doc` pushes, `p/norm` sends |
| `..` | the enclosing scope, which is the capability that produced this one | no ambient dictionary; a frame names only what was bound into it or its ancestors |
| `¨` over code | a macro is an ordinary each over a token array | no macro system, no quasiquote |
| `env`, `reify`, `reflect`, `lift` | the dictionary as a value; evaluator state readable at `/proc/self/{stack,ns,rest}` | a navigable reflective tower (now behind `../meta`, see section 3) |

element-level laziness. The syntax document listed as open: effects and IO, failure,
exhaustiveness of `@.`, ad hoc polymorphism, the mutation model, ragged carrier vs flat fast path,
concurrency, strings, FFI, the numeric tower. Each now has an answer below or in a topic page.

## 2 Where the substrate and the syntax coincide

On five points the syntax is not merely compatible with the core but a more direct notation for it
than a term language would be.

1. **Polarity is arity.** Call-by-push-value splits values (positive) from computations (negative); a computation of type `A → B` expects an `A` on top of the stack. The saturation rule is that split, decided by counting: a saturated frame is evaluated and its value pushed (`F A`), an unsaturated one is pushed as a quotation (`A → B`). The bar `x | frame` is Levy's push. The substrate's "call-by-value by default, laziness surfaces a thunk" is replaced: **saturation decides polarity** and no default is needed. Fixed valence makes it a running sum over tokens, so implicit polarisation costs no inference.
2. **Grades are two words.** Every word is linear on its stack effect except `dup`, `over` (duplicate) and `drop` (discard). The whole semiring apparatus appears at three sites: `dup` and `over` require grade ω or a copyable type; `drop` requires an affine grade; on a unique value `dup` and `over` are type errors. No annotation is written; the stack effect is the grade. This answers the aliasing objection in one rule, and the BCI/BCK/SK split of the combinators sorts by the same grades ([numbers and library](02.04.13-numbers-ml-library.md)).
3. **Capabilities are reached by path, used on the stack.** `..` is "the enclosing scope, which is the capability that produced this one"; "a frame names only what was bound into it or its ancestors" is the absence of ambient authority. The syntax's open *effects and IO* item closes without Kitten-style permission rows: rows are static annotations with no handler search, but a row is not a *value*, so it cannot be delegated, attenuated, sealed or revoked, and it merges input and output into one `IO`. `print` takes an `out` capability found lexically as `../out/console` and consumed on the stack; a reader takes an `in` capability; the two are never one. Paths give *access*, the stack gives *use*. See [capabilities](02.04.08-capabilities-effects-failure.md).
4. **Content addressing on token arrays is almost free.** A program is an array of tokens with two kinds of names, `→x` locals and paths; hashing modulo alpha is hashing modulo `→x` renaming. `once` is memoisation keyed by hash. The three reference kinds map directly: a quotation literal refers by content, a path by petname resolved through identity, a hash literal by hash ([identifiers](02.04.10-history-store-distribution.md)).
5. **Holes are stack effects solved from both sides.** `_` with an unknown effect is the elaborator's metavariable, and on a stack its type is a row-polymorphic stack function, which is CBPV's "rest of the stack". `dip` is untypeable without the row variable for the same reason CBPV keeps the stack explicit.

Smaller coincidences: "elaboration over a stack carrier" is the elaborator node B0 on the
critical path ([elaborate](../../01-bootstrap/01.02-pass/01.02.06-elaborate.md)); `⊨`, refinement
and `⊢` are the verification ladder with the gradual boundary still to be written into the syntax
([contracts](02.04.11-contracts-cost-totality.md)); `nats` as `value ⋈ [next]` is codata checked by
productivity; the `( )` rotation is a level-1 (staging) operation on quoted code.

## 3 Where they conflict

Four conflicts; the first is structural, the other three are decisions the syntax left open and
the substrate answered.

1. **`[ ]` is two things, and that is the fexpr trap.** A quotation is at once a *thunk* (pushed, run with `!`, CBPV's `U B`) and *code* (inspected by `¨`, received unevaluated by operatives, rotated by `( )`). Wand (1998): if every call can inspect its operands as syntax, no two quotations are ever equal and nothing can be proved statically. The substrate requires `U` (an opaque frozen computation) and `quote` (inspectable syntax at the meta level) to be different types under one notation. `lift`, `reify` and `reflect` mutate the evaluator that is executing them, which the substrate forbids at level 0.
2. **`bind` mutates the dictionary.** C6 makes the dictionary the log: `bind` is an ordered append, replayable, and a capability that escapes a frame via `bind` is a logged clock-extent right over an immortal referent. `→x` stays lexical and mortal. Arrays as values (K's rule) is consistent with grades: a copy is a `dup`.
3. **One carrier vs staged carriers.** The syntax wants one K-shaped ragged carrier and admits it costs the flat-memory BLAS path. Staging dissolves it: ragged nested arrays are the live-tier carrier; where shapes are static the residual holds flat unboxed arrays. The carrier is one *type* with two representations chosen by stage; "does shape information reach codegen" becomes a done-when of the first backend.
4. **Dynamic dictionary vs static effects.** Dynamic dispatch (`lookup !` on a non-literal quotation) has unknown arity and requires a declared effect; the substrate adds that such a site is where `div` enters and where reflection may be needed. The dictionary is typed: entries carry effects.

Two smaller frictions: hygiene "reduces to gensym for `→x`" is right for locals, but paths are
names too, and because `..` is the capability chain, path resolution is a scoping question the
expander need not solve; and "mention is use" must respect sealing: mentioning a sealed capability
yields an opaque node, never its contents, including through `reify`.

## 4 What emerges from the combination

Seven mechanisms neither side had alone.

1. **Classification by consumption: stage joins polarity and grade.** A quotation's type is fixed by its consumer: `!` makes it a thunk `U B` at level 0; `¨`, `( )`, `blocks node¨` or catenation onto code make it `Code B` at level 1. Because valence is fixed per glyph this is a static running sum, so one notation carries two types without annotation, and a quotation both forced and inspected in one frame is a type error (Wand's triviality as a compile-time rejection). Arity gives polarity, consumer gives stage, `dup`/`drop` give grade: all from use, none written.
2. **Literals bind by hash, mentions bind by name.** A quotation literal `[ mean ]` captured at definition time refers to the definition as it was (the lockfile reading); a path mention `mean` resolves at run time through the identity to the current petname binding (the Erlang fully-qualified-call reading). Hot loading is visible in the source: what was quoted stays, what was mentioned moves.
3. **Frames are extents.** A capability pushed inside a frame and not returned dies with it, so the frame is the lexical extent of C3 with no annotation. Returning a capability is promotion, explicit because the head line must name it (`-- h`). Escape through `bind` is the clock extent over the immortal dictionary-log. Three extents, three syntactic facts: frame, effect line, `bind`.
4. **Sessions are linear stack items with typestate.** A channel is a linear value whose type names its state: `open : -- h:Open`, `read : h:Open -- h:Open s`, `close : h:Open --`. Linearity forces threading, so word order is the protocol, and a forgotten `close` is a `drop` on a linear value, rejected.
5. **The head line is the interface hash; the body is the implementation hash.** A patch touching only body lines is interface-preserving and transports dependents; a patch to the head line is a real cascade and shows as `_` holes at every dependent. Contracts sit in the interface view (section 6).
6. **Uniqueness gives in-place array updates.** An array on which no `dup` or `over` has occurred is unique, and a rank-polymorphic update on it compiles in place (Perceus reuse). "Sharing is explicit" and "copies are `dup`" are the same sentence.
7. **The verification rung is a directory entry.** `mean/proof` is a tactic-script quotation; `mean/contract` a `⊨` quotation run at run time; `mean/effect` carries the refinement. Presence decides the rung: with a `proof` subtree the contract is erased (grade 0); without it the contract runs with blame at the boundary. The gradual boundary is a lookup, not a mode, and the residual is identical either way.

A consequence of 3 and 5 together: `reify` reading `/proc/self/{stack,ns,rest}` is a view of a log
prefix, so time-travel debugging is `/proc/self/history/<n>` and replay is re-running from a reified
state; the reflective tower and the event log are the same navigable object.

### 5.1 Lambdas, pattern matching, entries and conventions

- **Lambdas (S34).** A lambda is a quotation that begins with binders, `[ →y →x  x y - ]` (Smalltalk and Ruby blocks, Factor's locals); no new syntax; binders pop from the top; capture per reference as S30 (`x` snapshot, `$x` cell); Smalltalk's `^` is `shift` within the frame.
- **Pattern matching (S35).** A pattern is a constructor expression read backwards (`( circle r )` runs `circle` inverse and binds `r`); bare names bind, `_` matches anything, literals match by equality, `$x` matches the current value (Elixir's `^x`); guards are ascriptions in the pattern (`( circle r ∈ pos )`); `match` is the head word and rows are a rank-2 literal (pattern cell, body cell); first match wins, order is meaning; no catch-all means `+fail` inferred; overloading on types is matching on types (`( _ ∈ Int )`), static where known, dynamic with `+fail` declared; `agenda`/`@.` becomes `match`. Matching is one-way unification, the same algorithm as `unify`: outside a space it is first-match and deterministic, inside a space with fresh variables it is two-way with all solutions and the rows are Prolog clauses. Destructuring bind `→( … )` outside `match` is an open two-token form the elaborator joins. See the sketches in section 9.
- **Entries, checks, the caesura, tabs (S45).** `./` is the current scope (bare `/` the root). `require`, `ensure`, `rescue`, `test`, `proof`, `invariant`, `measure` are ordinary prelude macros filing their children as `./name/` of the innermost block, expanded before saturation and printed as the bare word; anonymous blocks get positional paths (`norm/3/ensure`). Check cells: a trailing cell `⊨ q` (check) or `⊢ q` (prove), saturation deciding equality vs predicate, run on a copy of the stack. The caesura `|` is a whitespace-delimited word. Tabs in code are kept as cells (authored alignment); the printer pads by cell kind so checks and comments align; spaces never align. Debugging is probes from outside on paths, no syntax.
- **Conventions (S46, proposed).** Convention over configuration with escape through the same mechanism (bind, mount); only grammar and printer law are strict. Proposed: `main`'s effect line is the program's manifest; an exported word without a `;;` doc warns; a naming lint (kebab-case words, PascalCase types, `?` predicates, `#` symbols) warns and renames safely; derived Hungarian as an agent print profile computed from types, never stored. Parked: image layout, Oberon's export mark, growing a corpus for model training.
- **Sketch 8 (head arguments).** A head's arguments are its child lines, in order, then its own tokens, postfix: `[ cos ] d` or the child-line form; `d [ cos ]` on one line is `d` (underflowing, curried) followed by a quotation. Head-first inline is the prefix form `(d [ cos ] [ ⊢ _ ])`. `d` has arity two and an unsaturated `[ cos ] d` is a section.
- **Spellings fixed along the way.** `_` is the hole and `?` is `unwrap` (settled by the maintainer, 2026-09-27; the wording of the hole discipline was updated from `?` to `_`). `∈` for finite domains and ascription, `≐` for posting a constraint (a tell): one glyph, one meaning, no second spelling of an existing concept.

Substrate answers to the open items: (1) *Theories as directories.* A planted tree is a mounted
directory with the reserved entry `seam`; a directory without `seam` is a namespace, with one it is
a theory. `logic/space` runs the word `space` in `logic/`; `logic` pushes the directory;
`logic/seam` pushes the functor (a level-1 value); `logic/seam/kind` gives `faithful not-full`.
(2) *`∨` against grades.* `fresh : -- v +st` pushes an identity of grade ω; `∨´` over a block of
quotation literals fits because the block is a saturated frame. (3) *`space` as a frame boundary:*
quotation literal plus a word of arity one is saturated, so the solutions array is a value on the
core stack; `[ goal ] logic/space : -- solutions +div`, `[ goal ] 100 logic/space : -- solutions`.
(4) *Seam kind as ascription.* `seam ∈ logic -- core` is ordinary ascription; kind words refine
that type; the obligations are `⊢`/`⊨` lines; a seam is `∈` plus the two proof rungs. (5) *Contracts
on handlers:* `⊨ glitch-free` (rung 3) or `⊢ glitch-free` (rung 1), no `contract` word. (6) *The
open case:* `_ [ sorry ]` is exactly the loosening at a point, the hole is the region and the frame
is its extent; a larger loosened region is a named block with the `sorry` capability bound in.
The store effect `+st` is sugar for `+in/store +out/store` on a lexical `../store`
([concurrency and logic](02.04.14-concurrency-logic-search.md)). Not decided on purpose: the
reflection capability's glyph, and whether `..` should be writable (rebinding a parent's capability
from a child is a security decision, not a syntax one). The tower is not simultaneously live
levels: `lift` creates one new stage and the tower exists as history in the log.

### 6.1 The syntax author's answers to the three questions

1. **One notation, two types for `[ ]`: accepted.** Operatives (`if`, `my-if`) receive thunks, never syntax; Kernel's `$vau` is downgraded to unevaluated-but-opaque operands, the right trade given Wand. `:` is the point where level 1 becomes level 0 (macros act on `Code` before `bind` lowers it to `U B`). `code ../meta eval-with` runs `Code` under a new evaluator rather than mutating the running one. The substrate's rider: at level 0 a thunk runs in the environment it was closed over, never one supplied by the caller (an env argument that let `if` run a branch under the caller's scope would be dynamic scope and reopen ambient authority).
2. **`bind` as ordered log append, `→x` the only mortal binder, arrays as values: accepted.** Order is log position, later shadows earlier. Copy-on-write is implementation, not semantics.
3. **Capabilities by path over permission rows: accepted,** with one proposal: keep `+io` on the effect line as sugar for "takes `../io` lexically and threads it linearly" (Clean `*World` and Mercury `io.state` without hand-threading). The substrate accepted the sugar and then split it into `in` and `out`.

## 7 Worked example: a counting file server

Nothing here runs; stack effects were worked by hand. The point is where annotations appear and,
more often, where they do not. The block is in the canonical ASCII spelling of the grammar.

```
;;; ── a counting file server ────────────────────────────────────────
serve : n req -- n resp +in/data	; +in/data: load permission on the data segment, resolved lexically
	req | #path lookup →p	; frame: p lives on this frame's stack; mentioned once below
	../data p index →text	; single-level store: a segment reached by path; no read call, mention is load
	text shape first →size	; text is mentioned once after binding: unique, freed in place
	n 1 + →n
	| #size size pair #count n pair dict	; saturated frame: a value, pushed
	n swap	; stack now matches the head effect

main : -- +in/net +out/net
	../net/in requests →reqs	; the network is a channel, not a segment: `in` is a real operation here
	0 →n
	reqs [ serve ] n \ →responses	; stateful scan: n threaded through the stream, one step per request
	responses ../net/out [reply] each	; `out` on a channel: each response sent; the each fuses with the scan

trace : code -- code	; a macro: an each over a code array (level 1)
	[ #print pair ] each [,] fold

[ serve ] trace →serve/traced	; [ serve ] consumed by trace: Code, level 1
[ serve ] !	; [ serve ] consumed by !: a thunk, level 0
;; [ serve ] dup ! swap trace  — rejected: one quotation both forced and inspected
```

| Line | Core | Which rule |
| --- | --- | --- |
| `serve : n req -- n resp +in/data` | head line is the interface hash; `+in/data` is a load permission on a segment capability reached lexically, part of the interface; `n`, `req`, `resp` at ω | section 5 rows 13 and 25 of [capabilities](02.04.08-capabilities-effects-failure.md) |
| `req \| "path" lookup →p` | a frame is a lexical extent; `→p` is CBPV sequencing on a mortal local; `p` is mentioned once, so it stays linear | frames are extents (section 4.3) |
| `../data p ⊐ →text` | single-level store: `../data` is a segment; indexing it is a load permitted by `+in/data`; no `open`/`read`; `text` carries the segment's integrity label | [history and store](02.04.10-history-store-distribution.md) |
| `text ⍴ ⊑ →size` | `text` is bound and mentioned once: unique; the backend may free or reuse in place | section 4.6 |
| `\| "size" size ⋈ "count" n ⋈ dict` | saturated frame: evaluated, its value pushed, a positive `F Dict` | section 2.1 |
| `main : -- +in/net +out/net` | the network is a channel, not memory: `in` and `out` are real operations with `+fail`, the boundary where single-level store stops | [history](02.04.10-history-store-distribution.md) |
| `reqs [ serve ] n \` | a stateful scan over a codata stream is productive by construction, so no `div` | [totality](02.04.11-contracts-cost-totality.md) |
| `responses ../net/out reply¨` | an `out` capability on a channel: a sink, confidentiality-graded; a `secret`-labelled `text` could not be sent; the each fuses with the scan at staging | [capabilities](02.04.08-capabilities-effects-failure.md) |
| `trace : code -- code` | a level-1 function `Code (A → B) → Code (A → B)` | section 4.1 |
| `[ serve ] trace` / `[ serve ] !` | the same notation is `Code` or `U (…)` depending on its consumer | section 4.1 |
| commented line | both consumers in one frame: type error, not a run-time surprise | section 4.1 |
| `serve/proof` absent | rung 3: `serve/contract` (if any) runs with blame; the residual is unchanged either way | section 4.7 |

After staging, `trace` has run and is gone; paths have resolved to identities and then hashes;
`serve` is first-order code that loads from a segment and `main` is a fused loop over two channel
entry points held as capability arguments; there is no dictionary and no file API at run time.
Annotations the programmer wrote: one head line per word and nothing else, no grade, extent,
polarity or stage. Annotations inferred and shown on request: `text` unique, `[ serve ]` at level 1
or 0, the scan productive, the send low, `serve` free of `+fail`, `main` carrying the channels'
`+fail`.

## 8 Open

In the order a working programmer would hit them:

- **Head lines with children.** A stack-effect discipline for head lines that receive quotations (the `→k` workaround in `shortest-paths`); a child's level (thunk or code) is fixed there too.
- **Classification by consumption across frames.** A quotation returned from a frame and consumed differently by two callers: most likely the level is fixed at its first consumer and a later inconsistent use is an error at that site.
- **The `..` chain and `bind`.** Whether a child may rebind a name its parent bound (shadowing is fine; rebinding the parent's capability is the security question).
- **Paths as names in patches.** A rename is an identity-preserving petname rebinding, never a textual edit.
- **Ragged arrays and shapes in types.** The arrays library must say which shapes are static enough to flatten.
- Concurrency, strings and Unicode, FFI (a capability boundary), the numeric tower have substrate answers but no notation yet.
- Claims for reviewers to attack: the four classifications by consumption as a sound static discipline; "grades are two words" as sufficient for aliasing safety when arrays are values; sessions as typestate against deadlock-freedom results; the head/body interface split against the cascade problem; the worked example against an ergonomic threshold (count its annotations).

Sketches at the conventions of the time (`:` heads, `´` fold, `` ` `` scan, `|` frames,

worked by hand. Glyph spelling is used; both spellings parse under the grammar. Name spelling
(S32): modifiers are words on a quotation (`[+] fold`, `[f] each`, `[f] scan`, `[-] swap-args`,
`[*] self`, `inverse`), APL verbs are English (multiplication excepted: `*` since 2026-10-31, the maintainer's choice over `times`); `∈ ⊢ ⊨` stay as line markers, sigils and pairs

### 9.1 Draft 1: the language in itself

```
read : text -- lines	; each line a depth‿tokens pair
	newline split
	dup  [ tab = [and] scan [+] fold ] each	; depth: leading tabs
	swap [ trim space split ] each	; tokens
	[pair] each

blocks : lines -- blocks	; one block per minimum-depth line: head + its subtree
	dup [first] each dup [min] fold = group

node : block -- code	; children-quotations , head-tokens
	dup 1 skip blocks [node] each [enclose] each
	swap first 1 first ,

tree : lines -- code
	blocks [node] each [,] fold

apply : tok --	; operative: receives thunks, never syntax (combined draft §6.1)
	if
		dup word?
		lookup !

boot : text --
	read tree [apply] fold

trace : code -- code	; a macro: acts on Code before `:` lowers it to a thunk
	[ #print pair ] each [,] fold	; #print: the word as a symbol, not the text

graph	; saturated frame of literals → a 4×4 matrix
	0 3 ∞ 7
	8 0 2 ∞
	5 ∞ 0 1
	2 ∞ ∞ 0

shortest-paths : D -- D
	dup shape first 2 log ceil →k
	k repeat
		dup [min] [+] inner

graph shortest-paths	⊨ ⟨ ⟨ 0 3 5 6 ⟩ ⟨ 5 0 2 3 ⟩ ⟨ 3 6 0 1 ⟩ ⟨ 2 5 7 0 ⟩ ⟩	; checked in Python
[ graph shortest-paths ] trace !
```

### 9.2 Draft 2: the design questions in the syntax

```
;;; ── frames ──
1 | 1 2 3 +	; 2 3 4        literals strand inside a frame; the bar applies across
1 2 3 +	; [1‿2‿3 +]    unsaturated, nothing below: a section
2 | 3 +	; 5
1 | 1 2 3 [-] swap-args	; 1 2 3 - 1    commute fills the right slot from outside

;;; ── currying ──
curry  : x q -- q'	; [x q]        (BQN ⟜)
	swap enclose swap ,
lcurry : x q -- q'	; [x swap q]   (BQN ⊸)
	[ swap ] swap , curry

;;; ── operatives (thunks + env; lift/reify/reflect are stage-creating behind ../meta) ──
my-if : c t --
	swap ! [ ! ] [ drop ] if
when-debug : q --
	../debug [ ! ] [ drop ] if

;;; ── effects, holes, ascription; refinement is ascription ──
mean : xs -- x
	;; Arithmetic mean. Empty input → ∞.
	dup [+] fold swap shape first divide
median : xs -- x
	dup grade pick ?	; goal: ? : sorted -- x, reported by the elaborator; _ would ask it to infer
3 Int ∈

	⊢ unfold grade-perm select-sorted qed
	⊨ sorted

;;; ── the dictionary is a directory; select over it ──
select
	words
	doc “∞” find [or] fold
	name effect
select
	trade
	price 100 >
	sym
	size price wavg

;;; ── constructors run backwards; clauses are an agenda ──
rect   : wh -- shape
	#rect swap pair

	#circle swap pair
area : shape -- a
	unpair swap | #circle #rect index
	| [ dup * π * ] [ [*] fold ] agenda

;;; ── scope follows the tree ──

	→k
	each
		k *
1 2 3 | 2 scale-all	⊨ 2 4 6

(+ 1 2)	⊨ 3	; rotates to 1 | 2 +
(+ (* 2 3) 4)	⊨ 10	; rotates to 2 | 3 * | 4 +
1 2 3 [+] fold	; variadic + is a fold over a strand

;;; ── quasiquote: $ inside a quotation is unquote; $xs each splices (S30) ──
twice : q -- q'	; the code of q, twice
	[ $q each $q each ]
with-log : q -- q'	; wrap a quotation: the value of q spliced as one item
```

### 9.4 Draft 4: pattern matching, one sketch (2026-09-28)

Everything S35–S40 gives in one file: Haskell's shapes (the `match` form and the pattern-in-head
form), Julia/CLOS multimethods (patterns on every argument, typed; `agenda` is not gone, it is
this), list patterns without a star, Prolog's family relations as the same `match` inside a
`space`, Python's keywords as a record pattern in the head, and ABC's keywords as a view. It parses
under the prototype grammar (73 lines, 249 tokens, 27 comments attached); `{ }` was added to the
code grammar for it (`dict` enclosure, indenter-tracked, both printer laws re-verified). A `match`
row is *arity* pattern cells followed by a body cell; an empty body succeeds (a fact).

```
;;;; Pattern matching, one sketch: Haskell shapes, Julia/CLOS multimethods, XDuce-free list patterns,
;;;; Prolog's family, Python's keywords, ABC's keywords — all the same match (S35–S40). Name spelling, tabs.

;;; ── 1. constructors run backwards: a pattern is the inverse of an injective constructor ──
circle : r -- shape
	#circle swap pair
rect : w h -- shape
	#rect swap pair pair

area : shape -- n
	match
		( circle r ∈ pos )	r dup * π *	⊨ 0 >	; guard: an ascription in the pattern, no `when`
		( circle 0 )	0	⊨ 0	; a literal matches by equality
		( rect w h )	w h *	⊨ 0 >=
		_	?	⊢ ?	; wildcard row; its body is a goal the elaborator reports (S40)
	test
		1 circle	π
		3 4 rect	12

;;; ── 2. the same, Haskell's way: the pattern in the head (S37, on the table) ──
perimeter : ( circle r ) -- n
	r τ *
perimeter : ( rect w h ) -- n
	w h + 2 *

;;; ── 3. multiple dispatch (Julia, CLOS): patterns on every argument, typed ──
collide : a b -- outcome
	match
		( _ ∈ Asteroid )	( _ ∈ Ship )	#boom
		( _ ∈ Ship )	( _ ∈ Asteroid )	swap collide	; symmetric case delegates
		( _ ∈ Ship )	( _ ∈ Ship )	#bounce
		_	_	#miss	; catch-all: without it the match is partial and carries +fail
					; static where the types are known (row 23); a dynamic site declares +fail (X20)

;;; ── 4. list patterns without a star: cons is injective, catenation is not (S38) ──
sum : xs -- n
	match
		⟨⟩	0
		( cons x xs )	xs sum x +
zip : xs ys -- ps
	match
		( cons x xs )	( cons y ys )	xs ys zip x y pair cons
		_	_	⟨⟩
contains : x xs -- b
	match
		_	⟨⟩	false
		_	( cons $x _ )	true	; $x: a pinned pattern, matches the current value of x (Elixir's ^x)
		_	( cons _ rest )	x rest contains
lines [ “err.*” regex ] find	; a sequence queried as a whole is a value-level query, where a regex belongs

;;; ── 5. Prolog's family: the same match, inside a space, is two-way unification ──
family/
	parent : x y --	; a relation: two pattern cells, an empty body = succeed
		match
			#tom	#bob
			#bob	#ann
			#bob	#pat
			#pat	#jim
	male : x --
		match
			#tom
			#bob
			#jim
	female : x --
		match
			#ann
			#pat
	mother : x y --
		x y parent  x female
	grandfather : x z --
		fresh →y
		x y parent  y z parent  x male

#pat #jim family/parent	; outside a space: one-way, first match, deterministic; succeeds
[ fresh →g  g #jim family/grandfather  g ] logic/space	⊨ ⟨ #bob ⟩	; inside: fresh g unifies against the rows
[ fresh →c  #bob c family/parent  c ] logic/space	⊨ ⟨ #ann #pat ⟩	; all solutions, not the first

;;; ── 6. Python's keywords: a record pattern in the head is the signature, values are defaults (S39) ──
join : xs { sep “ ” end newline } -- s
	xs sep interleave end ,	; sep and end are bound by the pattern; the caller's record unions over the defaults
words { sep “, ” } join	; under python the printer shows this call as join(words, sep=", ")
[join] { end “” } with →join-flat	; with: curry-with-union; later calls still override

;;; ── 7. ABC's keywords: a view, not a form ──
;; under abc the same ABT prints as a keyword template with holes, JOIN ? WITH ? ENDING ?, and the editor completes from the effect line, not from an LL(1) guess (CWI CS-R9256)
#abc under
words { sep “, ” } join

;;; ── 8. checks, tests and aligned binders (S45) ──
mean : xs -- m
	require
		shape first 0 >
	dup [+] fold	→sum	; xs in the effect line binds nothing (S37); the body finds it on the stack
	shape first	→n
	sum n divide	⊨ n times sum =	; a check sees a copy of the stack: no dup
	test
		⟨ 1 2 3 ⟩	2
		⟨ 4 ⟩	4
```
