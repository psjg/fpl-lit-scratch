Question: can the Lark grammar (`01-bootstrap/fpl/grammar.lark`) give us editor tooling for an
accessible IDE in the playground? Answer per item, with what was built under `01-bootstrap/ide/`.
Research claims marked *prior* were not read from a primary source; the rest cite one.

## Why the grammar alone is thin

**"Derived from the grammar" always means `grammar.lark` and `lex.py` together.** The Lark file gives structure; the shape of a token (sigil, number, path, modifiers) lives in the lexer module `fpl/lex.py`; the bracket set that suspends newlines lives in `FplIndenter` in `fpl/parse.py`. Every generator below reads all three.

The grammar is deliberately structural. Every word is one generic `TOKEN`; the shape of a word
(sigil, number, path, modifiers) is the affix pass in `fpl/lex.py`; strings `“ ”` `「 」` and block
comments `⟦ ⟧` are counted by a pre-lexer, and indentation by Lark's `Indenter`. So "derive from the
grammar" really means "derive from `grammar.lark` plus `lex.py`", and the parts neither holds
(what a word *means*) come from the resolver (`desugar.py`).

## Verdicts

| Item | Derivable | Evidence |
| --- | --- | --- |
| Syntax highlighting | partly | No Lark to TextMate or Monarch converter exists (searched; the nearest, [Monogram](https://github.com/johnsoncodehk/monogram), wants a TypeScript grammar). Monarch and TextMate are regex state machines, not CFGs. Built: terminals read from the grammar through Lark and shapes from `lex.py`; the tokenizer states are hand-written. |
| Semantic highlighting | yes (mechanism), resolver for meaning | [LSP 3.17 semanticTokens](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocument_semanticTokens): legend plus 5-integer relative encoding. A binder vs a use is not in the grammar; `desugar.definition` knows it. |
| LSP server | yes, cheap | [pygls](https://pygls.readthedocs.io/en/latest/) 2.x. Diagnostics are the interpreter's own `FplError(span, message)`; no new analysis. |
| tree-sitter | partly | No converter (searched). `grammar.js` hand-ported (about 70 lines); indentation and counted pairs need an external scanner ([docs](https://tree-sitter.github.io/tree-sitter/creating-parsers/4-external-scanners.html)), about 170 lines of C here (a level stack like Lark's Indenter; run `tree-sitter generate` in `ide/tree-sitter-fpl/` first, `src/parser.c` is not tracked). Frames and cells are not nodes: tree-sitter rules may not match empty, and an empty frame is legal FPL. |

## What was built

- `ide/gen_highlight.py` writes `assets/fpl-language.js` (Monaco Monarch, wired into
  `assets/fpl-playground.js`, language id `fpl`, theme `fpl-dark`) and `ide/fpl.tmLanguage.json`
  (VS Code, Shiki, linguist). Regenerate after changing the grammar or `lex.py`.
- `ide/analysis.py` (diagnostics, semantic tokens, LSP encoding; no LSP dependency, so Pyodide can
  load it) and `ide/lsp.py` (pygls: didOpen/didChange diagnostics, semanticTokens/full).
  `ide/smoke_lsp.py` drives it over stdio.
- `ide/tree-sitter-fpl/` (`grammar.js`, `src/scanner.c`, `queries/highlights.scm`).

## Measurements (31 `.fpl` files under `03-fpl/` and `learn/`)

- TextMate (vscode-textmate, Oniguruma): 13092 non-space characters, 0 left unscoped.
- Monarch (`monarchCompile` of monaco-editor 0.52.2, rules run by a small runner): 0 unclassified;
  per-class counts (848 identifier, 97 sigil, 90 number, 31 path) equal TextMate's. The runner is
  not Monaco's own tokenizer; the browser behaviour is unchecked.
- Lark parses 31 of 31; tree-sitter parses 31 of 31 without ERROR or MISSING with equal word counts
  (`ide/measure_parity.py`). That is weak: it does not compare block structure, and the corpus has
  no two-tab jumps, no islands, no modifier-suffixed numbers. `ide/test_treesitter.py` covers the
  indentation cases (siblings at one level, a dedent to an unopened level refused, a block comment
  line opens no block). Negative controls `[ 1 2` and `a ]` are refused.
- LSP smoke: `[ 1 2` gives `[ never closed`, a good example gives no diagnostics and tokens.
- `pytest ide`: 42 pass (run with `PYTHONPATH=01-bootstrap`, outside the noslop lane, which lints `fpl/` and `tests/` only).
- Review: GPT (`gpt-6.1-sol`) was unavailable (usage limit), so a Claude Sonnet verifier reviewed it; its confirmed findings (line splitting by `\n` only, UTF-16 columns, indentation stack, block-comment line, query order, numbers with modifiers) are fixed.

## Not done, and cost estimates (*prior*)

- Browser LSP: run `ide/analysis.py` in Pyodide behind Monaco providers (about a day); pygls has
  experimental Pyodide support.
- Hover, go to definition, completion: half a day each from `Catalog.resolve`.
- Block comments and strings with `⟨ ⟩` islands are one token in tree-sitter; islands are not parsed.
- Known gaps: Monarch drops `[ ] | ( ) { }` inside a string's `⟨ ⟩` island and TextMate does not nest islands; a bare sigil (`$`, `->`) is `modifier` in `lex.py` but highlighted as a sigil; the corpus cannot see these.
- Monarch tokenizes `;` note continuation lines per line; the multi-line NOTE token is not modelled.
- Recommendation: Monarch plus in-page semantic tokens first; tree-sitter only for incremental or
  structural editing, since it is a second parser to keep in step with Lark.

## Update 2026-10-22: browser, tree-sitter generated, service

- Browser-tested (headless Chrome through playwright-core against the site served locally): the
  Monarch tokens render in the playground; semantic tokens, markers, hover, completion run from
  `analysis.py` under Pyodide (`assets/fpl-service.js`, `ide/pack_analysis.py` builds the zip the
  page unpacks). Screenshots were taken in the session scratchpad. The playground's own `fpl` is the
  tangled walker, the service runs the bootstrap `fpl`: two implementations of one language, so
  hover and diagnostics describe the bootstrap's reading.
- tree-sitter is now generated: `ide/gen_treesitter.py` translates every rule of `grammar.lark`
  (the empty-matching `frame` rewritten to optional uses), reads the terminals, the bracket set and
  the counted pairs from the sources, and fills the tables of `scanner.c.in`. Hand-written left:
  `scanner.c.in` (157 lines: the indentation stack and the line-break protocol), the node names of
  the three counted pairs, and the generator's own translation code (324 lines). `grammar.js` (32
  lines) and `highlights.scm` are fully generated; `--check` fails when they are stale.
- Differential test against Lark, comparing tree shapes (`ide/diff_treesitter.py`): 31 fixtures,
  600 generated programs and 600 one-character mutations. Both accept and agree on shape in every
  case where both accept (31, 490, 487; 0 differences). Acceptance differs only one way: Lark
  refuses and tree-sitter accepts (9 and 22 cases), all `lex.strict` rules the grammar does not
  hold (a space after indentation, a bracket open across a dedent). `tree-sitter test` has a
  12-case corpus.
