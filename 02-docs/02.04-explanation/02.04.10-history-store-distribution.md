# 02.04.10 2026-09-29 — History, store and distribution

C1 and C6 of the [substrate](02.04.04-substrate.md) in detail. v0 is neither a version-control
system nor a document format: it is the **history layer**, a signed, causally ordered, append-only,
replicated, forkable log of typed events with identity (`$`) and content (`&`) and the
deps/links law. Files, packages, the temporal database and the image's persistence are *views* on
that one thing. Kay's word is *medium* (what everything is written on and what keeps every
inscription); Engelbart's is *journal* (NLS's permanent, citable, never-overwritten record). In
documents v0 is the substrate's history layer (the A-layer); "vcs", "format", "package manager",
"filesystem" and "database" name views one word above it. The name of the layer itself is open;
*journal* is proposed as the word one types in a path, *medium* as what it is philosophically.

## 1 Identifiers and sigils

Three reference kinds, three sigils: `&` names bytes (by hash), `$` names what was hashed at birth
(an op, an identity; by identity), `#` names a symbol (by petname). Same alphabet and length,
different referent, and the sigil is the only thing that tells which: that is the guarantee. `$` is
fixed at capture and untouched by later edits because later edits are other events. A definition's
identity is `$` of its birth event; the two-version rule reads: *quoted by `&` keeps the old,
mentioned by `$` or `#` gets the new*; interface and implementation hashes are both `&`. Atoms are
paths under identities: `$⟨event⟩/⟨offset⟩`. Nothing is stored or logged in a short form; a short
mention is an editor affordance resolved with a uniqueness check, and a mention that stops being
unique becomes a hole. `&` references are deps (in the closure), `$` and `#` references are links
(never in the closure); the sigil is the type of the deps/links law.

**Self-describing multihashes in decimal.** An identifier is the sigil, the function code in
decimal, a colon, and the digest as one decimal number without leading zeros: `&30:414210…` for
blake3-256 (multicodec `0x1e` = 30, still marked draft in that table), `&45600:…` for blake2b-256
(`0xb220` = 45600; permanent in the multiformats table). The code fixes the digest length so the
reader restores leading zeros; whitespace ends the identifier. Decimal because tokenisers cut digit
runs into groups of three (measured by the syntax author: 29 tokens per 256-bit identifier against
40 for hex; not repeated). Rules on top:

1. The store keeps raw bytes and the decimal is the canonical *print*; a hex multihash is accepted as alias input, and only in its varint-encoded form (the code is an unsigned varint: 45600 is `a0 e4 02`, so a hex blake2b-256 multihash begins `a0e40220`, not `b22020`).
2. One *current* code per store for new ids; old ids under other codes stay legal because each event's `$` is computed under the function it was born under and parents are referenced by their own self-describing ids, so history is never rehashed; two codes for the same content link only by a signed alias event.
3. A reader refuses an unknown code; a new function is a new code, never "version 2"; identifiers compare whole; deprecated codes are refused for new events but still verified on old ones, and a broken function is answered by re-attesting at a checkpoint under a new one.
4. FPL pins its own code table instead of tracking the multicodec registry.
5. Inline bytes, code `0`: for `&` only, `&0:<length>:<decimal>` with the bytes as one big-endian number, at most 32 bytes.
6. Short forms in editors are unique prefixes of the digest digits.
7. Fixed-width fields may keep 32 raw bytes internally only while a store has a single code; anything signed, logged or printed must be self-describing. The REPL log can start on blake2b-256 and move to blake3 with no rehash.

**Why `$` exists beside an ABT.** An ABT gives structural identity (equality modulo alpha, which is
`&`) and cannot give identity *across edits*: the edited definition is another term with another
hash. That relation is a property of history, not of the term, so `$` is the hash of an op and
lives in C6, not C1. Without it petnames bind straight to `&` and must be rebound on every edit
(Unison's cascade moved to the name layer); a text atom has no content identity worth citing;
CRDT merge and identity-keyed incremental compilation have no keys. `$` is `&` applied to the log;
the extra character is the difference between *what* and *which one, over time*.

The short form is the interface view: head line, contracts, doc, no body; contracts belong to the
interface hash, aliases (`pre`, `post`) are accepted input and `require`, `ensure` the canonical
print ([contracts](02.04.11-contracts-cost-totality.md)). Semver is a computed view of
interface-directory diffs (major if an interface hash changed, minor if only entries were added
with old hashes intact, patch if only implementation hashes changed); imports are the three kinds as
modes (`& use` pinned, `$ use` follows updates and rebinds hot, `# use` local petname); packages
cannot run install scripts, because a package is data plus capabilities it must be *granted*.
The textual form of all this is [FON](../02.03-reference/02.03.03-fon.md).

## 2 Single-level store and residency

Multics had no open/read/write: a file was a segment initiated into the address space and accessed
as memory; IBM i's single-level store, KeyKOS and CHERI are the descendants. Here the
content-addressed store *is* the single-level store: a file is a segment with an identity and a
hash, reached by path; mention is load. `in` and `out` are *permission bits on a segment
capability*, not operations ([capabilities](02.04.08-capabilities-effects-failure.md)); `open` and
`close` are the beginning and end of an extent (Multics' `initiate`/`terminate`), so there are no
handles to leak; RAM vs disk is *residency*, a backend concern; persistence is orthogonal (EROS)
and the log is where durability lives. A logic or constraint store is a segment too.

**Boundary.** The single-level store holds within an image. Across machines it fails (Apollo
Domain, Amoeba, Plan 9's remote files all broke on latency and partitions) because a memory
reference has no failure semantics; so network and devices remain *channels* on which `in`/`out`
are real operations carrying `+fail`, and device memory (MMIO, DMA) is a segment kind with its own
rules. The distinction Multics abolished returns in exactly one place: where the other end of the
reference is another machine.

**Residency is a grade.** The memory hierarchy (register, L1, L2, L3, RAM, NVMe, network) is a
lattice like the information-flow lattice, so a residency grade `Text@ram` means "no slower than
this" and a word may require its arguments resident: "this loop touches only pinned segments" is a
static statement, absence of paging as proof. `pin` and `prefetch` are capabilities (Zig's explicit
allocators are the precedent); an `@ram` grade without `pin` is a type error or carries
`+fail(paged)`. A load from a non-resident segment carries a cost effect so the benchmark contract
and the roofline see it ([cost](02.04.11-contracts-cost-totality.md)). Layout (SoA/AoS, alignment)
stays on the residual; residency says where, layout says how. Whoever does not care sees nothing;
whoever cares gets a guarantee instead of `madvise`.

## 3 Shared history, not shared memory

What is given up is transparent shared memory across machines (DSM, Amoeba, Sprite, Mach); Waldo et
al. (1994) said why: latency, partial failure and concurrency cannot be hidden. What is kept is a
distributed OS in Erlang's shape with uniform *mechanisms* and explicit *location*: one namespace
(paths cross machines via OCapN, as 9P mounts did, without pretending a remote path is memory); one
capability model (a remote capability is the same value, with `+fail` on the channel behind it);
one supervision chain (`..` may cross machines); one log semantics. Remote *state* can be a
segment, namely a local replica of a log (CRDT, local-first), so data replicates and becomes
single-level locally while remote *authority* stays a channel. Data replicates, control sends.

**Actors are mobile.** An actor is code (`&`) plus state (a log prefix); moving it is shipping the
closure, a certified checkpoint and the log tail to another image, capabilities travelling as OCapN
references. Lexical and protocol extents move; clock extents over the origin's log do not, and
capabilities on local segments and devices do not. Identity is `$` plus a signing key (Seif-style
mutual authentication without a CA: a challenge is signing a nonce). Knowing *which code* runs there
is harder than knowing who: a TEE attestation, or for cheap computations determinism itself (send
an input and compare the output with what `&` yields locally).

## 4 Restart by replay, write-ahead effects

**A bare-metal image restarts as checkpoint plus log replay.** The root supervisor applied to the
image: a failure reaching the root with no restart chosen is answered by restarting from the last
checkpoint and replaying the log up to, not including, the failing event. Four rules. (1) Checkpoint
*plus* replay, never checkpoint alone: external effects after the checkpoint are in the log as
performed, and replay replays results without re-performing effects, so the restarted image still
knows what it sent; only a corrupt log falls back to the checkpoint alone, as a logged loss. (2)
Checkpoints are taken only when the root invariant holds (root handlers' contracts, linear resources
closed): every checkpoint is consistent by construction. (3) Restart intensity against a poisoned
log: if the failure is deterministic from the log, replay reproduces it and loops; as in Erlang's
max-restarts-per-period the root chooses an older checkpoint or a safe mode with the minimal handler
set, and the failing event stays in the log for the debugger (NixOS generations and A/B firmware,
on the log). (4) A loader that shares no state with what failed: the seed of the bootstrap chain,
reading only the log; the watchdog is a time capability. Done-when for H2/M5: an image restarts
from checkpoint plus replay after an injected root failure ([failure](02.04.08-capabilities-effects-failure.md)).

**Write-ahead for effects (Waterken's rule).** An `out` on a channel is released only after the
event that produced it is durable: receive, execute the turn, mutate, *queue* outgoing messages,
commit the checkpoint, then release. Log first, then channel: exactly-once across restarts for free
once obeyed, and a v0 test (a crash between append and send neither loses nor duplicates the
send). A survey of orthogonal persistence and event-sourcing systems (STM, MVCC, Datomic/XTDB, Ken,
Napier88, Temporal, ZODB, Waterken) has as its "missing union" a branchable world DAG with
checkout, fork, diff, merge and replay-safe effects: that is this section and the next. Where ZODB
versions failed (competing branches locked objects instead of merging) v0 merges by commutation
with conflicts as holes.

## 5 The log as a temporal database, rewindable and forkable

The log is event sourcing and therefore a temporal database in Datomic's sense: immutable facts,
`as-of` queries (a citation at a frontier is one), and with the HLC and the time capability
bitemporal (log time is when an event was recorded, valid time what it asserts).
`/proc/self/history/n` is the reflective tower; rewinding is replay to a prefix. Rewinding deletes
nothing: the abandoned future stays as a branch and a new event after a rewind is a fork, so every
past frontier is a possible present. This is by construction because the log is append-only (git's
reflog does it halfway).

**Re-derivation, not NIH.** Each ghost is made to follow from the six choices, keeping its idea and
dropping the coupling its substrate forced on it (Nix without a sandbox, Terraform without state
drift, Eiffel without classes, Erlang with types, Multics with residency as a grade). Four rules: a
re-derivation names its ghost and says what it dropped; it is a library on the six choices, never a
seventh choice; it must win at the point where the ghost died; it re-derives the *semantics*, not
the world (providers, controllers, nixpkgs are the world, wrapped behind FFI with `sorry`s).
*Re-derive the semantics, FFI the world.* The warning is the second-system effect in its most
seductive form, because everything fits; the remedy is the [work graph](02.04.04-substrate.md):
a ghost is re-derived only when it blocks a node.

**Erase your darlings, Nix, infrastructure.** Christensen's setup (root rolled back to a blank
snapshot every boot, persistence declared) is C6 by construction: there is no state outside the log.
Nix maps term for term: input-addressed store paths are `$` of a build's birth event; ca-derivations
are `&` of the result; a derivation is a level-1 word with no capabilities (hermetic by
construction: a build without a network capability cannot fetch); system closure is the closure over
`&` deps; generations are checkpoints and log prefixes; nixpkgs as namespace is `#` to `$` to `&`;
a binary cache is any peer with the content; a flake is a mounted directory. A package is a
directory bound by `#` to a `$` with `&` content, distributed by replicating the log.
Terraform's `plan` is a staged residual, `apply` runs it with capabilities on cloud APIs (every
effect logged, revertible to a checkpoint); the drifting state file is replaced by the log as truth
with the cloud as a *foreign peer*; Kubernetes' reconcile loop is a coalgebra (observe, diff, act),
the scan over an event stream with the cluster as a codata source; secrets are factotum. Honest
limits: the cloud does not obey the log (reconciliation is a diff against observations, never a
proof); Nix's real work is nixpkgs, a hundred thousand packages of accumulated impurity, which FPL
wraps behind FFI capabilities; providers and controllers must be written: what is free is the
semantics.

## 6 The nPOV reading: v0 is a site

Five readings, layered, of which the second unifies. (1) Events with causal order form a poset; a
frontier is a down-set, frontiers under inclusion form a distributive lattice, and the world DAG
lives in it (a fork is two ideals over one common ideal, a merge their join). (2) State is a functor
`State : Frontiers → Types`, inclusion mapped to replay; functoriality is "replay composes",
determinism that it is a function. CRDT convergence (I-confluence) is the **sheaf condition**:
states on compatible frontiers glue to the state on their join; where gluing fails is the conflict,
and conflicts-as-holes is the failure of the sheaf condition kept as an object (Goguen on sheaf
semantics of concurrent objects). (3) Patches are morphisms and merges are pushouts (Mimram and Di
Giusto's categorical theory of patches: the added objects *are* the conflicts; homotopical patch
theory: the repository as a higher inductive type, patches as paths, merges as 2-paths, time travel
as transport). (4) The log is a run of the system coalgebra and the world DAG its unfolding. (5)
Commutation of independent events is Mazurkiewicz's trace monoid; a frontier is a trace and
Pijul's commuting patches are this structure. Unifying statement: give the frontier lattice the
coverage "a frontier is covered by the frontiers whose join it is"; sheaves on it are exactly
consistent state assignments. **v0 is the site; files, database, packages and image are sheaves;
FPL's state is a topos over v0.** Two honesties: this is a sketch, not a theorem (the sheaf
condition for CRDT states is something to *state* in Lean, and that is the test: R11); and the
nLab reflex to call everything a topos is the structure-without-time worry of P3, except that here
time is baked into the site as the order on events.

## 7 Recipes, certified checkpoints, the search layer

**Recipe.** An image is a checkpoint plus the `&`-closure of a frontier; the recipe is that closure
listed (the bill of materials). The empty checkpoint is the origin, and where patches commute the
affine reading holds: checkpoints are points, patch sets vectors, replay point plus vector; where
they do not it is a groupoid, and the log itself is a monoid action since events are not invertible.
Determinism means two peers replaying one recipe reach one `&` (diverse double-compiling with no
extra machinery); the recipe is itself a v0 document with its own `&` and signature, so
supply-chain provenance is the log rather than a layer on it.

**Certified checkpoint.** `Checkpoint = { frontier, tree: blake3(M(frontier)), attestation }`: a
verifiable claim, `replay(origin, patches) = checkpoint`, testable with two peers. Needed:
`state_hash(frontier)` over the canonical encoding, a `Checkpoint` record, and one property test
(two independent replays across peers or permitted orders give one `tree`). Without signing keys a
checkpoint is verifiable but not attributable, and the name must say which.

**Search layer.** With integer-only inference an embedding is bit-reproducible, and random
hyperplane signs make it a binary code under Hamming distance, entirely in the integers
([numbers and ML](02.04.13-numbers-ml-library.md)). The semantic index is a fourth index beside
store, e-graph and log: a sheaf on the journal, rebuildable, keyed by `&`, certifiable
(`index = blake3(f_model(&content))` with the frozen model a content-addressed input) and *never
authoritative*: it proposes candidates; `&`, the interface hash and the e-graph decide. Search has
three rungs, exact to approximate: `&`; interface hash and e-graph; semantic code (the last
proposes, the first two decide).
