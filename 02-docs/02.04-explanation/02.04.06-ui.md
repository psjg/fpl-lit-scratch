# 02.04.06 2026-09-28 — UI: FML as one tree

Starting point for a dedicated UI design effort. This page records what is already
decided elsewhere in the design and what the UI work inherits from it; it builds
nothing. It was written from the markup side, not the UI side, so the rows below are
claims to be proven or broken, and the open questions are the work.

Related pages: the markup language is [FML](../02.03-reference/02.03.04-fml.md), the
data layer is [FON](../02.03-reference/02.03.03-fon.md), the surface grammar is the
[grammar](../02.03-reference/02.03.02-grammar.md), and the choices a UI inherits (log,
identity, capabilities, reactivity) come from the
[substrate](02.04.04-substrate.md). The reasoning behind the surface forms the UI
relies on is in the [syntax rationale](02.04.05-syntax-rationale.md). The overall
language vision is [design.md](design.md); the normative text is
[spec.md](../02.03-reference/spec.md).

## 1 The claim

The web and Godot each keep four trees (document, layout, scene, widget state) plus
four synchronisation problems between them; the web keeps a fifth, the accessibility
tree, which AccessKit and Tagged PDF / PDF-UA make explicit. Here there is **one FML3
tree with attributes**, and every other tree is a *view*: a word over it in a mounted
dictionary. If that holds, most of what a UI framework is for disappears; if it
breaks, the row where it breaks is the design. The accessibility tree is the cheapest
test of the claim: it must come out as a view too, or "one tree" is four plus one.

Intent behind the brief, paraphrased:

- modern web UI is broken, partly because the retained/immediate split goes unnoticed;
- MVC and reactive can coexist (Elm is the existence proof);
- reference points are Slint and Imba;
- wants reactive, wants constraint layout, wants rapid application development at the
  speed of VB6, Turbo Pascal, Delphi or HyperCard;
- wants a full 2D/3D scene graph with shaders;
- builds UIs in Godot today and misses what Sun's NeWS and NeXT's Display PostScript
  shipped.

### 1.1 Principles, named 2026-09-28

Inspirations rather than rows, but each is a requirement in disguise.

- **The read/write web.** The first browsers (WorldWideWeb on NeXTSTEP) were
  browser-editors; the read/write web was lost with Mosaic and a CMS industry grew
  around the missing half. Hotglue.me is that half restored in miniature: the page
  edited in the page, freely positioned. Here it is a consequence, not a feature: the
  tree is the dictionary, the island is code, so every document is already an editor,
  and `fpl://` delivers FML3 the receiving frame may show and may edit (what it may
  *run* is decided by F15, the receiving frame's authority rule; see the
  [FML page](../02.03-reference/02.03.04-fml.md)).
- **Inventing on principle** (Bret Victor): an immediate connection between the maker
  and the thing. That is U3 as a requirement: latency between edit and effect at zero,
  which is why the fixed point must be incremental.
- **Kay: simple things should be simple, complex things should be possible.** The
  parsimony question in other words. HyperCard is already under U5.
- **Xanadu, restated.** v0 has it, minus micropayments. Transclusion is an `&`
  reference to a span of an identified rope, kept stable under others' edits by the
  CRDT, so the reference stays valid without a copy. Bidirectional links come free
  because the log is queryable: a backlink is a query, not a stored second arrow. Not
  free: transpointing windows, the side-by-side view showing where transclusions come
  from. That is a view word, FML5 work. Dropping micropayments is a decision, not a
  simplification: under `fpl://` access is governed by authority (F15), not payment.

## 2 Rows

Positions are claims. Status says whether the row is inherited from the substrate or
FML decisions, decided here, or still a claim.

| # | Question | Position | Status |
| --- | --- | --- | --- |
| U1 | Retained vs immediate | Not a choice here. Retained is the FML3 tree in the dictionary (the log); immediate is the view, a pure word from state to tree, recomputed. The immediate-mode trick (keep the previous frame's tree for hit-testing, scroll offsets, focus) is `$` identity: widget state hangs on identity, not on the frame. Retained by identity, immediate by function | inherited from C1 and P3 |
| U2 | MVC vs reactive | Elm's split, already present: model = the log, update = event → patch, view = the pure word. Both at once, which is what was asked for | inherited |
| U3 | Reactive + layout | Fixed-point iteration over the constraint tree (`fd/`, propagation + retract), Cassowary as the linear sibling tree (decided 2026-09-28, FPL tab; F18). Layout is not a separate engine but the same propagation reactivity already needs. Whether Knuth–Plass line breaking is a case of it or a sibling solver is open | decided in principle; solver open |
| U4 | Scene graph, 2D and 3D | A Godot node is an FML3 node with a transform attribute. 2D: CTM per node (FML5, the Display PostScript layer). 3D: same tree, CTM becomes 4×4, path becomes mesh. Shaders first as `⟪glsl … glsl⟫` dialect blocks on the bottom rung; the eventual position is that a fragment shader is a pure `Real -- Real` word, i.e. FPL\_smooth, a claim with no demo | claim |
| U5 | RAD | HyperCard, Delphi and Interface Builder are structural editors over the same tree; a `.nib` was a frozen object graph, which is FON. A widget is a block, its handler an island in it, so "double-click the button, get its code" is the tree, not a feature | claim |
| U6 | Where transient widget state lives (focus, scroll, drag in progress) | **In the log, with a rank.** Decided 2026-09-28. As in v0: patches and CRDTs over rope insertions, chunked; the rank keeps the mouse-move stream out of the way of the record it belongs to. Undo, replay and collaboration on UI state come free; the price is that the log carries every pointer event at some rank, and chunking is what makes that affordable | decided |
| U7 | Presentation | No CSS: a theme is a mounted dictionary, rendering is an `@.` agenda keyed by tag, an unstyled tag is a hole (F17) | decided |

U1 and U2 together say the whole framework debate is two words long: a *model* that
is a log and a *view* that is a function. The [substrate page](02.04.04-substrate.md)
carries the log and identity rules (C1, P3) and the capability rules (F15 source
side) the UI inherits.

| U4 text | HarfBuzz/HarfRust; Parley | shaping and text layout: bottom-rung dependency of FML4, never rewritten |
| U4 scene = canvas | Obsidian Canvas / JSON Canvas; Heptabase; LiquidText; MarginNote | spatial block protocols: an F16 node with a position attribute is the same node as a scene-graph node; canvas and scene graph are one thing |
| U5 RAD | HyperCard; VB6, Delphi; Tk (`pack`/`grid`); Interface Builder and the nib; Rebol/Red VID (a layout dialect: `view [button "hi" [print "clicked"]]`); Makepad's live DSL | the form is the program; VID is what it looks like when the UI language is a dialect of the host. | U5 structural editing | Medley Interlisp's SEdit (revived at interlisp.org); Dion Systems (Fleury & Webster; unverified) | the code edited as a tree, which is what a structural editor over FML3 is |

U6 was decided for other reasons; Peritext is the span half of U6 and v0 |

## 4 Open, for the UI work

- **U3: one solver or two.** Is line breaking a constraint problem in the same tree, or
  does Knuth–Plass sit beside Cassowary? Typst and Penrose are the two existing answers
  to read first.
- **U6: the rank.** What the rank is, concretely, and what the chunking unit is for a
  pointer stream; whether the same chunking as v0's rope insertions serves unchanged.
  Peritext is the reference for spans under concurrency.
- **U4: a minimal imaging model.** What a minimal imaging model is that both a 2D
  document renderer and a 3D scene consume: the same path/fill/stroke/clip/CTM as FML5,
  or a stricter subset. Vello is what that model compiles to today.
- **Accessibility as a view.** Derive the AccessKit tree from the one tree, or find
  where it cannot be derived.
- **Small screens.** What good layout on a small screen is. None of the above answers
  it; it stays craft.

## 5 Where this lands in the implementation

The UI tree is a client of the same [core representation](../../01-bootstrap/01.03-repr/01.03.07-core.md)
as every other program, and nothing in the bootstrap passes is UI-specific; the UI
rows here become obligations on the view words and on the [FML](../02.03-reference/02.03.04-fml.md)
dialects, not on the compiler.
