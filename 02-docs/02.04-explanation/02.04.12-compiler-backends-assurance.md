## 1 Compile speed: a phase ladder (P4)

The bar is Blow's order of magnitude for the mandatory work. Phases and cost class:

- **mandatory**: parse and arity (linear, one pass; fixed valence and indentation-only nesting mean no backtracking and no precedence); stack-effect inference (local unification); grades (counting `dup`/`drop`/mentions); capabilities and extents (a scope walk); hashing per definition;
- **opt-in per definition**: dependent elaboration (only definitions that use dependent types pay); e-graph optimisation; proofs (asynchronous, cached by hash); staging (level-1 code, bounded by the operator, memoised by hash like Nix);
- **per definition, parallel**: backends.

Jai does the same mandatory class (parse, whole-program typecheck through a dependency work queue,
`$T` instantiation, `#run`, own x64 backend) with no incremental compilation by choice; our three
extras (grades, extents, hashing) are counting and walking, not searching. Full textual rebuild:
hash every token array (linear); every unchanged definition is a hit for all phases; the cascade is
bounded by interface hashes (Go's export-data idea as a property of the store); parallel per
definition up to interface dependencies. No whole-program analysis by default; the authority graph
composes from per-definition capture sets. Dependent types get slow in implicit unification and
global inference, not in the types: bidirectional checking, local stack effects, explicit universes,
and the default tier pays nothing (Lean 4 the existence proof). **Backend**: LLVM is the slow part,
so dev builds use the direct backend without optimisation and release uses LLVM or Perceus-C.
Skipping typechecking is `../adyton/unchecked`, a whole-program hole discharged later
([principles](02.04.07-principles-and-privileges.md)). Budget (done-when of B0/C1 and a line in the
benchmark contract): mandatory phases at Blow's order per core; full elaboration of the default
tier at least an order below; opt-in phases unbounded but never on the critical path. Expect Jai to
win small cold builds by polish and FPL to win large codebases by memoisation.

## 2 The compiler is a nanopass pipeline

Precedent (verified): Sarkar–Waddell–Dybvig and Keep–Dybvig: many small passes over formally
specified intermediate languages, the infrastructure checking each pass's output; their Chez
Scheme replacement used over fifty passes, produced 15–27% faster code and compiled within a factor
of two. Here an intermediate language is a directory holding a grammar over the ABT and a checker;
a pass is a level-1 function between two such languages, hygienic by construction, memoised per
definition by hash, each declaring its *seam kind*.

**A translation is not an equality.** Rewriting within a language is governed by bisimulation
([meta level](02.04.15-meta-level-and-plane.md)); between languages the obligation is *adequacy*
(what the source does, the target does) or *full abstraction* (equalities preserved too). An
adequate-only translation may be used to run, not to reason, and a composite inherits the weakest
seam. Obligation per pass: rung 1 a proof (CompCert-shaped), rung 2 differential (the walker runs
source and target and compares event sequences: translation validation), rung 3 a contract at a
hole. **Targets in three roles.** *To run*: residual to machine IR to `.s` (an instruction a word,
the last pass a printer); a Forth-style kernel or Nock by bracket abstraction as the bootstrap
seed; interaction and proof nets for the dup-free linear fragment (HVM/Bend the engine); the pi
family as a guest for concurrency. *To analyse*: Petri nets as models of linear logic, so the
linear fragment translated to a net gives reachability and deadlock analysis with existing tools.
*To give meaning*: set theory and category theory are models, not compilation targets: a
denotation function whose value is proof at rung 1; set theory as a target is replaced by
Lawvere's structural set theory (ETCS). "The most promising within a family" is extraction from an
e-graph with a per-target cost model; across languages it is research, and the cheap version is a
fixed pipeline with explicit, cached, opt-in choice points.

## 3 Sequencing: reference implementation and the road to bare metal

**The Python/Lark/Hypothesis harness is the reference implementation, the executable
specification; bootstrap is a defined milestone, done differentially.** No early self-hosting: a
self-hosted compiler freezes its IR while representation, object theory and core consistency are
open. seL4 is the precedent (the Haskell model was the spec, the C came later, the proof connected
them). Order: reference implementation first (core evaluator with stack, saturation and the two
quotation types; minimal B0: stack effects, grades by counting, extents by scope walk; A1 hash; A2
log), the version-control harness dogfooded as soon as store and log exist even if slow; in parallel
the Agda side (`CBPV.agda` grows into the core with grades; type safety at rung 1). Bootstrap
trigger: when B0 elaborates the default tier and A1/A2 exist, write FPL's tokenizer, parser and
printer in FPL with the Python as oracle (the Hypothesis generators feed both implementations the
same programs and agreement is the test), then the elaborator, then backends. The reference is the
spec, FPL must agree, a disagreement is a bug in one of the two, decided by the Agda where it
exists. The reference may be slow: P4 governs the FPL compiler, not the spec.

**Road to bare metal.** Step 0, the AST walker (the fold of `apply` over the token array with the
stack as accumulator), built first in the reference; never thrown away, because staging executes
level-1 code by interpretation, so the walker is the meta-level runtime. Step 1, a known backend
under a host. Step 2, own backend emitting `.s`, an afternoon's work because the residual is
first-order with join points (residual to asm as a view), where the handler ABI and calling
convention are designed. Step 3, own encoder, when P4 demands it, tested by byte equality with the
assembler output. Step 4, a bare-metal image: first program "hello over serial on QEMU virt,
RISC-V", then handlers for serial, timer and memory. The hosting constraints (no POSIX, freestanding,
time as a capability) hold from step one ([substrate](02.04.04-substrate.md), section 10).

**Amendments from sequencing.** M1 has no typed-patch parent (A5 becomes an upgrade node); M2 splits
into M2a (own front end in FPL, differential agreement with the reference) and M2b (elaborator and
backends compiled through the residual); the `profiles/` node gets a done-when; every backend gets a
**reclamation test** (after running a closure-allocating loop N times the live heap returns to
baseline, and on a unique-array path the allocation count is zero); closing a graph node is logged
with a date and rough session count so estimates become measurements.

## 4 Backend order and the layer statements

**Order (decided 2026-09-30).** walker, cbpv-ir (A), machine IR (M), WebAssembly (D), RISC-V (E),
with Perceus-C postponed, not dropped, and clang a later third route for differential testing.
Reasons beyond taste: WebAssembly has a formal specification and a validator; an integer-only
subset is deterministic (the spec's nondeterminism is NaN bits, relaxed SIMD, `memory.grow` failure,
stack exhaustion and threads, all avoidable with i32/i64, fixed memory and tail calls); imports are
capabilities, so "no POSIX in the core" is tested from step one; `return_call` gives `recur/tail`
and escalation without stack growth. **C1 ends at the residual**: literal-quotation inlining,
closure conversion or defunctionalisation, monomorphisation, explicit allocation, Perceus
reference-count insertion; CFG construction, instruction selection and register allocation are M,
D and E. **Reclamation** is Perceus in linear memory, not WasmGC: deterministic reclamation and
cost, in-place reuse of unique values, freestanding portability, counting fits grades; M's
signature carries `alloc`, `retain`, `release`, `reuse` from the start. The subset leaves out GC
types and exceptions: `Fail` lowers to ordinary control transfer to a supervisor continuation, and
Wasm traps correspond to a root panic. **A keeps thunks** (`U B` and force are CBPV's core);
quotations that are literal arguments of control words are inlined by an early A-to-A pass because
fixed valence makes the consumer known. M carries a `cost-label` pseudo-operation preserved by every
pass and, per operation, the observations a leakage contract assigns (as data; no-ops in D). E is
RV64 assembly assembled by the host; QEMU has no timing model, so cost assurance needs the in-order
soft core.

**Statements.** A is the walker's program after desugar with level 1 run away: Levy's
call-by-push-value, simply typed, plus capability operations, the effect line `{div, fail}` and a
`label` pseudo-operation; grades are annotations on binders. Its model is a locally indexed
adjunction `F ⊣ U` (Levy), concretely interaction trees over the event alphabet, so a pass is
correct when source and target are equivalent up to silent steps. `asm-common` is a category:
languages are objects, a pass is a morphism carrying a forward simulation over one event alphabet
and preserving each language's well-formedness predicates, an ISA is a model of the signature and
instruction selection a morphism into it; cost is a per-language handler. `cost-label` is an
observation; **label per loop** is a well-formedness predicate in each language's checker, preserved
by every pass (in control-flow-graph languages, the graph minus its labelled nodes is acyclic).
Seven amendments, each with a default and none blocking cbpv-ir: effect placement on the returner
(`F^ε A`, hole `effect-placement`); written rules for `op`, `fail`, `label`, `rec`; `fail` finds its
supervisor *lexically* (hole `fail-frames`); `escalate(W)` and `restart(r)` join the shared event
alphabet; trace properties transfer but constant-time and non-interference do not (refinement can
introduce leaks, so secret-graded flows need leakage determined by the source); the unit boundary
in the cost sentence; reducibility of the CFG as a checked predicate. For cbpv-ir the done-when adds
cost labels, an event-trace comparison with the walker, a refusal with reason on untyped slots (hole
`untyped-slots`) and grades as unchecked annotations (hole `grades-unchecked`). The stack language
between cbpv-ir and `asm-common` is A after a pass that makes the data stack explicit.

## 5 FPL as an HDL, and ISA refinement

The synchronous, allocation-free, statically shaped fragment lowers to registers and combinational
logic (Hardcaml, Clash, Chisel, Bluespec as precedents). Values are wires and computations are
combinational (class 1, parallel by construction); sequential logic is a Mealy coalgebra `X → Out ×
X`, the clock the time capability as a tick event. Verilog is a backend with partiality in the
type: the compiler refuses the rest with a reason. "Compile this tensor to FPGA" is the op-set graph
lowered to a dataflow of Mealy machines, fixed point native
([numbers](02.04.13-numbers-ml-library.md)). Own hardware is a later backend, not semantics.

**ISA specification and implementation: refinement, not bisimulation.** The implementation has
internal state the spec lacks and different cycle counts, so the relation is refinement (simulation
up to an abstraction function, up to stuttering). Prior art: riscv-formal (a formal ISA description,
a retirement-trace interface, bounded model checking); Silver and CakeML (a verified processor,
translator and compiler on an FPGA); a verified Verilog compiler followed. Three directions: derive
the implementation from the spec (each step a nanopass with a stuttering-refinement obligation),
extract an abstraction function (Burch–Dill for pipelines; a retirement-trace port with the spec in
lockstep is automatic), and "not bisimilar" as the usual answer, the useful negative result being
a minimal diverging instruction sequence. Ladder: rung 1 simulation proof, rung 2 co-simulation plus
bounded model checking, rung 3 a runtime monitor on the FPGA. What FPL adds: the HDL *is* the
synchronous fragment, so the trusted step shrinks to FPL to Verilog plus synthesis, and for a soft
core written in FPL the machine model is *derived from the design*. Limits: a full out-of-order
processor is a project of seL4 scale; the target is an in-order core; the ISA spec is a trusted
artefact validated against a reference (the official Sail model imported through a seam).

## 6 Assembly-level assurance

If the macro-assembler is a level-1 library, assembly programs are FPL terms: an instruction is a
word with a typed stack effect over a machine state (registers a linear tuple, memory a segment with
capabilities, stack discipline a grade), and the ISA's semantics is a specification in the atlas.
The chain source, passes, assembly lives in one language and one checker; a proof about the output
is a term. Statements available: *functional* (the assembly simulates the source) and *only visible
at assembly level* (constant-time, stack bounds, allocation-freedom, cost).

**Cost by labelling (CerCo; Amadio et al., Tranquilli).** Insert cost labels at key points of the
source, preserve them through the intermediate languages, and at the end each label corresponds to
object code of constant cost; soundness needs every loop of the compiled control flow to pass
through a label; costs are then lifted back as source annotations. Limits from the sources:
precision is lost where the cost of the same code varies (loop optimisations, caches; indexed
labels extend the method), and industry practice for reaction time is abstract interpretation on
binaries. What this gives: the step grade ([contracts and cost](02.04.11-contracts-cost-totality.md))
refines to a concrete grade `cost@M` indexed by a content-addressed *machine model* `M`, and
`ensure cycles ≤ N` is rung 1 by the lifted bound, rung 3 by `⊨` with deadline events. On
predictable hardware bounds are exact or nearly so; on out-of-order cores with caches and branch
predictors the assurance is *sound but pessimistic* (every access a miss) or *measured* (the
validity of `M` an empirical claim checked at rung 2 and logged; a violated bound invalidates that
model version). Branches are made not data-dependent (branchless selects) so the predictor is
irrelevant; speculative side channels are where fences and constant-time are stated.

**Observations as an `out` capability to the adversary.** Koka would put `<obs>` in the effect row;
here an observation is an `out` sink to the attacker: `+out/obs/M` with a handler interpreting
`leak-branch`, `leak-address`, `tick`; a `secret`-graded value may not reach an `out` sink. A
**leakage contract** (Guarnieri, Köpf, Reineke, Vila; baseline CT-Seq observes addresses of loads,
stores and branch targets, CT-Spec the same under speculation) says exactly which observations a
side-channel adversary may make. Every assembly instruction carries beside its meaning the
observations `M` assigns. Three handlers on one definition: a *trace* handler, a *cost* handler
(`tick` summed), and a *type rule* (the payload of an observation must be public, so a branch on a
secret is a type error: constant-time as a static check). On own hardware "the core leaks no more
than `M`" is a theorem; on commercial silicon `M` is an assumption tested at rung 2 in the style of
Revizor. Limits: "secure under `M`" is not "secure" (power, port contention and EM are outside);
typing is conservative; non-interference is a hyperproperty needing relational reasoning.

**Speculation.** Blade types each expression *transient* or *stable*, requires sinks to be stable,
and synthesises a minimal set of `protect` fences instead of forbidding speculation (under 20%
overhead on cryptographic WebAssembly, about two orders of magnitude fewer fences; for general code a
hypothesis). Transient/stable is a further grade beside the information-flow grade; `protect` is an
assembly-level nanopass; under `common` only code handling secrets pays, on an in-order core without
speculation the price is zero. A new speculative variant is an added observation in `M`, a new `&`;
the checker reports which words no longer typecheck. **The hard limit** (Google's *Spectre is here to
stay*): speculative vulnerabilities defeat language-enforced confidentiality within one address
space. *Authority* stays confined (speculation commits no architectural effects); *confidentiality
between mutually distrusting components in one image* does not hold. Rule: secret plus untrusted
code belongs in separate images, checkable on the authority graph
([capabilities](02.04.08-capabilities-effects-failure.md)). A Meltdown-class flaw is a violation of
the hardware's contract, not fixable by a compiler; FPL registers it as an event naming the invalid
model version and the images built under it.

## 7 The dependent kernel's bootstrap

Revised 2026-09-29 as three steps, meta level first; status open. Precedent: Kovács's two-level
type theory with a dependent meta level and a simply typed polarised object level. (1) *Object
level*: polarised CBPV, simply typed; it exists (the tree-walk interpreter). (2) *Meta level*: the
dependent kernel on the strict level (UIP there): Π, Σ, universes with large elimination, strict
equality, and one inductive mechanism, codes for polynomial functors with `μ`, `con` and generic
`ind` (descriptions, Chapman et al.). Codes are data, so datatypes hash as any term, a typed patch
on a datatype is an edit of its code, strict positivity follows from the grammar of codes, and
generic code is specialised by staging. Kept pure and total, this level has no Fire Triangle, so a
strict category library lands here early. (3) *Object-level dependency, last, under ∂CBPV*: with
effects, dependent elimination must be restricted in call-by-name and substitution in call-by-value
(Pédrot–Tabareau); types depend on values only; the rule pinches at sequencing (in `M to x. N`, `x`
may occur in types inside `N` but not in `N`'s own type). Only `div` and `Fail` sit on computation
types and capabilities are values, so FPL's boundary is narrow: start with the weak rule; the
stronger rule is a named hole under R3 with two known closings. H1's J-only identity enters here
with K-free unification where `match` elaborates to `ind`. State the model first in Agda: a CBPV
model is a locally indexed adjunction.

The ladder runs meta level first, then object level: ⊥ and Bool (elimination must reach a universe,
or even `0 ≠ suc n` is unprovable); ℕ (ι-reduction and NbE conversion); Id; List and `From o`
(parameters); ℤ. **Codes, not W, not declarations**: W as primitive costs every term an encoding;
declarations would put a positivity checker and recursor generator in the kernel; codes keep a
W-only kernel as a priced exit. **ℤ** is `pos ℕ | negsuc ℕ` with `negsuc n = −(n+1)` (zero on one
side only): canonical forms matter, since equal integers must hash alike; the cost is case splits
in induction; in the cubical universe ℤ is a higher inductive type, equivalent to the sum, and that
seam is R8's instance zero ([the plane](02.04.15-meta-level-and-plane.md)). **Numerals**: unary ℕ is
the specification and the representation is separate; a literal is a host integer with two
conversion rules, `add`, `mul` and kin are jets on the hashes of their unary definitions, exactness
an obligation (rung 2 differential, rung 1 proof). **Task edges** (hard = necessary condition,
soft = decision): K1 object level (done); K2 meta kernel (no incoming edges: a standalone checker);
K3 codes with `μ`, `con`, `ind` and the ladder; K4 level bridge, quote, splice (hard K1, K2); K5
object value types as `μ` over codes, parametrised only; K6 literals and jets (hard K5, A1); K7
strict category library (hard K3); K8 datatype library; K9 object-level dependency under ∂CBPV
(hard K5, B0; soft R3); K10 R8 instance zero (hard K8 and a cubical tree). Agda at rung 1 runs in
parallel and never blocks. K2 and K3 need nothing from the walker, so they can start now.
