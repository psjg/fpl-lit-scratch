# 02.04.09 2026-09-30 — Objects, dispatch and visibility

FPL does the object half of OOP and refuses the class half, with no new construct. The mechanisms
are the ones already in the [substrate](02.04.04-substrate.md): directories, path sends, the
creation chain `..`, capabilities, sealing and grades. The notation is in
[syntax rationale](02.04.05-syntax-rationale.md) (paths, `match`, `has/`).

## 1 Objects

Objects are coalgebras (state plus observations; Jacobs; Cook on objects vs ADTs) and object
equality is bisimulation, C1's behavioural identity. Messages are path sends (`p/norm`), late-bound
through identity, so replacing a method is petname rebinding; where the target directory is static,
staging resolves the send at meta level (devirtualisation) and the residual has a direct call.
Encapsulation is capability plus sealing plus uniqueness grades; a facet is an exported
sub-directory. Interfaces are structural (`has/norm`): a type with a `norm` entry satisfies
`has/norm`, dispatch by path, no class system. Self is `./`. Inheritance is delegation: `bind`
union-mounting a prototype directory, in log order (Self, Plan 9 union directories). Actors are
objects with a mailbox effect ([concurrency](02.04.14-concurrency-logic-search.md)).

Refused: classes as entities, implementation inheritance (it would make a child's interface hash
depend on a parent's body), nominal subtyping with variance, `null` (a value without a capability),
implicit mutable `this` (ambient authority), downcasts. The expression problem is not solved but
split (Cook): `match` agendas are the ADT side, `has/` the object side; choose per type.

## 2 Multimethods and typed specificity

A `match` whose classifier reads a *tuple* of tags is multiple dispatch (CLOS generic functions
dispatch on all arguments). A generic function is a directory of clauses keyed by tag tuples;
adding a method from outside is a union mount into that directory, logged (`defmethod`). Predicate
dispatch is the same agenda with predicates for tags. Exhaustiveness: a missing combination is a
hole. The sketch is draft 4 of [syntax rationale](02.04.05-syntax-rationale.md), example 3
(`collide`).

**Typed positions: most specific wins** (amendment 2026-09-30; clause order for typed dispatch
decided by the maintainer). Among the clauses whose typed slots fit a call, the most specific wins.
A clause is more specific when it is at least as specific at every input and strictly more specific
at one. Specificity is a partial order: an untyped slot is less specific than a typed one; builtin
type words are pairwise disjoint; user predicates are unordered, so clauses differing only by user
predicates are equally specific. Clauses that fit on crossing typed positions (each more specific
at a different input) are ambiguous and refused at the later head, a compile-time error, never a
run-time choice; among equally specific clauses the newest wins. Mount order, explicit and logged,
stays the only order for equal specificity and for `match` agendas over untyped tag tuples.
Consequences for versioning (open until confirmed): (a) a word's *interface* is the set of clause
signatures, not their order; a clause with an equal signature replaces the older one and changes
only the implementation hash; (b) adding a clause with a new signature changes the interface, minor
only if its domain is disjoint from every existing clause's, otherwise it captures calls and is
major; with pairwise disjoint builtins the captured set is computable at the later head; (c) only
a holder of the word's directory can add a clause, which limits capture to its owners; (d) no
fitting clause is a hole or `+fail` ([capabilities](02.04.08-capabilities-effects-failure.md)).
Semver is a computed view of interface diffs ([history](02.04.10-history-store-distribution.md)).

## 3 Advice and method combination

CLOS `:around`/`:before`/`:after`, Emacs advice and AOP pointcuts are one thing: an effect handler
installed around a path send, the send being the join point. Because a send is a capability,
advice can be installed only by whoever holds the capability to the target: no weaving from afar
and no obliviousness problem (Filman–Friedman). `:around` is a handler that may or may not resume;
`:before`/`:after` always resume. Advice installed at meta level is staged into the residual;
advice at level 0 is a logged rebinding. Dynamic access in Stallman's style is the same machinery
([capabilities](02.04.08-capabilities-effects-failure.md), section 5).

## 4 Metaclasses and the meta-object protocol

CLOS has two relations users conflate: *instance-of* (my metaclass, which made me) and
*subclass-of* (whom I delegate to). Here they are two paths that already exist: `..` is who created
me (the creation chain, my supervisor), the mount is whom I delegate to. So `class-of` is `..` and
`superclass` is the mount. A metaclass is an object at level n+1 producing directories at level n;
the meta-object protocol (control over dispatch, slot access, instantiation) lives behind `../meta`
and is staged: it changes how sends *elaborate*, never the running evaluator (Wand; PCL implemented
its MOP by partial evaluation). The class-of-class tower is the `..` chain at meta level, which is
the log. At level 0 one can rebind mounts (`bind`, logged), which is `change-class` as an event;
changing the dispatch protocol itself is level 1 only ([meta level](02.04.15-meta-level-and-plane.md)).

## 5 Branding and substitutability

Nominal typing is not in the core but available per type through sealing: Morris (1973) introduced
sealers to brand abstract data types, so a value only the holder of the sealer can produce is a
nominal `Foo` without a nominal type system. Liskov substitutability does not exist, because there
is no nominal subtyping; in its place: structural conformance (`has/`) for typing, and
bisimulation as the proof two objects are interchangeable, which is stricter and honest.
Destructors are unnecessary: dropping a unique resource without `close` is a type error. Contracts
bind every implementer through `has/norm/contract`, subcontracting without classes
([contracts](02.04.11-contracts-cost-totality.md)).

## 6 Visibility is reachability

Miller: object capabilities replace access lists. `private` is non-export: an object exports a
*facet* (a sub-directory of words); what is not in it is reachable only via `./` from inside.
`friend` is a capability grant of an unexported facet to a specific object, finer than C++ on
three axes (per word, per object, revocable by clock extent) and logged. `protected` is the facet a
prototype hands to whoever mounts it: the counterpart of delegation, explicit. Python's `_x`,
`__x` (name mangling) and `__proto__`-style reserved names dissolve: non-export is real, each
prototype has its own directory so private names cannot collide, and protocols are `has/` paths.
The cost is that facets must be designed; under P2 an operator may export everything as an
explicit act, which leaves a hole ([principles](02.04.07-principles-and-privileges.md)).
A facet type may name the identities it may be granted to ([authority graph](02.04.08-capabilities-effects-failure.md)).

## 7 Monkeypatching and refinements

Monkeypatching (Ruby) is a union mount into someone else's directory: one can patch only what one
holds, and "reopen `String`" needs the capability on that directory, there being no spellable
global root. Ruby's refinements (lexically scoped patches) are the safe form: a mount visible only
under a scope, `under` for a passage ([principles](02.04.07-principles-and-privileges.md)), and the
distance to `common` says how much has been patched.
