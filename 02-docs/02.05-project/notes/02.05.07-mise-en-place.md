**Why the name.** A kitchen's *mise en place*, everything in its place before service,
is a chef's standing war on perplexity: the same station, the same containers in the same
order, labelled and dated, so hands find things without eyes. Ergonomists and safety
engineers do the same work under other names: light switches sit at fixed heights because
it is safer and, above all, handier. The curb-cut effect rubs against it: the ramp cut for
wheelchairs serves prams, suitcases and bicycles; conventions that make a codebase legible
to an agent make it legible to a person, and the reverse. The kitchen maps without strain:

| Kitchen | FPL |
| --- | --- |
| the station | the image layout (§12) |
| the mise laid out before service | `MAIN.fpl` (§7) |
| the pass, where dishes leave the kitchen | the interface, `interface.fil` (§9) |
| the brigade (Escoffier), each at a station | the named agents |
| clean as you go | the printer law and the naming classes |
| the call-out before you move, *behind*, *hot* | the effect line |
| the label and date on every container | the log and content hashes |
| each cook's own knife roll | views and profiles (the station stays the same for everyone) |
| omakase, "I leave it to you" at a sushi counter | the default; ordering à la carte is the escape hatch, and the kitchen still cooks it |

## 1 The principle

Convention over configuration, with escape through the same mechanism as the default,
never through an exception. The image layout is a mount that can be bound differently;
names are petnames; the linter warns and never refuses. Strict are the rules of **form**:
the grammar, the printer law, and (second pass) the naming classes. Strictness is about
form, not about how anyone thinks. Reference: the Rails Doctrine: *convention over
configuration*, *the menu is omakase* (the defaults are chosen for you, any dish may be
substituted), *provide sharp knives*. Contrast: Java places its conventions in the
compiler (file name equals class name, one public class per file, checked exceptions), so
departing from them is an error. Here departing is a `bind`. Support, not constraint.

## 2 Why: perplexity

Conventions lower the perplexity of a codebase in two ways. When every project has the
same shape, each project is another sample from the same distribution, so the effective
amount of data grows, for a model's training and for a reader's experience alike. And the
*location* of things becomes predictable: in Rails, "change the view for this route" names
the file. The gofmt argument is the third: a settled form frees attention for what
matters, and the printer law has settled tabs against spaces for good.

## 3 Evidence, with its limits

- **Volume matters.** StarCoderBase's performance on MultiPL-E generally rises with a
  language's share of the training data (Cassano et al., MultiPL-T).
- **Shape matters too.** On AutoCodeBench (Tencent Hunyuan, 20 languages, 3,920 problems)
  the share of problems solved by at least one of thirty models is highest for Elixir
  (97.5 %), then Kotlin (89.5), C# (88.4) and Racket (88.3); Julia 78.0; the average 74.8;
  Python 63.3; PHP 52.8. Racket and Elixir are low-resource languages. (AutoCodeBench has
  no J or APL, and Dyalog reports APL still well behind mainstream languages.)
- **What in the shape matters.** A follow-up study on the same benchmark (Schulz, "The
  Language Is the Prompt", CyberAgent, 2026; published as a repository, not peer-reviewed)
  finds explicit contracts (typespecs and guards) the largest effect and prose
  documentation the second; removing examples alone had no effect, removing prose
  documentation dropped performance sharply.

## 4 FPL's levers, mapped to that evidence

| Lever | FPL | Status |
| --- | --- | --- |
| convention density | the printer law: all FPL looks alike, so every example is maximally informative | decided |
| borrowed priors | names chosen for single tokens in the large tokenizers (S31, S32) | decided |
| explicit contracts | `require` / `ensure` / `test` entries and `⊨` / `⊢` check cells (S45): the largest lever in the study | decided |
| prose documentation | `;;` becomes the word's `doc` entry, attached to the word, not in a separate file | decided; the lint below proposed |
| predictable location | the dictionary is a directory; every word has the same entries in the same order | decided; image layout open |

## 5 Rules proposed (S46)

- **`main` is the entry point and the manifest.** Its effect line states what the whole
  program may touch (`main : -- +in/net +out/net`): one line tells a reader the program's
  reach, which C's `main` never did.
- **Documentation lint.** An exported word without a `;;` doc gets a warning. Prose over
  examples, per the evidence. Literate programming (Knuth) fits without a seam: text as
  carrier and weaving by the printer exist already.
- **Naming classes, enforced** (second pass: "for agents and people, basta"). Words in
  kebab-case, types in PascalCase, predicates ending in `?`, symbols with `#`, short
  binders in loops. An error, not a warning; the editor's completion supplies the right
  form, so it costs no typing. A class suffix is a type suffix, an application inside the
  word, inferable like any other affix. A fix is always safe: names are metadata and
  identity is the hash of the tree (as in Unison).
- **Derived Hungarian notation.** Hungarian lost because highlighters and hovers showed
  the type; a model reads raw text and has neither. Following Spolsky ("Making Wrong Code
  Look Wrong"): Simonyi's *Apps* Hungarian encoded the kind (`us` unsafe string, `rw` row,
  `dx` width) and was useful; *Systems* Hungarian encoded the machine type and was not.
  **Materialised on disk, Spolsky's way** (second pass): the point of a canonical printer
  is bytes on disk that are scraped and fed into a BPE, so the Apps-Hungarian kind is in
  the stored name, not only in a view. It must not go stale, which is what killed
  Hungarian: the elaborator checks every kind prefix against the inferred type, and
  completion inserts it. The name never *determines* the type: Fortran's lesson (implicit
  typing by initial letter made a typo a silent type change, and `IMPLICIT NONE` became
  the convention that undid the convention). Only kinds the type does not already show
  (units, safety, coordinates), because every prefix costs a token.

## 6 Parked, to be taken up

- **The image layout, FPL's FHS.** Precedents: Rails, Maven's standard layout, Cargo
  (which finds targets by convention: `src/main.rs`, `tests/`, `examples/`). Tests and
  docs hang on the word (locality), and nothing forbids a parallel `/test/` as a *view*
  that collects every word's tests, for a build step or an agent that runs them all.
  Minimal start: `/fpl` (primitives, decided), `main`, the capabilities where the program
  meets the world. The rest open; rebinding is a Plan 9 mount. The layout proposed is §12.
- **Conventions from the 1950s and 60s**, to be mined systematically (§11): COBOL's level
  numbers, PICTURE clauses (`PIC 9(5)V99`, a type as a picture of its values, fixed
  point), 88-level condition names (`88 IS-ADULT VALUE 18 THRU 150`, a named refinement
  from 1960), and its four fixed divisions; Fortran's implicit typing (I–N integer);
  PL/I's ON-conditions (a forerunner of effect handlers).
- **Oberon's export.** Oberon dropped Modula-2's separate definition modules: one file per
  module, an export marked by one `*` after the name, and the interface extracted as a
  view. The interface view exists here (row 72: the entries without the body); the export
  mark is open.
- **Growing a corpus (MultiPL-T).** Generate tests in a high-resource language, translate
  them mechanically, have a model translate the code, keep only translations that pass.
  For FPL the `test` entries are the checks and the walker is the oracle: a corpus can be
  grown rather than awaited.

## 7 Manifests and indices: `MAIN.fpl`

Agents in large codebases start by building a map, or build one over time. FPL can give
them one, optional, generated when absent and type-checked when present: `/MAIN.fpl` at
the root and `./MAIN.fpl` in each module. It is the **manifest** (entry point, effect line
as the capability manifest) and the **index**, a book's table of contents. The codebase is
then less Knuth's free-flowing essay than a scholastic tome whose conventions every monk
knows. Everything becomes a grep and every location is fixed.

Precedents: `index.html` (index, not main: the directory's table of contents); Python's
`__main__.py` and `__init__.py`; Java's JAR manifest (`Main-Class:` in
`META-INF/MANIFEST.MF`) and `public static void main(String[] args)`; Go's `package
main`; Rust's `main.rs`, `lib.rs`, `mod.rs`. The named closer is real, not confabulated:
Fortran's `PROGRAM xyz … END PROGRAM xyz`, Modula-2's `MODULE xyz; … END xyz.`, Ada's
`procedure Xyz is … end Xyz;`, and the grammar already offers it opt-in (X21, `end name`).

**Arguments typed.** BusyBox is one binary that is many programs by `argv[0]`; FPL's
equivalent of `argv` is typed by `main`'s effect line, so a future FPL shell passes
values, not strings (PowerShell passes objects, Nushell has typed pipelines). Help text and
man pages generate from the same effect line and the `;;` docs (Python's argparse and
Rust's clap generate help; man pages need an extra tool there). A generated man page
follows the Unix fixed headers: NAME, SYNOPSIS, DESCRIPTION, OPTIONS, EXIT STATUS,
EXAMPLES, SEE ALSO.

## 8 Documentation: a map, and docs on single names

The syntax proper is FML's ([FML reference](../../02.03-reference/02.03.04-fml.md)); this
is the map of what exists, for FML and FPL to draw on.

| System | Language | Attaches by | Per-argument or per-field docs |
| --- | --- | --- | --- |
| Javadoc | Java | `/** … */` before the declaration, `@param`, `@return`, `@throws` | `@param name` |
| JSDoc | JavaScript | same shape as Javadoc | `@param {type} name` |
| Doxygen | C, C++ and others | `/** */`, `///`, `\param` | `///<` after a member |
| C# XML docs | C# | `///` with XML | `<param name="x">` |
| rustdoc | Rust | `///` (item) and `//!` (module), Markdown, code blocks run as doctests, intra-doc links | on fields and enum variants |
| Haddock | Haskell | `-- \|` before, `-- ^` after | `-- ^` after each argument in a type signature |
| Python | Python | docstrings (PEP 257), then several styles: Epydoc's `@param`, Sphinx/reST `:param x:`, Google's `Args:`, NumPy's `Parameters` section | Sphinx's `#:` comment before an attribute |
| Go doc | Go | a plain comment directly before the declaration, first sentence starting with the name | none |
| ExDoc | Elixir | `@moduledoc`, `@doc`, doctests; hexdocs for every package | none |
| Julia | Julia | a string before the definition, Markdown | on struct fields |
| odoc | OCaml | `(** … *)` | on record fields |
| roxygen2 | R | `#' @param` | `@param` |
| POD | Perl | its own block language | none |
| docstrings, plists | Lisp | a string in the definition; any symbol's property list | `(get 'x 'doc)`: a doc on any single name |
| Scribble | Racket | a separate documentation language | none |

What is missed is a doc on a single, even trivial, name, shown on hover and in
completion and queryable by an agent. It exists in Haddock's `-- ^`, Doxygen's `///<`,
Sphinx's `#:` and Lisp's plists. In FPL every name is a path, so a doc can be an entry of
any name (`mean/doc/xs` for an effect-line slot; a trailing `;` on a binder's line as that
binder's doc); the mechanism is to be settled with FML. FML is a file tree that hangs in
the same tree; the Xanadu layer (transclusion, spans by identity) makes it a textual
Xanadu, where agents already thrive in Obsidian-like vaults.

**The features, not only the systems:**

| Feature | Examples | In FPL |
| --- | --- | --- |
| doc before a definition | Javadoc `/** */`, rustdoc `///`, Go | `;;` becomes the `doc` entry |
| doc after a line or member | Haddock `-- ^`, Doxygen `///<` | trailing `;` |
| per argument | `@param`, `:param x:`, `Args:` | a field in the doc, addressed by name (so destructuring binds, S35's open `→( … )`, cause no ambiguity) |
| per return value | `@return`, `Returns:` | a field, or the effect line itself |
| per error or effect | `@throws`, `Raises:` | unnecessary: `+fail`, `+io` are in the effect line |
| types in the doc | JSDoc `{type}`, NumPy style | unnecessary: types are in the tree |
| runnable examples | rustdoc doctests, Elixir, Python doctest | `test` rows |
| cross-references | `{@link}`, intra-doc links | paths (`mean/doc`) |
| module and package docs | `//!`, `@moduledoc`, `doc.go` | `;;;;`, and `MAIN.fpl` |
| inherited docs | Javadoc `{@inheritDoc}` | a doc entry is a path: refer to it |
| deprecated, since | `@deprecated`, `@since` | fields, or derived from the log |
| hidden | `#[doc(hidden)]` | not exported means not documented |
| coverage enforced | rustdoc `missing_docs`, Python's interrogate | the doc lint (S46) |
| generated site | docs.rs, hexdocs | a view on the tree |
| examples scraped from use | rustdoc's scrape-examples | a view: callers of the word |
| literate | WEB, Scribble | text as carrier, weaving by the printer |

Much falls away: types, errors and effects are in the tree, examples are tests. What
remains documentation is prose, which is what the Elixir study found matters most.

## 9 Interfaces

**Greenfield method.** First the types taken from and returned to the world; then the path
A → ? → B (filling holes, the parked synthesis of the substrate's §6); then the invariants
to keep on the way; then the types and interfaces; then the code is a filling-in exercise.
This is Wirth's *Program development by stepwise refinement* (1971) and Dijkstra's
structured programming, with the holes made literal by `?` goals, and it is how agents do
best as well. Escape hatch included.

**Deep, narrow modules.** Ousterhout's *A Philosophy of Software Design*: a module should
have a small interface over much functionality; the root is Parnas's information hiding
(1972). Jonathan Blow's counterpoint, that sometimes tight coupling is what gets the job
done, is supported too (omakase), with the capability system saying what is coupled to
what.

**Nothing exported by default**, as in Rust (`pub`), OCaml with an interface file, Oberon
(`*`). Go exports by capitalisation, a naming convention doing export, relevant to §5's
enforced naming classes.

**`interface.fil`** (FIL: FPL Interface Language, *fill in the gaps*). Both of Wirth's
phases supported: an export annotation in the module (Oberon's `*`, so the programmer
never needs the interface file open and an agent never needs to grep for it), *and* an
interface file `./module/interface.fil` that is generated when absent and checked for
congruence when present, hangable under a head as `./interface`. Precedent, exactly:
OCaml's `.mli`, optional; without it the inferred interface is used (`ocamlc -i` prints
it), with it the implementation must conform. Also TypeScript's generated `.d.ts`, Ada's
specs, Mesa's DEFINITIONS modules (Modula-2's model), Standard ML's signatures. The
interface view is row 72's: the entries without the body.

## 10 Locality

Most code on the web is neither context-free nor local: a snippet needs imports, setup and
conventions from elsewhere. FPL does well here and should keep it: a word carries its doc,
contracts, tests and effect line with it, and an export is marked where the word is defined
(Wirth's `*`), so what is relevant is in front of the reader. The same property helps
people and agents.

**Does the point hold? Yes, more strongly than stated, with four holes.** The strong part
is a property of concatenative languages: every contiguous fragment is itself a program
with an inferable stack effect. A line cut from a Python function is not a program;
`dup shape first` cut from FPL is a function `xs -- xs n`. On top, the effect line says
what a word needs and outside dependencies are visible capabilities (`../io`).

The holes:

- **binders**: a fragment using `x` depends on the line with `→x`; point-free code is
  local, binders bring context back;
- **cells**: `$x` depends on a value elsewhere, deliberately;
- **profiles**: under `#sac under` the same text may read differently, the largest hole,
  meaning that depends on the surroundings;
- **names**: resolved in scope; but since identity is a hash, any fragment can be printed
  in a transport form with `&hash` references and is then truly context-free, as in Unison.

Checkable once the walker exists: a property that every point-free fragment of the corpus
has an inferable effect; measurable as, per word, the free references not in its effect
line or the dictionary.

## 11 Mined from the 1950s–70s

- **Algol 60's three languages**: a reference language, a publication language and
  hardware representations, one abstract language with several spellings. Our ABT with its
  glyph, name and ASCII spellings is this, with a printer law between them (see the
  [archive of the glyph spelling](02.05.08-archive-glyph-spelling.md)).
- **Algol 68 stropping**: keywords told apart from names by marking: bold in print,
  `UPPER`, `.point` or `'quote'` in hardware. Relevant to shouting `BREAK` and to enforced
  naming classes: case as a class marker has a long history. Algol 68's two-level (van
  Wijngaarden) grammars, from the Mathematisch Centrum in Amsterdam, made context-sensitive
  rules part of the grammar.
- **COBOL**: four fixed divisions (a place for everything); level numbers (hierarchy by
  number); PICTURE clauses; 88-level condition names (named refinements); `OCCURS … DEPENDING
  ON n` (an array whose length depends on a value, 1960: a dependent type); `REDEFINES` (two
  views on the same storage); COPY books (shared record layouts); column 7's `D` for
  debugging lines.
- **Fortran**: implicit typing (I–N integer) and its reversal by `IMPLICIT NONE`, the
  cautionary tale for any naming convention that decides types (§5); FORMAT statements
  (layout as data, apart from the I/O call: a printer specification as a value); COMMON
  blocks (named global storage, the cautionary tale PHP's globals repeated).
- **Lisp 1.5 property lists**: any symbol carries a list of properties, documentation on
  any single name (§8).
- **Forth shadow screens**: in block-based Forth each code screen was paired with a
  documentation screen at a fixed offset, a parallel documentation view with fixed
  locality, which is §6's `/test/` idea applied to docs.
- **Smalltalk-80's System Browser**: categories → classes → protocols → methods in four
  panes, a fixed layout for navigating code, the image as a FHS.
- **Unix man pages**: numbered sections (1 commands, 2 system calls, 3 library…) and fixed
  headers, a documentation convention every reader knows (§7).
- **Parnas 1972 and Wirth 1971**: §9. **PL/I**: ON-conditions (a forerunner of effect
  handlers), and as a whole the cautionary tale against a language with every feature.
- **Stable addresses under insertion.** Dutch legislation inserts article 3:84a between
  3:84 and 3:85 rather than renumbering, and a repealed article stays as "vervallen" under
  its number; BASIC numbered lines by tens (`10 PRINT`, `20 GOTO 10`) to leave room.
  American common law goes further: a case is cited by reporter, volume and page (*347 U.S.
  483*), an address fixed forever, and Shepard's citator (from 1873) is a reverse index of
  every later case that cites it, followed, distinguished, overruled, so a reader learns
  whether a case is still good law. That is our reverse "why is this here" view and
  deprecation-through-the-log, a century and a half earlier (§16); and readable stable
  labels for lines and probes, if wanted, look like `3:84a`.
- **Military manuals and standards.** COBOL came out of CODASYL (1959), convened with
  Department of Defense backing; JOVIAL was built for the Air Force's SAGE-era systems;
  Ada answered the DoD's Steelman requirements (1978); software documentation was
  standardised in MIL-STD and DOD-STD-2167. What that culture made that is useful here:
  *warning, caution, note* as a typed hierarchy in technical manuals (injury, damage,
  information: a severity type for annotations); decimal paragraph numbering (stable
  addresses again); the five-paragraph operations order (situation, mission, execution,
  sustainment, command and signal: a fixed form every reader knows); bottom line up front;
  the pilot's checklist (after the Boeing Model 299 crash of 1935); the NATO spelling
  alphabet (names chosen to survive a noisy channel: our token-chosen names); and
  Simplified Technical English (ASD-STE100, from aircraft maintenance), a controlled
  vocabulary against ambiguity, the naming discipline of §5 as an industrial standard. The
  standards reach down to the layout and numbering of the manuals themselves (MIL-STD-38784,
  MIL-STD-40051). A US Army technical-manual number is itself an address: `TM 9-2320-280-10`
  is the operator's manual for the HMMWV, 9 the category, 2320 the federal supply class
  (trucks), 280 the model, `-10` the maintenance level and so the audience (`-10` operator,
  `-20` unit, `-34` higher levels). S1000D, the international specification for technical
  publications, goes further: documentation is made of small *data modules*, each with a
  structured data module code, kept in one common source database and reused across
  publications, with *applicability* filtering which modules hold for which configuration:
  our tree with its views and profiles, for manuals.

To continue: Simula 67, JOSS, IPL, Mesa/Cedar, CLU (clusters, iterators), Alphard and
Euclid (verification-oriented), Lucid, early APL workspaces.

## 12 The station laid out

A book has a table of contents (the author's order and argument) and an index
(alphabetical, derived); they are different things. The contents is written and checked;
the index is a view: kept by hand it would lie, like stale Hungarian.

```
/
	MANIFEST.fpl	; the package: identity, dependencies by hash, exports, reading order
	                ; (Maven's pom, Cargo.toml), FON-data
	MAIN.fpl	; `main` first, at a fixed place; the other programs under it
	interface.fil	; generated, or written and checked
	<module>/	; the same shape: MANIFEST.fpl, MAIN.fpl if runnable, interface.fil, the words
	doc/	; prose that belongs to no single word: guides, design
	data/	; segments the program owns
	fpl/	; mounted: the kernel, a few dozen primitives, read-only (Forth)
	std/	; mounted: the standard library, batteries included (Python, Go)
	deps/	; mounted: third parties, as source, by hash
	test/	; view: every word's test entries
	index/	; view: the index
	log/	; view: the history
```

No `/etc`: configuration is code, the `under` lines at the top of `MAIN.fpl` and its
effect line, typed. No `/dev`: the world (`io`, `net`, `clock`) comes from `..`, what the
parent mounted, in Plan 9's terms. Every name here is a petname: anyone may bind the
station differently. The manifest is FON data
([FON reference](../../02.03-reference/02.03.03-fon.md)).

## 13 The fixed order of a word

Documentation, then the type line, then the preconditions, then the code, then the
postconditions, then the tests: `;;` doc, the head (`name : effect`), `require`, body,
`ensure`, `rescue`, `test`, `proof`. The printer enforces it, so every reader finds every
part where it always is. The rationale is the scholastic article: a question, the
objections, an authority against them, the answer, a reply to each objection, whose fixed
form existed to give every objection its full voice, a structure for disputation, not
obedience. Lawyers still work this way: a judgment of the Hoge Raad answers each ground of
appeal in turn, and the commentaries descend from the Bologna glossators. (The Summa's own
order would put the examples, its *sed contra*, before the body; this order keeps them
last.)

## 14 The compiler is part of the language; the build is FPL

The build script is FPL, as Zig's `build.zig` is Zig; the compiler is a library in `/std`,
as in Lisp and Smalltalk images. A build is a program with an effect line (`build : --
+in/src +out/artifact` says what it may read and write), so builds are **hermetic by
construction**, which Bazel and Nix enforce with effort: a build sees only the capabilities
passed to it. Inputs by hash make the same input the same output, so building is caching
(Nix, Bazel's remote cache), and the elaborator-as-reactive-program (parked) makes it
incremental. Code run at compile time avoids Jai's hole (`#run` may do anything) without
Zig's prohibition (`comptime` may do no I/O): it gets the capabilities passed to it through
`../meta`, stated in its effect line. The pass pipeline this builds on is described in
[the pass pages](../../../01-bootstrap/01.02-pass/index.md), and the backends that
extend it in the [backend plan](02.05.06-backend-plan.md).

**Batteries included.** Three layers: `/fpl`, the kernel (a few dozen primitives, the
trusted base); `/std`, shipped with every image (the printer, linter, tests, docs and
build live here and are FPL: Go's one toolchain, and the Zen of Python's "one obvious way
to do it"); `deps/`, everything else. Python's PEP 594 removed dead batteries and broke
code; here `/std` is on hashes, each word versioned, deprecation goes through the log, and
a module moving from `/std` to `deps/` stays reachable by a mount under the same name:
names are petnames.

## 15 Capabilities and capacities

"Capability" means two things that coincide here. In Sen, *functionings* are what a person
actually does and is; the *capability* is the set of functionings they can achieve, their
real freedom. Nussbaum distinguishes *internal* capabilities (what the person can do) from
*combined* ones (that ability plus the conditions to exercise it).

| Sen, Nussbaum | FPL |
| --- | --- |
| functionings | what the word actually does; what `ensure` describes |
| capability set | what the word can do: bounded by the effect line, exactly and checked |
| internal capability | the code and its type: what it can compute on its own |
| combined capability | that code plus the authorities it receives from `..`: capabilities in the object-capability sense |

A word with the code to send mail but no `+out/net` has the internal capability and not
the combined one: Nussbaum's point that ability without conditions is not freedom, and the
ocap point that code without authority cannot act. The effect line reconciles the two
meanings: the ocap capabilities a word holds determine its Sen capability set. Sen's
methodological point carries over: judge by the capability set, not only by what happened;
for a dependency, not what it did in the tests but what it could do. And with P1 there is a
mirror: for the *operator* the language widens capabilities (what the checker carries, the
person need not); for the *program* it narrows them to what is granted. One mechanism
emancipates the person and bounds the code. (This is the syntax author's account, for the
substrate author to amend; the [substrate page](../../02.04-explanation/02.04.04-substrate.md)
holds the principles.)

## 16 What the common law teaches

1. **An address is assigned at publication and never changes.** *347 U.S. 483* says where
   and when a case appeared, not what it contains. FPL has both kinds: the hash says
   *what*, the log position of first publication says *where and when*; a word can carry a
   citation address as stable as a judgment's.
2. **Pin cites are stable because the book no longer changes.** *347 U.S. 483, 495* points
   into the case and stays right because printed reporters are immutable. So a path into the
   *current* version (`norm/3/ensure`) shifts under edits, but hash plus path points into an
   immutable version and does not; a probe or a reference hangs on a version and is carried
   forward on update, as Shepard's keeps track.
3. **The reverse index carries kinds of relation, not only "uses".** Shepard's records
   whether a later case follows, distinguishes, criticises or overrules an earlier one. The
   log can do the same: a new version *supersedes*, an overlay patch *distinguishes* a
   special case, a deprecation *overrules*. "Is this word still good law?" is then a query,
   and the editor can show it as Westlaw's KeyCite does, a red flag for overruled, a yellow
   one for negative treatment.
4. **Holding versus obiter dicta.** Only the holding, the decision that carries the
   outcome, binds later courts; remarks along the way do not. For code this answers Hyrum's
   law (with enough users, every observable behaviour is depended on): only the contract
   binds: the interface, `ensure`, the effect line. Everything else is dicta: whoever leans
   on it does so at their own risk, and the checker can warn when a dependent relies on
   anything but the contract.
5. **Binding versus persuasive authority.** A higher court's ruling binds; one from another
   jurisdiction may only be weighed. Here contracts bind, examples and docs persuade: the
   line between `ensure` and `test`.

## 17 Forms as compression

A shared form is a shared codebook: whoever knows what "an Anselm" is hears a whole
argument in two words: compression against a prior the writer and reader share, the same
mechanism as our codebook and BPE tokens. Classical rhetoric called shared forms *topoi*,
*loci communes*: literally places, where an orator kept arguments as in the method of loci,
mise en place for arguments. The danger is in the same examples: "it is evident that"
sometimes compresses and sometimes hides five pages or a gap (Lakatos, *Proofs and
Refutations*). A form that points at nothing is not compression but a promise.

**The rule: a named form is a word with a contract**, so the compression can never hide a
gap.

| Shorthand | In FPL |
| --- | --- |
| "it is evident that" | a proof the checker discharges with a named decision procedure (Lean's `simp`, `omega`): evident *to the machine* (P1 at work) |
| "left to the reader" | a `?` goal |
| "analogously", "similarly" | the same word or macro, reused |
| "without loss of generality" | a named symmetry lemma |
| "a standard argument", "an Anselm" | a word in the library |

**Japanese forms.** *Kigo*, season words in haiku: one word calls up a season, recorded in
the *saijiki*, an almanac of season words; such meaning is not assigned but grows with
use, so our saijiki is a register that grows from the corpus. *Makurakotoba*, pillow words:
fixed epithets bound to certain words, like Homer's formulae, which Milman Parry showed
existed to compose orally within the metre: compression for the poet, not only the reader.
*Utamakura*: place names with fixed associations (Yoshino means cherry blossom): places
again. *Honkadori*: taking a line from a famous older poem so the reader hears the whole of
it: transclusion in the thirteenth century, working only because the reader holds the
canon, as an `&hash` works only because the store holds the original.

**Patterns as words.** Christopher Alexander's *A Pattern Language* gave each pattern a
fixed form (name, context, problem, forces, solution, links to larger and smaller
patterns), the fixed order of §13, and made patterns compose into a language; the Gang of
Four took the catalogue. Peter Norvig showed (1996) that 16 of the 23 GoF patterns become
simpler or vanish in Lisp or Dylan: with enough abstraction a pattern is a word, Forth's
philosophy of factoring until every recurring form has a name. Two kinds follow.

- Some **dissolve**: a factory is a quotation returning a value, so `xFactoryFactory`
  cannot arise.
- **Architectural** ones keep their roles but become *checkable*: MVC is already the core
  (the model is cells, the view is `$=` views over them, the controller is words with `+st`
  that `set`), and the pattern's rule, a view does not change the model, is a type rule (a
  view has no `+st`; `$var` in a `:` definition is refused). That is Uncle Bob's dependency
  rule (*Clean Architecture*) made mechanical, and Cockburn's ports and adapters likewise:
  ports are interfaces (FIL), adapters are the modules holding a capability on the world.
  A pattern becomes a named template: a directory with expected role entries and rules on
  which role may hold which capability, checked.

Omakase: whoever wants no pattern uses none. Alexander told programmers at OOPSLA 1996 that
they had taken half his work: the catalogue without the generative part, patterns combining
into something living; composition of words is that generative part.

## 18 Spelling hashes

Hashes need not be hexadecimal noise. Precedents: RFC 1751 (1994, 128-bit keys as six short
English words); the PGP word list (1995, two lists for even and odd positions so a swap or
omission shows); BIP-39 (a key as a phrase from 2048 words, with checksum bits);
proquints (16 bits as a pronounceable syllable group); Urbit's names; Python's `humanhash`.

**Measured** (o200k; 64- and 256-bit hashes; bits per token, higher is better):

| Spelling | Bits per token |
| --- | --- |
| hex | 7.0 |
| BIP-39 words joined by hyphens | 5.8 (worse than hex: each hyphen is a token and words without a leading space split) |
| base32 as in IPFS | 8.1 |
| base58 (Bitcoin) and base60 | 8.5 |
| CamelCase from a codebook chosen so each word is one token | 9.5 (1,342 of BIP-39's 2,048 words qualify) |
| **decimal** | **9.8** (the tokenizers cut digit runs into groups of three, so a decimal number is base 1000 to the model) |

Base 60's divisibility does not help a hash, which is never computed with. Two good
candidates were words (memorable, pronounceable, and where a kigo can grow) or a decimal
number (slightly denser).

**Fixed.** It is a spelling of the same bits, not a new identity: bijective, hex remains a
valid view, and S47 holds. Words must start neutral (concrete nouns, no judgements or
emotions, sounds easy to tell apart: the NATO principle) so that meaning is earned by use
rather than preloaded; that is Zooko's triangle resolved in layers, as petname systems do
(Miller, Stiegler): the hash secure and decentralised, the petname meaningful and local, a
nickname meaningful and shared, and a kigo the nickname that became convention. A checksum
word at the end, as BIP-39 has, so a typo is not another valid hash. The naming class is
known per prefix (`&` versus types' PascalCase). The canonical form has a fixed length,
because a shortest-unique prefix (Git) changes as the store grows and would break the
printer law; the full hash lives in the store and a collision is refused. From IPFS, whose
identifiers are never truncated and describe themselves (multibase, multicodec, multihash):
the hash *function* belongs in the identity (multihash), so a future migration adds names
without renaming old ones (Git's long SHA-1 to SHA-256 transition is the cost of not doing
so); the *spelling* does not (multibase), because spelling is the printer's view. Renaming
is deferred as long as possible.

**Decided (2026-09-29): full decimals.** Hashes are spelled as the full decimal number, and
so are all numbers in the canonical text (the `.fpl` materialisation): no separators of any
kind, because the tokenizers cut digit runs into groups of three and anything between them
costs a token (measured on o200k: a 64-bit hash 8 tokens plain, 14 with `_` every three
digits; `86400000` 4 against 6). The word spelling is dropped; kigo can still grow as
petnames attached to a hash, not inside it. Grouping digits for the eye is a view only, and
it must be injective (S47).
