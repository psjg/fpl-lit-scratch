## 1 Reference kinds and the sigils

- **`$` is identity, `&` is bytes, `#` is a symbol.** `$` names what was hashed at
  birth (an operation); `&` names bytes (a body, a blob); `#` a petname. Same alphabet
  and length for `$` and `&`, different referent, and the sigil is the only thing that
  tells them apart, so it is the guarantee, not a convenience.
- **An atom endpoint is a path under the identity**: `$⟨event⟩/⟨offset⟩`. `$e` names the
  whole run, `$e/3` its fourth atom; a span is `{ from $e/3 to $f/7 }`. The offset
  addresses the body as typed, so under a header/body split it survives redaction as a
  hole.
- **Hash form**: first one encoding of 64 lowercase hex (blake3-256), later a
  self-describing multihash spelled in decimal (`&30:…`, see the Scratchpad row 39).
  Rules kept throughout: no short form in anything stored or logged; a short form in a
  mention is an editor affordance resolved with a uniqueness check and becomes a hole
  when it stops being unique; readers refuse unknown codes; a new function is a new
  code, never a "version 2"; identifiers compare whole; history is never rehashed.
  Pitfall found: the multihash code is an unsigned varint, so the blake2b-256 hex form
  begins `a0e40220`, not `b22020`; an alias reader refuses the unencoded form.
- **Deps versus links.** A proposed law (the sigil is the type: `&` is a dep, `$`/`#` a
  link) was refuted by a counterexample: in the version-control layer every reference in
  an operation (an insert's anchor, a delete's target) is a `$` and still a dep. What
  holds: the *field* says whether the referrer can be evaluated without the target;
  bytes you evaluate are always deps. Deps count for closure, links do not, so a
  citation never adopts what it cites.
- **A `$x` cell versus a `$` identity**: `$name` (a cell, an identity of a local place),
  `$code:digest` (an object or event) and `$n` (the n-th argument at entry) are
  separated lexically by the colon; purity is decided by context (refused in a `:`
  definition, a pure read in a `$=` view within the tick, a capability elsewhere). A
  quotation capturing `$x` captures the identity, so the code still hashes.

## 2 Citations, spans and standoff markup

- **The standoff record and the citation are one object**: a span of `$` identities plus
  the frontier it was written at, `{ from $… to $… kind #em at ⟨…⟩ }`. "Is this
  annotation still current" is a diff between the text at that frontier and now,
  computed, never guessed. Cost stated honestly: a full replay per frontier until a
  `goto` operation exists.
- **A `Cite` is a link-only operation**: replicated like any event; links count for the
  reverse index ("who cites this atom") and never for closure; a citation whose atoms
  are absent or dead renders as a hole with provenance, never as a guess.
- **Where the link lives**: on the event, not the operation, so every operation can carry
  links without behaviour of its own; closure stays the sole product of the operation's
  references; the Lamport check walks parents, references and links ("you cannot cite
  what you have not seen"). The theory states two relations on one poset: dependency
  order, and a link relation that never enters closure.
- **Authority decides edits inside a quote.** Typing inside a quote is a write on the
  source's atoms: it goes through iff the writer holds the write capability on that
  mount; otherwise the edit forks the span into the citing document. Copy-on-write is the
  consequence of refusal, not a per-quote setting. The fork is itself a write on the
  citing mount, so a citing document that forbids it refuses outright: the same rule
  applied twice, no third state.
- **A span is its two ends**, and a *torn* span (the last before the first after a move)
  is reported with a reason, which is a hole and so a task, visible to a reader. The
  alternative (a span as the set of its atoms) would hide the tear.
- **A quote is an atom of the citing document** (an island with its own identity), not a
  marker between characters, so before-the-quote and after-the-quote are different
  places, a quote can be deleted like any character, and the citing document stays a
  plain document.
- **Milestones versus standoff**: overlapping markup uses standoff records on identity;
  milestone atoms survive only as the TEI import dialect, never as FML's own mechanism.
- **The outliner node (F16)**: children use `-`; properties go in one `{ id $b1 … }` line
  under the item, never `- key value` (which is ambiguous); tree form
  `( item { id $b1 } "text" ( item … ) )`, which is FON, so the outline ↔ tree round trip
  is the printer law. See [FML](../../02.03-reference/02.03.04-fml.md) and
  [FON](../../02.03-reference/02.03.03-fon.md).

## 3 Profiles, interface views and contracts

- **`under <profile>`** mounts a vocabulary and a view at the scope root, logged, in the
  interface hash. For documents (F19) the view may vary the FML2 spelling (which
  line/block/inline grammar reads the string interior) but never FML1 (the pre-lexer
  with Dyck pairs, islands, raw runs is under no profile, so no profile can admit
  overlapping pairs). A legacy dialect is a `⟪md … md⟫` block, not a profile. The
  profile line is the first line of the file and an island `⟨under org⟩`, because a
  positional rule on a bare word would be a heuristic; absent means `common`. In code it
  is `#ML under`, postfix, scope-local, `use` an alias.
- **The interface view** (F20): a word's short form is the head line, contracts and doc,
  without the body; a document's is the tree minus every body (headings and block tags
  with properties, island head lines with effect lines, references, the profile line).
  It is what an `fpl://` receiver reads before running, and what the interface hash
  covers (over the ABT, spelling-free). Print profiles are now full, tangle, weave and
  interface under the same two laws. Open: whether a heading's first paragraph counts as
  its doc (needs a `doc` tag, never a position rule).
- **Contracts** (D33): `require` / `ensure` / `rescue` as children `f/require`, order
  doc–require–body–ensure–rescue by printer rule; a clause's contract prints under the
  clause; `rescue` wraps the body in a `try` frame and offers `retry`; `old` refers to
  the previous frontier. Then S44/S45: entries `./name/` filed by prelude macros that
  expand *before saturation* so they never count toward arity; a line-level `⊢ q` is a
  proof obligation carried as a goal; `⊨ q` runs on a read-only borrow (linear items are
  never copied; capabilities visible by identity only; `q` capability-free and total) and
  a failing `⊨` is a blame event, erased once discharged by `⊢`. A bare `/` is
  escalation, never a root.
- **Patterns respect grades**: `_` in a linear position is a drop and a type error unless
  the component is affine; inside a `space`, rows inherit the rule that a goal may not
  close over linear or unique values.

## 4 Typed dispatch and the effect line

- **Overloading is typed dispatch**: a clause is keyed by its input types, arity being one
  part; arity-only dispatch is the case where every input is `value`. The typed effect
  line is `f : x: Int  y: Int -- z: Int` (named, typed slots; compound type in `⟨ ⟩`).
- **Clause order B** (decided): the most specific clause wins; crossing typed positions
  are ambiguous and refused at the later head (unless a clause covers their meet);
  equal specificity goes to the newest. Per position untyped is less specific than
  typed; builtin type words (`Int`, `Decimal`, `Text`, `Symbol`) are pairwise disjoint;
  user predicates are unordered. The generated dispatcher is a `match` ordered by
  typed-position count, newest first.
- **Why newest-wins needs care**: a new clause can capture calls that resolved to an older
  one, so clause order is in the interface hash and an added clause is a semver major
  unless its domain is disjoint; only a holder of the word's directory can add one.
- **What the effect line must carry**: the two computation effects (`+div`, `+fail` with
  restarts and condition paths), the capability requirements (`+in/…`, `+out/…`,
  `+ctx/…`, `+nefas`); never a grade, a polarity or a stage (inferred); it maps to a
  CBPV arrow with the stack as accumulator.
- **Slot kinds** (`thunk-or-code` closed): each slot is a value (forced at once), a
  thunk (`t: [ -- x ]`, forced by the head when it chooses) or `Code` (inspected, never
  run); a child is only ever run by its head. `if` is `choose !`.
- **`( … )` and stranding**: names as arguments make `(f a b c)` plainly `a b c f`; bars
  are needed only between adjacent literals, because literals side by side form one
  strand. Whether stranding is worth the bar is an open syntax question.

## 5 Substrate rules from the version-control layer

- **Write-ahead**: an `out` on a channel is released only after the event that produced
  it is durable. v0 obeys trivially because it only pulls; the test belongs with the
  first push path.
- **Certified checkpoint**: `Checkpoint { frontier, tree }` with `frontier` the antichain
  of maximal changes and `tree` a blake3 over a canonical length-prefixed encoding of the
  state; two replicas reaching one head by different routes compute the same pair. It is
  verifiable by recomputation and attributable by nothing (no signature yet; the field
  name keeps the two apart).
- **Sheaf reading**: states on frontiers glue on compatible frontiers; a failure to glue
  is a conflict object kept as a hole (R11, to state in Lean).
- **Naming**: *journal* for the word one types in a path, *medium* for what it is.
- **REPL as the first v0 prototype**: each input is an event whose `$` hashes a header
  holding its parent; provenance field (operator or agent, model, session) with a keyed
  integrity MAC outside the hashed header (integrity among key holders, not
  attribution); fuel as a step budget; compare-and-append on the head (one logical
  writer); rewind is an event that deletes nothing. Its semantics is re-running all
  accepted inputs as one file, valid exactly for capability-free inputs; inputs holding
  capabilities must have effect results read from the log. See
  [REPL phrase costs](02.05.05-repl-phrase-costs.md).

## 6 Grammar, comments and the harness

- **Grammar ambiguity** found by implementing the parse obligation: `frame` could match
  nothing, so a leading blank or comment line was ambiguous (26 of 29 examples, 1814 of
  2000 generated programs). Settled rule: `frames: frame (_BAR frame)*` with an empty
  frame allowed, `[]` is one empty frame, `start: line*`. Comments are nodes, not trivia.
  Both printer laws hold at 2000 examples (earlier runs were actually 300).
- **Flat fragment**: the generator for `from_lark` gets the flat fragment of the grammar
  (no indenter, one newline); blocks come from a tree strategy; the sublanguage property
  should itself be a test.
- **Quality gate**: a module owes the language its metatheory from the moment it has
  code (`parse`: unambiguous; `desugar`: preserves meaning; `types`: progress and
  preservation); `eval` and `types` may not import `parse`, `desugar` or `lark`; lints
  that never refuse fit a separate report. See the [grammar](../../02.03-reference/02.03.02-grammar.md)
  and [bootstrap parse](../../../01-bootstrap/01.02-pass/01.02.02-parse.md).
- **Nagini study** (a Python verifier): not integral, not parked: an opt-in `make verify`
  lane over marker-named modules, run beside CrossHair and mutmut, never instead. It
  proves range and length safety and, with a dialect price (no allocation in a pure
  function, no self-reference in a pure postcondition, proof hints for recursion), the
  `desugar` meaning obligation for all terms. See
  [Nagini](../../../01-bootstrap/01.06-nagini/01.06.01-advance.md).

## 7 Backend plan and work graph

- **Track structure**: a CBPV IR (A); WebAssembly and RISC-V as one-to-one IRs (B, C); an
  `asm-common` abstraction (M); nanopass A → M → WebAssembly (D); M → RISC-V (E);
  AArch64 pulled forward as its own one-to-one IR because it runs natively on the
  maintainer's machine; MMIX as a later instance. See [Backend plan](02.05.06-backend-plan.md).
- **Settled**: WebAssembly before Perceus-C; C1 ends at the residual; own reference
  counting in linear memory, not WasmGC; A keeps its thunks; M carries `alloc` / `retain` /
  `release` / `reuse`, a `cost-label` and observation sets as no-ops in D. Stack
  exhaustion is an observed outcome like a trap, never FPL's `Fail`. A trap in a test
  frame reports and resumes so a run terminates; in production it reaches the root
  handlers and the image restarts from checkpoint plus replay.
- **A and `asm-common` statements** accepted with amendments: effects on the returner
  (`F^ε A`), `rec` with `div` by default, `fail` to its lexically bound supervisor (not
  the nearest frame on the continuation), `escalate` / `restart` in the event alphabet,
  plain simulation does not transport hyperproperties, the cost sentence carries the
  unit boundary, reducibility as a checked predicate. Instruction selection is a
  signature morphism (an institution); the one global pass per target family (register
  allocation, control restructuring) is a separate morphism.
- **Cost handler per language**: a labels-by-passes table where each column difference is
  one pass's cost, valid only within a unit; labels checked as dynamic traces with the
  every-loop condition in each language's checker.
- **Scheduling insight**: a precedence-only work graph cannot say "X makes Y faster", so
  tools (REPL, oracles) are modelled separately from routes; the constraint is review
  capacity, not agent count, so work is released at the pace of review (drum-buffer-rope).
  Measured on the stand-in program: a WASM route is the cheapest fallback if the walker
  gets too slow (about 80 lines, 80-90× the Python walker).
- **Dependent kernel**: step order meta level first, ℤ before the Boom hierarchy as the
  first R8 instance. The [core representation](../../../01-bootstrap/01.03-repr/01.03.07-core.md)
  is the walker's target.
