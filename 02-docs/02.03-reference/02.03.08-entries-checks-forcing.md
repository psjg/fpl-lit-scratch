# 02.03.08 2026-09-29 — Entries, checks and forcing

Decisions S44, S45, S47 and S49, split out of the [FON](02.03.03-fon.md) decision log.
They fix where examples, contracts and proofs live in the source, what a check is, how
whitespace separates things, and who runs a child line. Each revises its predecessor; the
text below keeps the *current* form and says what it replaced. The syntax is that of the
[surface grammar](02.03.02-grammar.md); the contract and proof ladder belongs to the
[substrate](../02.04-explanation/02.04.04-substrate.md); the pattern machinery that S49
reduces to inverses is in [binding and matching](02.03.07-binding-and-matching.md).

## 1. Entries (S44, S45)

**S44 (proposed, then revised).** The objection that started it: `⊢` and `⊨` exist, so a
claim must not become a third mechanism. It does not have to. Inside a definition the
current scope is the word's directory (`mean/require`), so a child line names an entry of
the word being defined, and the rung is which entry:

| entry | rung | glyph view | Hoare reading |
| --- | --- | --- | --- |
| `test` rows | example, checked by running | — | {stack = these inputs} word {stack = this value}: a triple on one state |
| `require`, `ensure` | contract, checked as a property (Hypothesis, CrossHair) | `⊨` | {P} word {Q}, universally quantified, tested |
| `proof` | proven | `⊢` | {P} word {Q}, discharged |

So `⊨` and `⊢` become the glyph views of `ensure` and `proof` (names are canonical, see
[spellings](02.03.06-spellings-and-comments.md#3-tokenizer-aware-naming-and-fpl_bpe-s31-s32)),
and a `test` row is a `match`-shaped table: input cell, tab, expected cell. Printer order:
doc (`;;`), `require`, body, `ensure`, `rescue`, `test`, `proof`. Precedents: Hoare triples
are what Eiffel's design by contract checks at runtime and what Dafny, SPARK and Why3
prove; attached examples are Pyret's `where:` blocks, D's `unittest`, Rust's doctests; a
claim shown instead of checked is Quokka/Light Table — the same value-after-line node in
the other mode (write the value the run produced, rather than compare it). The
contribution is not the triple but one mechanism across three rungs.

**Obligations are not comments.** The inline `; → v` claim was withdrawn as a checked
form. A comment never changes what a program means — the inert-reader principle applied
to the source itself: `;;` may *become* a word's `doc` entry, which is documentation, but a
comment the checker reads as an obligation is code in a comment's clothes. Examples live
only in `test` rows. The Quokka/Light Table mode is an editor overlay, never written into
the source. See [comments](02.03.06-spellings-and-comments.md#5-comments-s33-s48).

**S45 item 1: `./` is the current scope.** As in Unix and Plan 9: `/x` the root, `./x` here,
`../x` the enclosing scope (`..` already). Replaces S44's leading `/name`; bare `/` is the
root.

**S45 item 2: entry macros.** `require`, `ensure`, `rescue`, `test`, `proof`, `invariant`
and `measure` are ordinary macros in the prelude — not reserved, shadowed by `bind` like
any name — that file their child lines as the entry `./name/` of the innermost enclosing
block. They expand before saturation: entry lines are not children and do not count toward
a head's arity. The printer always prints the bare macro word; `./name/` is accepted input
and never printed. A named block's entries have a path (`norm/ensure`); an anonymous
block's have a positional one from the enclosing word (`norm/3/ensure`, clause paths). An
entry on an `if` node is Hoare's rule for conditionals (Q after either branch); `invariant`
on a loop block is `require` and `ensure` on every iteration; `measure` is Dafny's
`decreases` and `recur/measure`.

```
norm : p -- n
	require
		point?
	#x #y [lookup] each [times] self [+] fold sqrt
	ensure
		0 >=
	test
		3 4 point	5
		0 0 point	0
```

## 2. Check cells and the caesura (S45 items 3-5, S49 item 2)

**S45 item 3, check cells.** A cell that begins with `⊨` (name `check`, Eiffel's in-body
`check`) or `⊢` (name `prove`), after a line's code cells. Saturation decides, the core
rule: a saturated right side is an equality (`⊨ 5`), an unsaturated one a predicate on the
stack (`⊨ 0 >=`). A check runs on a copy of the stack after the line and never changes it,
so it needs no `dup`. `⊨` is tested by running (and as a property where the line is
generic); `⊢` must be discharged statically. Both on one line is allowed: `⊢ ?` beside
`⊨ q` is "test now, prove later", and a check beside a proof that rests on `sorry` is its
evidence. Position decides: `⊨` first on its own child line is the `ensure` entry's glyph
view; as a trailing cell it is a check.

**S45 item 4: `; →` is withdrawn**, as a checked comment and as sugar: `⊨ v` does the same
before the comment. The drafts' `; →` lines are respelled as check cells where they were
checks and as `; yields …` where they were illustrations.

**S45 item 5: the caesura `|` becomes a word**: whitespace-delimited under the Forth rule,
no longer self-delimiting. That frees `|=` and `|-`; `1|2` without spaces becomes one name
(never canonical). The grammar terminal is renamed `_CAESURA` (the grammar page shows the
earlier `_BAR`). A glyph view `‖`, the modern caesura mark, is possible. No `|>`:
juxtaposition is already the pipe (`xs sort first`).

**S49 item 2, the final spelling.** `∈` is withdrawn; `⊢` and `⊨` are words. Types are
predicates, so `⊢` (`prove`) and `⊨` (`check`) are ordinary words of effect `x p -- x`:
`3 Int ⊢` is what `3 Int ∈` was (static), `⊨` checks at run time. In the canonical text a
check is always the last cell of its line, spelled with the caesura:

```
xs sort	| sorted ⊨
code	| 0 >= ⊨
3 4 point | norm	| 5 ⊨
```

Right of the caesura is a frame of its own: `0 >=` is unsaturated, so by the core rule it
is a section, the predicate; `⊨` takes the value from the left by underflow, as `1 | 1 2 3
+` does. A saturated right side (`5`) is a value, and `⊨` compares. The caesura, the one
separator that does not compose, marks exactly what a check is: something that looks
alongside without changing the stream. No alternative spelling and no view (regularity in
the corpus is the point of the cells); the printer puts every check in the check column. A
check mid-line checks the stack at that point, so the printer does not move it but breaks
the line after it; consecutive lines compose, so the meaning is unchanged.

## 3. Tabs and alignment (S45 item 6)

Inside a cell, spaces (composition). Between semantic columns — pattern, body, check,
comment — and wherever the author aligns, a tab: a cell boundary, kept in the tree, so an
author's alignment is part of the source (`#debug⇥under` over `#sp/*⇥enable`). The printer
pads by cell kind within a block so that checks and comments each stand in one column:
Gravgaard's column blocks break at a missing cell and the grammar keeps no empty cells, so
the padding is computed, not stored. In pure-literal blocks tabs are columns (rank), not
alignment. Spaces never carry alignment: one meaning (composition), stable under renaming,
correct in proportional fonts. Precedent: Go's `text/tabwriter`, which gofmt uses,
implements Gravgaard's algorithm. Background:
[grammar, indentation is tabs](02.03.02-grammar.md#7-indentation-is-tabs-alignment-is-elastic-tabstops-decided-2026-09-27).

## 4. The whitespace ladder

| separator | in code | in data |
| --- | --- | --- |
| space | composition | token within a cell |
| tab | composition, and an alignment point | column boundary |
| newline | next line of the block | next row |
| blank line | section | next axis |
| form feed | page | the axis above |
| caesura `\|` | side by side, a stack per frame | — |

Space is composition, not application (Haskell's juxtaposition is application, which is not
associative and needs a precedence convention): von Thun's point for Joy, text
concatenation mapping to function composition, one monoid onto another. The caesura is the
one separator that does not compose, which is why it alone has a visible mark. The data
column is the rank literal of [FON](02.03.03-fon.md#4-ranked-whitespace-arrays-tables-spreadsheets).

## 5. Every view is injective (S47)

A view may omit, style or rearrange what it shows, but two different trees must never look
the same in it. Otherwise the view lies, as a stale Hungarian prefix lies. The printer law
makes the canonical text injective by construction; this rule extends the obligation to
every other view: glyph and name spellings, print profiles, the editor's rendering. Found
through a collision: showing a decimal number's digit groups with thin spaces makes
`12483436` appear as `12 483 436`, indistinguishable from the three-element strand
`12 483 436` (see [FON, numbers](02.03.03-fon.md#10-numbers-s27)).

## 6. The head forces (S49)

S49 corrects S43, S45 and the `∈` of S35.

1. **Typed declarations: `name: Type`.** In effect lines, binders and patterns:
   `f : x: Int  y: Int -- z: Int`, `3 →x: Int`, `( circle r: pos )`. `--` stays (the Forth
   convention; currying needs no arrow, underflow is currying). A compound type goes in an
   evaluating group: `ys: ⟨ sorted ∩ xs perm ⟩`. Precedent: Factor's typed stack effects
   `( x: fixnum -- y: fixnum )`. The head's `:` and the slot's `name:` are the same typing
   colon, as in Lean. Measured: 13 tokens for the typed line against 16 with `∈`.
2. **`∈` withdrawn; `⊢` and `⊨` are words; a check is a cell in one spelling** (section 2).
3. **Entries on every node.** Words, blocks and lines have the same entries (doc, require,
   ensure, test, proof), in three spellings: the word mid-line, the caesura check ending a
   line, the entry macro under a block.
4. **Three forms of `$`, told apart by the colon.** `$name` is a cell's identity (live);
   `$code:digest` is an object's or event's identity; `$n` is the n-th argument at entry
   ([binding and matching, S36](02.03.07-binding-and-matching.md#1-lambdas-s34-and-positional-arguments-s36),
   kept for the prior of shell `$1`, Swift `$0`, awk and regex back-references). `$n` is the
   deliberate exception to "`$` is identity"; confusion is lexically impossible because an
   identity always has a colon.
5. **The head forces** (call-by-push-value, Levy). A child is never run by its position,
   only by its head. Each effect-line slot is a value (forced at once, top to bottom —
   ordinary strict arguments), a thunk (`t: [ -- x ]`, forced when and if the head chooses)
   or `Code` (inspected, never run). Computing both branches ahead is not part of any word's
   meaning; a compiler may do it only under the as-if rule (C's and C++'s), when no branch
   has `+io`, `+fail` or `+div` and it is cheap. This closes the open hole of whether a
   child is a thunk or Code.
6. **`if`, `each`, `match` are ordinary words; `( … )` is a reader macro.** `if` is
   `choose !`: `choose` only moves data (two quotations), and `!` forces the chosen one, so
   running ahead cannot even be expressed (Factor defines `if` almost so). `each` takes a
   thunk. `( … )` only reverses order (`( circle r )` is `r circle`) — the first and
   simplest test of the macro system. Destructuring is done by the words themselves,
   through their inverses: a pattern is a program and matching runs it backwards; since a
   program is a composition, its inverse is the reversed composition of the inverses (APL's
   `⍣¯1`, J's obverse, our `inverse`/`⁼`). The pattern rules of
   [S35](02.03.07-binding-and-matching.md#2-pattern-matching-s35-s37-s38) then follow rather
   than being stated: the inverse of pushing a name is binding it (`r` ↔ `→r`), of pushing a
   literal is checking equality and dropping, of `_` is dropping, of `$x` is comparing with
   x's current value, of a constructor is destructuring or failing. `match` tries each
   row's inverted pattern and then its body, with `or`; `or` restores the stack when a row
   fails (failure leaves no trace). Inside a `space`, `or` yields all solutions: Prolog.
7. **Macros** are only words that inspect or store code: `( )`, `trace`, and the entry
   macros (`require`, `ensure`, `rescue`, `test`, `proof`, `invariant`, `measure`).

## 7. Inverses: precedents, for inspiration

Running words backwards has a long line behind it, and each precedent suggests something
beyond pattern matching.

- **APL**: the power operator with a negative count, `f⍣¯1`, is the inverse of `f`
  (Dyalog), defined for the invertible primitives and their compositions.
- **J**: `u^:_1` is the inverse; `u :. v` declares `v` as the *obverse* of `u` when J cannot
  derive it — an explicit inverse entry, our `word/inverse`. And `u&.v`, *under*, applies
  `v`, then `u`, then `v`'s inverse: add under log is multiply, sort under a key is sort by
  that key.
- **BQN**: `⁼` is *Undo* (the source of our `⁼` glyph) and `⌾` is *Under*, which BQN
  extends structurally: `f⌾(1⊸⊑)` applies `f` to the second element and puts the result
  back — modifying inside a structure without taking it apart by hand.
- **Janus** (Lutz and Derby 1982; formalised by Yokoyama and Glück 2007): a reversible
  language in which every program runs backwards; the discipline that makes inversion total.
- **Prolog**: a relation runs in both directions — `append` concatenates and splits — which
  S35 already reaches through `space`.
- **Lenses and Boomerang** (Pierce and others): a get paired with a put, bidirectional
  transformations with laws.

What this suggests for FPL, to take up later: *under* comes free once inverses exist (`f g
under` = `g`, `f`, `g inverse`), and with patterns as inverted constructors it gives
structural update — change a field inside a value in one word, BQN's `⌾`. Where an inverse
cannot be derived, the word declares it (J's obverse), as an entry beside `doc` and
`ensure`.

## 8. Debugging, and what was refused

**Debugging: a direction, no syntax.** Inline debug forms are a Postel case
([grammar, no Postel](02.03.02-grammar.md#8-no-postel)): every form added now must be read,
printed and explained for good. Probes come from outside, on paths, as handlers — DTrace's
named probes, aspects on pointcuts — in a debug profile (`#debug under`), and the editor
shows them in the gutter as a view. Open: a probe must attach to the CRDT identity of a
node, not to a positional path, which shifts under edits. `trace` may remain an ordinary
library word.

**Briefly.** Sugar separating quotations by `\` is refused: the child-line form exists (a
head's child lines are its quotations) and `\` is the stateful scan. `match` rows are a
rank-2 literal, so dispatch tables are values. Sticky head lines, a frozen first cell and
folded columns are views. Hoare triples moved out of comments into languages — Anna `--|`,
JML `//@`, ACSL `/*@`, SPARK 2005 `--#`, then Ada 2012 and SPARK 2014 aspects and C++26
`pre`/`post` — which grounds "obligations are not comments"; Clojure's `{:pre … :post …}`
map on a function is the closest precedent for entries in a word's directory.
