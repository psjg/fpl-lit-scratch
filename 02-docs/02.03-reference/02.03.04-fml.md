# 02.03.04 2026-09-28 — FML: the markup companion

FML sits beside [FON](02.03.03-fon.md) as the second profile of the one
[grammar](02.03.02-grammar.md). It is not a second language: it is the FPL grammar with the
polarity of prose and code swapped, one more spelling of the tree FON already has, and
libraries below that tree. Its consequences for documents, UI and literate programming are
developed in [UI](../02.04-explanation/02.04.06-ui.md); the reasons behind the Dyck-only
rule are in [syntax rationale](../02.04-explanation/02.04.05-syntax-rationale.md); the
reference and effect machinery it leans on (capabilities, `Cite` records, palimpsest
transclusion) is in the [substrate](../02.04-explanation/02.04.04-substrate.md) and the
[Discussion design notes](../02.05-project/notes/02.05.10-discussion-design-notes.md). The
executable delivery of its harness was owed to the same shar discipline as the grammar
([SHAR](02.03.05-shar.md)).

## 1. Purpose and status

Five layers, agreed 2026-09-28; each is useful without the one below it, and only the top
three are built.

| layer | what | kind of thing |
| --- | --- | --- |
| FML1 | the swap: prose outside, `⟨ ⟩` islands inside | a boundary: an `.fml` file is the interior of one `“ ”` (incidental indentation, [grammar §9](02.03.02-grammar.md#9-multiline-strings-are-free-incidental-indentation); the pre-lexer as it stands) |
| FML2 | `#`, `-`, `>`, `[[…]]`, `#tag`, `⟪md … md⟫` | a *spelling* of the tree, the third beside indented and braced ([FON, layout spellings](02.03.03-fon.md#7-layout-spellings-indented-and-braced)) |
| FML3 | the tree: `( h1 { } “…” )`, tagged tuples with `{ }` attributes, TEI-shaped | the semantics; this is FON, nothing new |
| FML4 | layout: boxes and glue, Knuth–Plass line breaking, page breaking | a library of FPL words over the tree (TeX's contribution) |
| FML5 | imaging: paths, fill, stroke, clip, CTM — `ps/` with an `out` capability to a device; events from the log make it a UI | the Display PostScript / NeWS equivalent; PostScript is postfix and concatenative, so the imaging model is a dictionary, not a substrate change |

| state | items |
| --- | --- |
| decided and implemented | FML1; FML2's block spelling (headings, bullets with tab nesting, quotes, paragraphs as lines, dialect blocks) and Dyck-only inline spelling (wikilink `[[target\|label]]` with the three reference kinds, tag, island — with strings inside islands — raw run, balanced quotes); the canonical printer; both printer laws over generated documents (trede 2) |
| decided, not implemented | `:exports both` as a print profile (F9); tables as the tab block (F10); the braced spelling `( h1 … )` and the printer between the two; the outliner node with `{ }` properties (F16); the effect line on an island (F15); presentation as mounted dictionaries (F17); rendering to HTML/PDF through an existing renderer as bottom-rung evidence |
| not yet decided | footnotes; the TEI standoff spelling in prose; what a heading *contains* (F12); which block words the protocol needs beyond heading, item, quote, paragraph, dialect |
| test coverage | 2000 generated documents per law, re-run after the Dyck-only change; 20 hand-written acceptance and rejection cases; no coverage of FML3's braced form yet |

Replacing HTML, PDF and LaTeX is three unequal replacements: HTML → FML3, free, because
`( p { … } … )` is SXML and XML round-trips as data; LaTeX → FML4, a total dynamic program,
ordinary FPL, with LaTeX's macro half already covered by `Code` at level 1; PostScript →
FML5, a dictionary. Layers 4 and 5 wait for a residual to run on; building a PostScript
interpreter in Python before FPL exists is the case the
[sober note](../02.05-project/notes/02.05.02-sober.md) warns against, so they are named here
and not started.

**Direction set 2026-09-28, after the first fill.**

1. No CSS: presentation is not a cascade over the tree but words in a mounted dictionary —
   a theme is a `bind` union-mount, overriding is log order, and there is no specificity.
2. Everything Dyck: no asymmetric inline markup (an opener that is its own closer — `*x*`,
   ``x`` — is out); line-start markers stay, since they are prefixes under the affix
   discipline, not pairs.
3. FML2 is a block protocol: tagged blocks, an outliner, YAML-shaped bullets, links and
   transclusion and span addressing from what exists (`$`, `&`, v0). FML3 may be written
   inline in FML2 — that is what an island is.
4. Wikilinks with Obsidian's pipe, `[[target|label]]`.
5. Lineage: HyperCard, OpenDoc, Lepiter, Org, the Gemini protocol; and the intent that
   FML4/5 settle UI. Gemini is the nearest precedent for (2): gemtext has headings,
   bullets, quotes and links on lines of their own and no inline styling at all, and is
   readable because of it — FML2 is gemtext with islands.

## 2. Polarity flipped, and literate programming falls out

An island is code the evaluator runs; the rules FPL already has decide what an island in
prose means, and no construct is added:

- an island whose contents is a `:` head line **defines** — `bind`, the word enters the
  dictionary, nothing is pushed;
- an island without a head line is an **expression** — its value is spliced into the text;
- a `$` island is a **view** that recomputes on the log clock — Org's `#+RESULTS:`, live.

Tangle and weave are two print profiles on one tree: "code only" prints the `.fpl` file,
"with prose" prints the document, and the printer law covers both, so `parse ∘ print = id`
is also the tangle guarantee. WEB needed two programs because TeX and Pascal were two
grammars; here it is one grammar with the polarity swapped.

Three consequences that go past noweb and Org. (1) `mean/doc` needs no separate field: the
doc of a definition is the prose its island sits in; the file *is* the directory view of
the dictionary, and `;;` ([comments](02.03.06-spellings-and-comments.md#5-comments-s33-s48))
stays the short form for code-first files. (2) noweb's `<<chunk>>=` and Org's `:var` are
paths and capabilities that exist; island order is log order (`bind` is an append), so
"defined later, used earlier" is the same rule as in FPL itself. (3) A foreign language is a
dialect block, `⟪py … py⟫`, and the pair names the interpreter. The difference from an FPL
island is the rung: an FPL island stays on the tree under the printer law; a `⟪py⟫` block
tangles to a file on disk and is evidence, not source. So the document states, per seam,
which trede it is on — the integration ladder as a property of the format rather than a
convention — and retiring a language removes one pair from the list. Grammars for such
dialects are `match` rules in a `space`
([binding and matching, S41](02.03.07-binding-and-matching.md#5-grammars-are-match-in-a-space-s41)).

**Decided:** an island that is both a definition and a shown value (Org's `:exports both`)
is a print profile that shows the definition and places the value after it — a view, not
syntax.

## 3. Decisions (F1-F20)

The collisions between the Markdown spelling and the core table, each with its
recommendation. Prose is outside code, so line-level markers collide with nothing in FPL;
the collisions are with the pairs the pre-lexer counts and with the one-glyph-one-meaning
rule.

| # | decision | recommended | whose | changes |
| --- | --- | --- | --- | --- |
| F1 | Links | `[[target\|label]]`, Obsidian's pipe; target a reference kind (`fon`, `$fon`, `&sha256/…`, a URL), no spaces in the target, label optional; `[text](url)` refused — it would use both FPL pairs across the polarity boundary. Under palimpsest's deps/links proposition: `[[&…]]` pins a version and is a dep, `[[$…]]` and `[[name]]` are live and are links — "quoted by `&` keeps the old, mentioned by `$` gets the new", the same sentence for prose as for code | decided 2026-09-28 | notation; implemented |
| F2 | Emphasis and every other inline mark | none asymmetric (Dyck-only): emphasis is an island holding the element, `⟨“word” em⟩` — FML3 inline in FML2; `em`, `strong` are words in the markup dictionary producing elements. In a structural editor the spelling cost is nil ([UI](../02.04-explanation/02.04.06-ui.md)); in a text editor it is the price of having no ambiguity to specify. TEI milestones (`⌜em … em⌝`) have no meaning in FML2 — only inside `⟪tei … tei⟫`; the standoff record is FML's one mechanism for a second hierarchy | decided 2026-09-28 | notation; `*`/`**` removed from the harness |
| F3 | Shown code vs run code | `「dup ⍴」` is a raw run: shown, never run, keeps every marker; `⟨dup ⍴⟩` is run. One mechanism for "literal" — the raw pair already in the core | syntax author | notation; implemented |
| F4 | `#`: heading vs symbol | `#{1,6}` + space at line start is a heading; `#word` after whitespace is the symbol, i.e. a tag; both are the existing `#name` ([spellings](02.03.06-spellings-and-comments.md#2-symbol-and--for-content-s29-revising-s16)) | syntax author | none |
| F5 | `//` in prose | not a comment: URLs contain it; `//` is text in FML, a comment only inside islands | syntax author | none |
| F6 | Lists | `-` bullets; nesting one tab per level; blank line ends a list; ordered lists deferred with canonical numbering when added | syntax author | grammar |
| F7 | Quotes | `> ` per line; a run of `>` lines is one paragraph; nested content in quotes deferred | syntax author | grammar |
| F8 | Paragraph lines | kept in the tree, one run-tuple per line, whitespace to the renderer; trailing whitespace an error; leading spaces an error | syntax author | grammar |
| F9 | `:exports both` | a print profile: definition shown, value placed after it | decided 2026-09-28 | printer profile |
| F10 | Tables | the tab block with a header row ([FON](02.03.03-fon.md#4-ranked-whitespace-arrays-tables-spreadsheets)); a line containing tabs in prose is a table row once blank-line rank reaches the grammar; until then it parses as a paragraph | both | grammar, next step |
| F11 | Footnotes, citations | open; nothing new if a footnote is a link to a block by identity, `[[$note-3]]`, rendered as a footnote by the print profile | syntax author | — |
| F12 | Headings | flat markers in the tree today; whether a heading opens a section (a subtree) is the same question as blank-line rank in code, and should be decided with it | both | tree shape |
| F13 | `“ ”` in prose | balanced typographic quotes are text and may hold islands; unbalanced is an error, because the outer `“ ”` of FML1 is counted by the FPL pre-lexer; other quote styles (`„ ”`, `‘ ’`) are plain text | syntax author | none |
| F14 | Holes in prose | `_` is text; an unspecified span is `⟨_⟩`, an island holding the hole, so the task list of unresolved holes includes documents | substrate | none |
| F15 | What an island may ask for | an island that needs authority declares it as an effect line on its head, `⟨main : -- +in/net⟩`, so a reader can refuse before anything runs; an island without a head line is pure and runs with nothing. What arrives over `fpl://` is FML3, inert; "app" is a document whose islands the receiver has bound capabilities into, and the authority graph is the permission sheet. The same rule decides transclusion: an edit inside a quote is a write on the source's atoms and goes through iff the writer holds the write capability on that mount; otherwise the edit forks the span into the citing document — copy-on-write as the consequence of refusal, not a per-quote setting | substrate | effect-line grammar on islands |
| F16 | The block protocol: every block is an outliner node | a block = tag, `{ }` properties, inline content, children. Children with `-`, one tab per level; properties as **one `{ id $b1 … }` line under the item** — never `- key value`, which is ambiguous against a two-word child (syntax, not heuristics); `$id` in the properties gives the block identity, `#tags` in the content give it tags; the tree form is `( item { id $b1 } “text” ( item … ) )`, a tagged tuple in the data profile, so the outline↔tree round trip is the printer law and not new work. Logseq/Roam blocks, Lepiter snippets, HyperCard cards, OpenDoc parts (a part is a dialect block with its own interpreter), and a canvas node (an item with a position) are readings of this one node | decided with the syntax author 2026-09-28 | grammar; the item rule gains a property line |
| F17 | Presentation without CSS | a view is words over the tree in a dictionary; a theme is a mounted directory (`bind`, log-ordered); a block's rendering is a `@.` agenda keyed by its tag, exhaustiveness by holes: an unstyled tag is a `_`, a task, not a silent default. No selectors, no cascade, no specificity; overriding is mount order | decided: no CSS, 2026-09-28 | FML4/5; nothing in FML2 |
| F18 | Layout for print and screen | Knuth–Plass (boxes and glue) and Cassowary (linear constraints, Apple's AutoLayout) are both layout as optimisation; whether one solver serves both, or the constraint tree (`fd/`, with Cassowary as a linear sibling) hosts both, is open and decides FML4's shape | substrate | FML4 |
| F19 | A document's profile: `under` | taken. A profile mounts a vocabulary and a view at the document's root, logged, part of the interface hash — the same mechanism as for code, nothing FML-specific. What a profile may vary is the FML2 *spelling*: which line, block and inline grammar reads the string interior (the `#`/`-`/`>` of this page is the `common` spelling; an Org spelling or a gemtext spelling are other views of the one FML3 tree, with a mount as the switch). What it may not vary is FML1: the pre-lexer (Dyck pairs, islands, dialect blocks, raw runs, counted quotes) is under no profile, so no profile admits overlapping pairs or an asymmetric inline mark. A legacy dialect (CommonMark with `*x*`) is therefore not a profile but a `⟪md … md⟫` block; a document that is all legacy is one block. The profile line is the first line of the file and is an island, `⟨under org⟩` — not bare `under org`, because a prose line may begin with the word "under" and a positional rule on a word would be a heuristic; as an island it is FPL, the same word as in code, and the pre-lexer finds it before any profile-dependent layer runs. Absent line = `common`. Block-scoped profiles get no second spelling in FML: a dialect block already scopes | taken 2026-09-28 | grammar: the first island may be a profile; the line/block/inline layers become a profile's view |
| F20 | The interface view of a document | taken. A document's short form is the tree with every body removed: headings and block tags with their `{ }` properties (F16), island head lines with their effect lines (F15), the references it makes (`[[…]]`, `$`, `&`, `Cite` records), the profile line (F19) — no paragraph bodies, island bodies or dialect-block bodies. It is the outliner's folded view and Org's overview; it is what a receiver over `fpl://` reads before running (F15 is the document's `require`); and it is what the document's interface hash is over. Print profiles on one tree are then four — full, tangle, weave, interface — and both printer laws cover each. Open edge: Eiffel's short form keeps the header comment, but a document's doc *is* its prose, so the interface view keeps none; if a first paragraph under a heading should survive as that heading's doc, it needs a mark (a `doc` tag on the block), never a position rule | taken 2026-09-28 | printer profile; interface hash of a document |

**Precedents filed against the rows above** (from a reading/annotation survey, 2026-09-28).
For F16: JSON Canvas (Obsidian), Heptabase, LiquidText and MarginNote are spatial block
protocols — an item with a position attribute — and Logseq (DB version), RemNote, SiYuan and
Roam are the outliner reading of the same node; the node with a position is also the
scene-graph node of the [UI](../02.04-explanation/02.04.06-ui.md), so canvas and scene graph
are not two things. For the TEI standoff row: the W3C Web Annotation Data Model is the
existing spelling of a span that refers rather than encloses (TextQuoteSelector,
TextPositionSelector, FragmentSelector), implemented by Hypothesis and dokieli; Xanadu's
enfilades, istream/vstream and edit decision lists are the ancestors of a document as a list
of `&`-references to spans elsewhere, transclusion included; CTS URNs and Stephanus/Bekker
numbering are addresses that survive re-edition, which is `$` identity with an
edition-independent scheme; Peritext is the span under concurrent edits. For ingestion:
hOCR, ALTO and PAGE are zone markup — coordinates plus text, the same node again — and
enter as `⟪alto … alto⟫` dialect blocks on the bottom rung, produced by GROBID, PaperMage,
Tesseract, kraken. CollateX and Needleman–Wunsch are diff over prose, i.e. patch theory on
text. RDF, SPARQL and Datalog are the `/facts/` directory and `select` over the tab block,
not FML syntax. Nothing in the survey asked for a mechanism FML2 does not already have;
what it adds is spellings and evidence.

## 4. Markdown's defects, and the existing answer to each

The defects have one root: Markdown was a text-to-HTML shorthand with no grammar, and
CommonMark specified the shorthand's behaviour rather than a language. FML fixes them by
fiat of the printer law — one spelling per construct is canonical, the rest are errors —
and by the mechanisms the core already has. Nothing in this table needed a new one.

| defect | in CommonMark | in FML |
| --- | --- | --- |
| no grammar: emphasis is decided by left/right-flanking rules over delimiter runs, `***` and `*a**b*` by precedence tables | 130 pages of disambiguation | there is no asymmetric inline markup at all (Dyck-only). Emphasis is an island holding the element, `⟨“word” em⟩`, i.e. FML3 written inline; the first fill had `*`/`**` with three refusals and the properties showed exactly Markdown's ambiguities returning one by one (`*#a*`, `*a*b*`, `***`) — the refusals held, but the rule that removes the class is the pair |
| raw HTML passes through; nothing is inert | allowed, sanitised downstream | the FML tree is FON-data: inert, no evaluation in the reader; islands are `Code` until forced ([FON, parser dramas](02.03.03-fon.md#6-pre-empting-the-parser-dramas)) |
| indentation means three things: code block, list continuation, nothing | four spaces = code | tabs only; a tab nests under a bullet and is an error under a paragraph; code is an island or a `⟪⟫` block, never indentation |
| link reference definitions are global and unordered | resolved after parsing | a link is one token, `[[target\|label]]`, and the target is one of the three reference kinds: `name` petname, `$name` identity, `&hash` content, or a URL |
| no attributes; every extension invents `{.class #id}` | none | `{ }` is the dict pair; a block's properties are the tree's `{ }` (F16), not a spelling of their own |
| blocks have no identity: nothing is addressable or transcludable | none | identity and content references exist (`$`, `&`); span addressing comes from v0's patches over ABT edits, not from anchors |
| hard break is two trailing spaces, invisible | trailing spaces | a paragraph is a tuple of lines: the newline is kept in the tree (the line is the diff unit) and is whitespace to the renderer; trailing whitespace is an error |
| loose vs tight lists decided by blank lines inside the list | both allowed, rendered differently | a blank line ends the list; consecutive `-` lines are one list; there is no loose list |
| escapes: `\*`, `\#`, `\[` everywhere | backslash | no escapes (the affix discipline): a literal marker is a raw run `「[[x]]」`, the same mechanism as raw strings in code; shown-not-run code is the same raw run |
| lenient numbering, `1.` `1.` `1.` renumbered | any start number | ordered lists not yet in the grammar (F6); when they are, numbering is canonical or an error |
| tables, footnotes, math, wikilinks, tags are extensions with colliding syntax | out of scope | a table is the tab block FON already has; a tag is `#name`, the symbol; a wikilink is `[[…]]`; math is an island; footnotes open (F11) |
| `#hashtag` vs heading ambiguity | heading only with space | `# ` at line start is a heading; `#word` after whitespace is a symbol — the same `#name` as in code |
| inline code span ``x``: same glyph opens and closes, doubled for a literal backtick | backtick runs | out with the rest of the asymmetric marks; `「dup ⍴」` shows, `⟨dup ⍴⟩` runs |
| Postel: tolerate and render anyway | everything renders | no tolerance ([grammar, no Postel](02.03.02-grammar.md#8-no-postel)): unmatched, unbalanced, space-indented input is refused with the line named |

## 5. The grammar (`fml.py`: pre-lexer, line lexer, `fml.lark`, inline scanner)

The same layering as the [surface grammar](02.03.02-grammar.md#1-layers-and-what-lives-where),
one layer added for prose (Lark 1.3.1, Hypothesis 6.168):

| layer | class | how |
| --- | --- | --- |
| pre-lexer | Dyck, counted per pair | `⟨ ⟩` islands, `「 」` raw runs, `⟦ ⟧` comments (dropped) counted by their own opener/closer; `“ ”` counted and *kept* as text whose interior is scanned again (islands inside quotes work); `⟪name … name⟫` by named closer. Placeholders `¶islN` etc. as in the grammar page. Inside an island the string pre-lexer runs before the FPL grammar, so `⟨“word” em⟩` parses |
| line lexer | Type-1 → tokens | tabs only, one per level; emits `HEAD` `BULLET` `QLINE` `LINE` `DIALECT` `BLANK` `INDENT` `DEDENT`; leading spaces, trailing whitespace and an indent deeper than depth+1 are errors naming the line |
| block grammar | Type-2, LALR | below |
| inline scanner | Type-3 per line, no stack | Dyck only: `[[target\|label]]`, `#tag` after whitespace, and the pre-lexer's placeholders; everything else is text. There is nothing to get wrong, which is the point |

```
start: BLANK* (block BLANK*)*
?block: heading | list | quote | dialect | para
heading: HEAD                                      // "#{1,6} " + inline
list: item+                                        // consecutive "- " lines; a blank line ends the list
item: BULLET (INDENT BLANK* (block BLANK*)+ DEDENT)?   // children one tab deeper
quote: QLINE+                                      // a run of "> " lines is one paragraph
dialect: DIALECT                                   // ⟪name … name⟫ on a line of its own
para: LINE+                                        // one run-tuple per line; the newline is kept
%declare HEAD BULLET QLINE LINE DIALECT BLANK INDENT DEDENT
```

Inline runs: `text`, `link (target, label)`, `tag`, `island` (an FPL tree with its string
stash), `raw`, `quo (runs)`. The example file, in canonical form as the printer emits it
(tabs shown as indentation):

```
# FML: the markup companion

A file is the interior of one string: prose outside, code inside. The mean of
⟨1 2 3 mean⟩ is shown here; the word itself is defined below, in the same file.

⟨mean : xs -- x
	xs [ + ] fold xs shape first ÷⟩

## Why ⟨“this” em⟩ and not ⟨“that” strong⟩

- headings, bullets and quotes keep their Markdown spelling, one per line
- a tag is a symbol: #pkm #fpl
	- nesting is a tab, never spaces
	- a wikilink names by petname [[fon|the FON tab]], by identity [[$fon]] or by content [[&sha256/00]]
- shown code is a raw run: 「dup ⍴」; an island is run: ⟨2 3 +⟩
- a literal marker is a raw run: 「[[not a link]]」

> Quotes are lines beginning with a bar of their own.
> Two lines, one paragraph.

⟪md
| a | b |
|---|---|
md⟫

She said “this ⟨1 1 +⟩ is ⟨“inside” em⟩ a quotation”.
```

The definition island parses as an FPL head line with a body block (the FPL indenter runs
inside the island), and `[+]` canonicalises to `[ + ]` through the FPL printer: one printer
per pair, the pair names the printer as it names the interpreter. The block comment is
dropped, which is the one place the file is not its own canonical form; trivia by identity
is owed here as in the grammar page (settled by
[S48](02.03.06-spellings-and-comments.md#5-comments-s33-s48)).

## 6. The printer, and the two laws as properties

`pprint : Doc → text`, canonical form: headings `#…` + one space; bullets `- ` with one tab
per level; quotes `> ` per line; paragraph lines as written, stripped; blocks separated by
one blank line; inline link `[[target|label]]`, tag `#name`, island `⟨…⟩` printed by the FPL
printer with its strings restored, raw `「…」`, quotes `“…”`; dialect blocks verbatim. A
hand-written tree strategy generates documents up to five blocks, list nesting depth 2,
inline nesting depth 2, islands drawn from a small FPL vocabulary. Rung: **trede 2**.

| property | examples | result |
| --- | --- | --- |
| `parse ∘ print = id` on trees | 2000 | holds |
| `print ∘ parse` idempotent on generated source | 2000 | holds |
| the example file above: both laws | 1 | hold |
| the same two laws before the Dyck-only change, with `*`/`**`/backtick in the grammar | 2000 each | held, after three refusals were added (below) |

What the properties found in the first fill, when `*` and `**` were still in: `*#a*` (a tag
directly after an opener was text); `*a*b*` (em inside em is `**`, the strong delimiter);
`***a** b*` (an em opening on a strong is `***`). Each was closed by a refusal and the laws
then held — and each is a CommonMark flanking case returning, which is what decided the
Dyck-only rule: the refusals were correct and the class was still there. With the
asymmetric marks gone the inline scanner has no stack and the generator no shape
constraints. One shrunk case reported during a run with a stale module — a `⟪md⟫` block
under a bullet followed by a second list — did not reproduce on a clean run and is recorded
as not reproduced, not as fixed.

Hand-written cases:

| input | result |
| --- | --- |
| `see [[fon` | rejected: unclosed `[[` |
| `[[a b]]`, `[[ a ]]` | rejected: a space in the target, or padding |
| `[[a\|b c]]` | accepted: target `a`, label `b c` |
| `x ⟨1 2 +`, `a ⟩ b` | rejected: unclosed / closer without opener |
| `x ⟨“a ⟨1⟩ b” em⟩` | accepted: an island holding a string holding an island; round-trips |
| four-space indent under a bullet | rejected: indentation must be tabs |
| a tab-indented line under a paragraph | rejected: indent without a parent item |
| `- a` then a two-tab line | rejected: indent of 2 under 0 |
| `he said “hi` | rejected: unclosed `“` |
| `a␣` (trailing space) | rejected |
| `a *b* c`, `a `x` b` | accepted as plain text: no inline marks exist |
| `#tag alone` | accepted: a paragraph starting with a tag, not a heading |
| `see http://x//y and a // b` | accepted: `//` is text in prose |
| `snake_case _ ok` | accepted: `_` is text in prose |
| `「[[not a link]] ⟨1⟩」` | accepted: a raw run keeps every marker |
| `“a “b” c”` | accepted: quotes nest by counting |
| `a⇥b⇥c` | accepted as a paragraph line with tabs — a table only once F10 lands |

## 7. Not yet

- **F16, the outliner node**: decided in form (above); the harness step is the item rule
  gaining a `{ }` property line, the `( item { } … )` tree form, and the printer between
  them.
- **F15, the effect line on an island**, and the receiver's refusal before running: the
  `fpl://` half of the document/app question.
- **FML3's braced spelling and the printer between the two** (`# x` ↔ `( h1 “x” )`), which
  is what makes FML2 sugar rather than a format; with it, TEI round-trips as a dialect and
  the tree hashes like any FON value.
- **Tables** (F10) and blank-line rank: shared with the grammar's next step, one change for
  both.
- **Footnotes** (F11), **headings as sections** (F12), **ordered lists** (F6), **nested
  content in quotes** (F7).
- **PKM words** as dictionary entries, not syntax: tasks as task-DAG nodes, backlinks as the
  inverse of `[[…]]` over the store, queries as `select` over the tab block, transclusion as
  an island mentioning `$name` or `&hash`.
- **Overlap, standoff and transclusion** (settled in the
  [Discussion](../02.05-project/notes/02.05.10-discussion-design-notes.md), 2026-09-28): overlap
  is not solved but made impossible — the pre-lexer refuses overlapping counted pairs and
  imposes nothing on what is not a pair. It is carried in the two non-enclosures: milestones
  as atoms (`⌜em … em⌝`, tokens whose meaning comes from the `⟪tei … tei⟫` dialect; in FML2
  prose they are text) and standoff as records on identity. The record is the citation:
  `{ from $… to $… kind #em at ⟨…⟩ }` — endpoints are `$` (`$` names what was hashed at
  birth, an op; `&` names bytes), `at` is the frontier it was written at, and staleness is a
  diff between then and now, computed, never guessed. Evidence: the `v0/xanadu/transclusion`
  spike in the vcs repository, nine claims as nine tests, green on a clean clone (trede 2).
  The quote atom of that spike is FML's island: `⟨$…⟩` is one Dyck token in the string
  interior with its own identity. Records live in the log as a link-only `Cite` op, not as a
  sidecar file and not as a tab block; "sidecar" is a matter of whose mount, i.e. authority,
  not of file layout. Still open: the spelling of an atom endpoint as event plus offset
  (proposed `$⟨event⟩/⟨offset⟩`, a path under the identity); the printer between inline (TEI
  in the text) and standoff; and the gate — no standoff record is written until `Cite` is an
  op in the log rather than a table in memory. The substrate side is in
  [substrate](../02.04-explanation/02.04.04-substrate.md).
- **Rendering** to HTML and PDF through an existing renderer, kept as bottom-rung evidence
  that the tree is complete; not a substrate.
- **FML4 layout** (F18) and **FML5 imaging** (F17): named, sequenced after a residual
  exists, not started. The UI consequences are in [UI](../02.04-explanation/02.04.06-ui.md).
- **Serialisable comments** as trivia by identity, owed here as in the grammar page.
