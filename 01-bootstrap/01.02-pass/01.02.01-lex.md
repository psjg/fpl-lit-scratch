# 01.02.01 Lex

Source text comes in. Tokens go out, and with every character of them
the place in the source it came from.

Two rules of FPL's text cannot be left to a grammar. Strings “ ” and
「 」 and block comments ⟦ ⟧ nest, but each only by its own pair: in
`“a 「 b”` the 「 is a letter of the string and opens nothing. And
indentation is strict: tabs only, and no bracket left open across a
dedent below the line that opened it. A context-free grammar can count
neither. So a hand counter runs first, and Lark only ever sees code in
which both questions are settled. The Lark of this page cuts that code
into tokens, and the Lark of [01.02.02-parse](01.02.02-parse.md) reads
them.

The counter keeps one promise throughout. Every character of the code it
writes knows the offset in the source it came from, so that an error
found later, by the parser or by the type checker, is reported at a line
and a column the author can find.

The module opens by saying so, in a docstring that `help` shows to
whoever imports it.

```python
<<Say what the pre-lexer does
fpl/lex.py 1>>=
"""Count what the grammar cannot, before Lark reads the text.

:func:`prelex` counts each pair (strings “ ” and 「 」, block comments
⟦ ⟧) by its own pair only. A string becomes one placeholder with its
interior left in the source, and a block comment becomes a space or
nothing. It then refuses indentation with spaces and a dedent below the
line of a bracket still open. Every character of the :class:`Prelexed`
code keeps its source offset. After lexing, :func:`shape` reads a
token's sigil, kind and modifiers.
"""
```

## The plan

Pre-lexing, `prelex', is two steps, and in this order because the
second needs the first. `pairs' takes the strings and comments out, so
that a tab or a bracket inside a string is not mistaken for code. Then
`strict' holds the code that is left to the rules of indentation.

```python
<<Pre-lex a source>>=
def prelex(source: str, start: int = 0, end: int | None = None) -> Prelexed:
    r"""Pre-lex ``source[start:end]`` into code the grammar reads.

    Args:
        source: Text to read.
        start: Offset where reading starts.
        end: Offset where reading stops; the end of *source* by default.

    Returns:
        The code, ending in a newline, with the source offset of each of
        its characters and the strings it stashed.

    Raises:
        FplError: A pair is never closed, a closer has no opener, a line
            is indented with spaces outside brackets, a dedent goes
            below the line of a bracket still open, or a bracket closes
            nothing, closes the wrong opener or is never closed. The
            error is placed at the offending line and column of
            *source*.

    Examples:
        >>> prelex("a “b” c\n").code
        'a ¶  c\n\n'
        >>> prelex("x “ab\n")
        Traceback (most recent call last):
            ...
        fpl.errors.FplError: ERROR: 1:3 “ never closed
    """
    lexed = pairs(source, start, end)
    strict(source, lexed.code, lexed.origin)
    return lexed
```

The result is a `Prelexed'. Its `code' is what the grammar reads. Its
`origin' gives each character of the code the offset in the source it
came from, and holds one entry more than the code has characters: the
offset of the end, so that a token ending where the code ends still has
a place. Its `stash' holds the strings that were taken out.

```python
<<Describe what pre-lexing produces>>=
@dataclass(frozen=True)
class Prelexed:
    """The output of :func:`prelex`: grammar code with its origins."""

    #: The code the grammar reads; it ends in a newline.
    code: str
    #: Source offset of each character of *code*, then of the end.
    origin: tuple[int, ...]
    #: The string each placeholder stands for, by the placeholder's
    #: offset in *code*.
    stash: dict[int, Stashed]
```

The stash is keyed by the offset in the code of the placeholder that
stands for a string: in `\t“b”` the code is a tab, then the
placeholder, so the key is 1. Each entry, a `Stashed', says where the
string's interior lies in the source, between `start' and `end', which
is where the parser's reader of strings will look for it. Its `kind' is `str`
for “ ”, which interpolates ⟨ ⟩, and `raw` for 「 」, which does not.
Its `depth' counts the tabs before the line the string opens on: the
string's continuation lines drop that many (S26).

```python
<<Describe a stashed string>>=
@dataclass(frozen=True)
class Stashed:
    """A string's interior in the source, the range ``[start, end)``."""

    #: ``str`` for “ ”, which interpolates ⟨ ⟩; ``raw`` for 「 」, which
    #: does not.
    kind: Literal["str", "raw"]
    #: Source offset of the first interior character.
    start: int
    #: Source offset just past the last interior character.
    end: int
    #: Tabs before the line the string opens on; its continuation lines
    #: drop that many (S26).
    depth: int
```

Two strings side by side show both kinds, and the offsets: the code is
`¶ ¶`, so the second placeholder stands at offset 3, and its interior,
`b`, at offset 5 of the source.

```pycon
>>> prelex("“a” 「b」").stash
{0: Stashed(kind='str', start=1, end=2, depth=0), 3: Stashed(kind='raw', start=5, end=6, depth=0)}
```

## Places

An offset is what the counter works with; a line and a column is what an
author reads. `Lines' keeps the offset at which each line starts, and
its `span' finds the line of an offset by bisection. Lines and columns
count from 1, as an editor shows them, and a column counts characters:
a tab is one column, so the first character after one tab is in
column 2.

```python
<<Turn offsets into lines and columns>>=
class Lines:
    """Turn offsets into a source into lines and columns."""

    def __init__(self, source: str) -> None:
        """Index the lines of *source*."""
        #: Offset at which each line starts, the first line included.
        self.starts = [0] + [
            n + 1 for n, char in enumerate(source) if char == "\n"
        ]

    def span(self, offset: int) -> Span:
        r"""Return the 1-based line and column of a source offset.

        Args:
            offset: Position in the source; the end of the source is
                just past its last line.

        Examples:
            >>> Lines("ab\ncd").span(3)
            Span(line=2, col=1)
        """
        line = bisect_right(self.starts, offset)
        return Span(line, offset - self.starts[line - 1] + 1)
```

The offset just past the last character still has a place, at the end
of the last line; the parser reports there a failure it can place
nowhere else.

```pycon
>>> Lines("ab\ncd").span(3)
Span(line=2, col=1)
>>> Lines("ab\ncd").span(5)
Span(line=2, col=3)
```

## Strings and comments

The three pairs, `PAIRS', each opener with its closer:

```python
<<Name the characters of the pairs>>=
#: Opener to closer of each pair: string, raw string and block comment.
PAIRS = {"“": "”", "「": "」", "⟦": "⟧"}
```

Counting a pair, `counted', is counting its own opener and closer and
nothing else. That is the whole of the nesting rule: a 「 inside “ ” is
not seen, so pairs of different kinds cannot overlap, and a string can
hold any character but its own closer unbalanced. The
[fon](../01.01-boundary/01.01.02-fon.md) reader and the parser's ⟨ ⟩
islands count their pairs with the same function.

```python
<<Count one pair>>=
def counted(text: str, at: int, close: str, end: int) -> int | None:
    """Return the offset just past the closer that balances an opener.

    Only the opener's own pair is counted, so a nested opener of the
    same pair needs a closer of its own and other brackets are ignored.

    Args:
        text: Source holding the opener.
        at: Offset of the opener.
        close: Closer of that opener.
        end: Offset where counting stops; the closer lies before it.

    Returns:
        The offset after the balancing closer, or ``None`` if none
        occurs before *end*.

    Examples:
        >>> counted("“a”", 0, "”", 3)
        3
        >>> counted("“a“b”", 0, "”", 5) is None
        True
    """
    opener, depth, j = text[at], 1, at + 1
    while j < end and depth:
        depth += (text[j] == opener) - (text[j] == close)
        j += 1
    return None if depth else j
```

The answer is the offset just past the balancing closer, or None when
the text up to `end` holds no closer that balances. A nested opener of
the same pair counts against the one closer: in `“a“b”` the one ” closes
the inner “, and the outer is never closed.

```pycon
>>> counted("“a“b”", 0, "”", 5) is None
True
>>> counted("“a“b””", 0, "”", 6)
6
```

The counter copies code until the next character that starts something
it must handle: an opener, a closer, or a line comment, `;` or `⍝`. One
regular expression, `SPECIAL', finds the next of them. A string is
replaced in the code by a `PLACEHOLDER', `¶`, which the grammar reads as
one token.

```python
<<Name the marks the counter looks for>>=
#: Stands for a whole string in the code the grammar reads.
PLACEHOLDER = "¶"
#: The characters :func:`pairs` stops at: the openers and closers of the
#: pairs, and the marks ``;`` and ``⍝`` of a line comment.
SPECIAL = re.compile(r"[“「⟦”」⟧;⍝]")
```

The loop of `pairs' is then short, and what it writes is plain to
state. A string becomes the placeholder and one space after it, with a
space before it too when it follows a word directly: `a“b”` becomes the
code `a ¶ `. A block comment becomes no token at all. In the middle of a
line it becomes one space, so `a ⟦c⟧ b` becomes `a   b`, the space
before it, its own, and the one after it. At the start of a line, after
nothing but tabs, it vanishes together with the spaces that follow it,
so `⟦c⟧  a` becomes `a` and a tab before the comment stays. A line
comment is copied as it stands. And the code always ends in a newline,
which the code of every example below shows.

```pycon
>>> prelex("a ⟦c⟧ b").code
'a   b\n'
>>> prelex("\t⟦c⟧  a").code
'\ta\n'
```

Everything between two special characters goes into the code as it
stands; what a special character starts is written by `_special', which
says where copying resumes. The final newline is placed at the end of
the source. The pattern of special characters is a parameter,
`special', for the sake of one reader: fon has no line comments, and
passes a pattern of the pairs alone.

```python
<<Stash the strings and drop the block comments>>=
def pairs(
    source: str,
    start: int = 0,
    end: int | None = None,
    special: re.Pattern[str] = SPECIAL,
) -> Prelexed:
    """Stash the strings and drop the block comments of a source range.

    Indentation and brackets are not checked here; :func:`strict` does
    that.

    Args:
        source: Text to read.
        start: Offset where reading starts.
        end: Offset where reading stops; the end of *source* by default.
        special: The characters that open or close a pair or start a
            line comment.

    Returns:
        The code, ending in a newline, with the source offset of each of
        its characters and the strings it stashed.

    Raises:
        FplError: A pair is never closed, or a closer has no opener.
    """
    stop = len(source) if end is None else end
    code, at = _Code(), start
    while at < stop:
        found = special.search(source, at, stop)
        upto = found.start() if found else stop
        code.put(source[at:upto], at)
        at = _special(source, upto, stop, code) if found else stop
    code.put("\n", stop)
    return Prelexed("".join(code.chars), (*code.origin, stop), code.stash)
```

The code is written into a `_Code', which keeps beside each character
the offset it came from. Its `put' appends text. Most text is copied,
and then each character keeps its own offset. A pad or a placeholder is
not in the source; every character of it gets the offset of the thing
it stands for.

```python
<<Write code that remembers its origin>>=
class _Code:
    """Collect the code being written, with each character's origin."""

    def __init__(self) -> None:
        self.chars: list[str] = []
        self.origin: list[int] = []
        self.stash: dict[int, Stashed] = {}

    def put(self, text: str, at: int, verbatim: bool = True) -> None:
        """Append *text* to the code.

        Args:
            text: Characters to append.
            at: Source offset the text comes from.
            verbatim: If true, character *k* of *text* has origin
                ``at + k``; if false, as for a pad or placeholder, every
                character has origin *at*.
        """
        self.chars.extend(text)
        self.origin.extend(
            at + k if verbatim else at for k in range(len(text))
        )

    <<Tell whether the code is at the start of a line>>
```

So a string of two letters becomes a placeholder and a pad that both
point at its opener, and the closing newline and the end point at the
end of the source:

```pycon
>>> prelex("“ab”").origin
(0, 0, 4, 4)
```

A block comment that is the first thing on its line must vanish without
leaving a space, or the line's indentation would change. So the code
answers, by `at_line_start', whether nothing but tabs was written since
the last newline.

```python
<<Tell whether the code is at the start of a line>>=
def at_line_start(self) -> bool:
    """Tell whether only tabs came since the last newline."""
    for char in reversed(self.chars):
        if char != "\t":
            return char == "\n"
    return True
```

A special character is one of three things. An opener starts a pair. A
closer found here closes nothing, because a balanced closer is consumed
with its opener. Anything else is a line comment, which is copied up to
the end of its line: the grammar reads it as a note or a doc, whose
meaning depends on where it stands, so it keeps its place.

```python
<<Write what a special character starts>>=
def _special(source: str, at: int, end: int, code: _Code) -> int:
    """Write what starts with a special character.

    A pair goes to :func:`_pair`, a closer with no opener is refused,
    and anything else is a line comment, copied up to its newline.

    Args:
        source: Text being read.
        at: Offset of the special character.
        end: Offset where reading stops.
        code: The code being written.

    Returns:
        The offset where the next write starts.

    Raises:
        FplError: The character is a closer with no opener, or opens a
            pair that is never closed.
    """
    char = source[at]
    if char in PAIRS:
        return _pair(source, at, end, code)
    if char in CLOSERS:
        raise FplError(Lines(source).span(at), f"{char} closes nothing")
    newline = source.find("\n", at, end)
    after = end if newline < 0 else newline
    code.put(source[at:after], at)
    return after
```

A pair, written by `_pair', that never closes is refused at its opener.
Otherwise a block comment becomes nothing and a string becomes a
placeholder.

## Strict indentation

With the strings out, a bracket in the code is a bracket. There are
four kinds, `BRACKETS'. `CLOSERS' maps every closer, of a pair or a
bracket, back to its opener; `_special' above uses it to refuse a lone
closer of a pair.

```python
<<Name the characters of the brackets>>=
#: Opener to closer of each bracket.
BRACKETS = {"[": "]", "(": ")", "⟨": "⟩", "{": "}"}
#: Closer to opener, for the pairs of :data:`PAIRS` and the brackets of
#: :data:`BRACKETS`.
CLOSERS = {close: opener for opener, close in (PAIRS | BRACKETS).items()}
```

The rules are checked on the code but reported in the source. `strict'
does the translation: a refusal carries an offset in the code, and the
origin table turns it into a place the author sees.

```python
<<Hold the code to strict indentation>>=
def strict(source: str, code: str, origin: tuple[int, ...]) -> None:
    """Refuse loose indentation in code, at its place in the source.

    Args:
        source: Text the code was lexed from.
        code: The code from :func:`pairs`.
        origin: Source offset of each character of *code*, then of the
            end.

    Raises:
        FplError: A line is indented with spaces outside brackets, a
            dedent goes below the line of a bracket still open, or a
            bracket closes nothing, closes the wrong opener or is never
            closed.
    """
    lines = Lines(source)
    try:
        _lines(code, lambda offset: lines.span(origin[offset]).line)
    except _RefusalError as refusal:
        raise FplError(
            lines.span(origin[refusal.offset]), refusal.message
        ) from None
```

The refusal is an exception of this module only, `_RefusalError',
because the checker below knows offsets in the code and nothing of the
source. It never leaves `strict'.

```python
<<Carry a refusal to its place in the source>>=
class _RefusalError(Exception):
    """A strictness refusal at a code offset, not yet placed."""

    def __init__(self, offset: int, message: str) -> None:
        super().__init__(message)
        self.offset = offset
        self.message = message
```

The checker, `_lines', reads the code a line at a time. A line's depth
is its leading tabs. Two things are refused before the line's brackets
are counted, and one at the end: a bracket still open when the code
runs out.

```python
<<Refuse loose indentation, line by line>>=
def _lines(code: str, line_of: Callable[[int], int]) -> None:
    """Refuse loose indentation, line by line.

    A dedent below the line of a bracket still open is reported at the
    dedenting line and names the opener's line.

    Args:
        code: The code to check.
        line_of: Maps an offset in *code* to its source line number.

    Raises:
        _RefusalError: A line is indented with spaces outside brackets,
            a dedent goes below the line of a bracket still open, or a
            bracket is never closed. A bracket error of
            :func:`_brackets` passes through.
    """
    open_: list[tuple[str, int, int]] = []
    base = 0
    for line in code.split("\n"):
        depth = len(line) - len(line.lstrip("\t"))
        <<Refuse a line indented with spaces>>
        <<Refuse a dedent below a bracket still open>>
        _brackets(line, base, depth, open_)
        base += len(line) + 1
    if open_:
        raise _RefusalError(open_[-1][1], f"{open_[-1][0]} never closed")
```

Inside brackets a line may be aligned as the author likes; outside them
indentation is tabs, and a space after the tabs is refused.

```python
<<Refuse a line indented with spaces>>=
if not open_ and line[depth : depth + 1] == " ":
    raise _RefusalError(base + depth, "indentation must be tabs")
```

A bracket opened on a line belongs to that line's block. A non-blank
line that dedents below it while it is open would leave the block with
the bracket still unclosed, so it is refused at the dedenting line, and
the message names the line of the opener.

```python
<<Refuse a dedent below a bracket still open>>=
if open_ and line.strip() and depth < open_[-1][2]:
    opener, opened, _ = open_[-1]
    message = (
        f"dedent below line {line_of(opened)}, "
        f"but its {opener} is still open"
    )
    raise _RefusalError(base + depth, message)
```

The brackets of one line are tracked by `_brackets' on a stack of the
open ones, each with its offset and the depth of the line that opened
it. A closer must close the latest opener; one that closes nothing, or
the wrong kind, is refused where it stands.

```python
<<Track the brackets of one line>>=
def _brackets(
    line: str, base: int, depth: int, open_: list[tuple[str, int, int]]
) -> None:
    """Track the brackets of one code line, ignoring its line comment.

    Args:
        line: The line, without its newline.
        base: Offset in the code of the line's first character.
        depth: Tabs at the start of the line.
        open_: Stack of the open brackets as (bracket, offset in the
            code, depth), updated in place.

    Raises:
        _RefusalError: A closer closes nothing, or does not close the
            latest opener.
    """
    body = LINE_COMMENT.split(line, maxsplit=1)[0]
    for n, char in enumerate(body):
        if char in BRACKETS:
            open_.append((char, base + n, depth))
        elif char in CLOSERS and not open_:
            raise _RefusalError(base + n, f"{char} closes nothing")
        elif char in CLOSERS and open_[-1][0] != CLOSERS[char]:
            raise _RefusalError(
                base + n, f"{char} does not close {open_[-1][0]}"
            )
        elif char in CLOSERS:
            open_.pop()
```

A line comment is not code, so the brackets in it do not count:
`_brackets' cuts the line at the first comment mark, `;` or `⍝`, which
`LINE_COMMENT' finds.

```python
<<Name the marks the counter looks for>>+=
#: A line comment: a run of ``;`` or one ``⍝``, up to the end of the
#: line.
LINE_COMMENT = re.compile(r"(;+|⍝)[^\n]*")
```

Every refusal of this page, then, with the place in the source it is
reported at. A refusal prints as the one line an error case of the
walker holds, `ERROR: line:column message`, and the message names the
character itself.

| Refused | Reported at | Message |
| --- | --- | --- |
| an opener, “ 「 ⟦, whose own closer never balances it | the opener | `“ never closed` |
| a closer of a pair, ” 」 ⟧, with no opener of its own before it | the closer | `」 closes nothing` |
| a space after the leading tabs of a line, outside every bracket | the space | `indentation must be tabs` |
| a non-blank line indented less than the line of a bracket still open | the first character after the tabs | `dedent below line 1, but its [ is still open` |
| a closer of a bracket when no bracket is open | the closer | `] closes nothing` |
| a closer of a bracket that is not the latest opener's | the closer | `) does not close [` |
| a bracket still open when the code ends | the bracket | `[ never closed` |

Inside an open bracket a line may begin with spaces, so `[`, a newline,
then `  a ]` is accepted; a bracket inside a block comment or after a
line comment is not code and is not counted. Four refusals in full:

```pycon

>>> prelex("\ta [\nb ]\n")
```

## The shape of a token

One reader belongs here although it runs after Lark: the affix pass of
the parser asks of each token what shape it has. A token is an optional
prefix sigil, a body, and modifiers, `MODS', that may stand only at its
end. The sigils are `->`, `→`, `$`, `#`, `&`, `../` and `..`; the
modifiers are the six marks ´ ` ¨ ˜ ⁼ ˙. `SHAPE' cuts a token into the
three; `NUMBER' tells a number's body: an optional minus, digits with an
optional fraction, or ∞, or π.

```python
<<Name the characters of a token's shape>>=
#: The modifier characters that may end a token.
MODS = "\u00b4`\u00a8\u02dc\u207c\u02d9"
#: A token as sigil, body and trailing :data:`MODS`, the groups
#: :func:`shape` reads.
SHAPE = re.compile(rf"(->|→|\$|#|&|\.\./|\.\.)?([^{MODS}]*?)([{MODS}]*)")
#: A number body: an optional minus, then digits with an optional
#: fraction, ``∞`` or ``π``.
NUMBER = re.compile(r"-?(\d+(\.\d+)?|∞|π)")
```

The body decides the kind that `shape' gives, and the body is what is
left once the sigil and the modifiers are cut off: nothing at all is a
lone modifier, so `´` alone is the kind `modifier` with the body `('',)`;
a number is a number; a body with a `/` is a path, given as its segments
split at each `/`, so `1/2` is the path `('1', '2')` and `../a/b` the
sigil `../` before the path `('a', 'b')`; anything else is a name, whose
body is the one segment. The body is always a tuple, of one segment
unless the token is a path: `abc` is `('', 'name', ('abc',), '')`. A
modifier anywhere but at the end makes no shape, and the parser refuses
the token.

```python
<<Read a token's shape>>=
def shape(token: str) -> tuple[str, Kind, tuple[str, ...], str] | None:
    """Split a token into prefix sigil, kind, body and suffix modifiers.

    Args:
        token: One token of lexed code.

    Returns:
        A tuple of the prefix sigil (``""`` for none), the kind, the
        body (the segments of a path, else the one-element name) and the
        modifiers of :data:`MODS`; ``None`` when a modifier stands
        anywhere but at the end.

    Examples:
        >>> shape("->x´")
        ('->', 'name', ('x',), '´')
        >>> shape("a/b")
        ('', 'path', ('a', 'b'), '')
        >>> shape("a´b") is None
        True
    """
    match = SHAPE.fullmatch(token)
    if match is None:
        return None
    prefix, body, mods = match.group(1) or "", match.group(2), match.group(3)
    kind: Kind = (
        "modifier"
        if not body
        else "number"
        if NUMBER.fullmatch(body)
        else "path"
        if "/" in body
        else "name"
    )
    return (
        prefix,
        kind,
        tuple(body.split("/")) if kind == "path" else (body,),
        mods,
    )
```

```pycon
>>> shape("$a/b˙")
('$', 'path', ('a', 'b'), '˙')
>>> shape("-1.5")
('', 'number', ('-1.5',), '')
>>> shape("a´b") is None
True
```

## The token stage

The seed walker stops at the pre-lexer: its parser hands the code to a
Lark that lexes and parses in one go. The literate tree splits the two,
so that `lex', a stage of its own, can be run and looked at alone. It
reads the token rules from the parser's grammar, `GRAMMAR', the file
next to the package.

```python
<<Find the token grammar>>=
GRAMMAR = Path(__file__).resolve().parents[1] / "grammar.lark"
```

The stage's output, `Tokens', keeps the `source', the pre-lexed text,
`lexed', and the tokens themselves, `raw': each its type, its text and
where it starts and ends in the code.

```python
<<Describe the tokens a stage hands on>>=
@dataclass(frozen=True)
class Tokens:
    """
    The lexer's output: the pre-lexed text and the tokens the second
    Lark will read.
    """

    source: str
    lexed: Prelexed
    raw: tuple[tuple[str, str, int, int], ...]
```

Building a Lark from the grammar takes about 80 ms, far longer than
lexing a line, so it is built once, when first asked for, by
`token_lark', and kept in `_LEXER'. It is asked
only to lex, never to parse; `code_tokens' asks it for the tokens of
code the pre-lexer produced.

```python
<<Build the token Lark once>>=
_LEXER: Lark | None = None


def token_lark() -> Lark:
    """
    The lexer Lark. It does not parse.
    """
    global _LEXER
    if _LEXER is None:
        _LEXER = Lark(
            GRAMMAR.read_text(),
            parser="lalr",
            propagate_positions=True,
            maybe_placeholders=False,
        )
    return _LEXER


def code_tokens(code: str) -> list:
    """
    Tokens for code the pre-lexer already produced.
    """
    return list(token_lark().lex(code))
```

The stage itself, `lex', pre-lexes, lexes, and packs each token into
the four plain values that `Tokens' keeps, so that the next stage can
read them without Lark. It is a `Pass' from Source to Tokens.

```python
<<Run the stage>>=
def _pack(got: list) -> tuple[tuple[str, str, int, int], ...]:
    return tuple(
        (token.type, str(token), token.start_pos or 0, token.end_pos or 0)
        for token in got
    )


def _lex(source: str) -> Tokens:
    lexed = prelex(source)
    return Tokens(source, lexed, _pack(code_tokens(lexed.code)))


lex = Pass("lex", _lex, source="Source", target="Tokens")
```
