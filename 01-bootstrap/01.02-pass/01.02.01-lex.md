# 01.02.01 Lex

Source text comes in. Code that a Lark grammar can read goes out, and
with it the place in the source of every character it holds.

Two rules of FPL's text cannot be left to a grammar. Strings “ ” and
「 」 and block comments ⟦ ⟧ nest, but each only by its own pair: in
`“a 「 b”` the 「 is a letter of the string and opens nothing. And
indentation is strict: tabs only, and no bracket left open across a
dedent below the line that opened it. A context-free grammar can count
neither. So a hand counter runs first, and the Lark of
[01.02.02-parse](01.02.02-parse.md) sees code in which both questions
are settled.

The counter keeps one promise throughout. Every character of the code it
writes knows the offset in the source it came from, so that an error
found later, by the parser or by the type checker, is reported at a line
and a column the author can find.

## The plan

Pre-lexing is two steps, in this order because the second needs the
first: the strings and comments are taken out, so that a tab or a bracket
inside a string is not mistaken for code; then the code that is left is
held to the indentation rules.

```python
<<Pre-lex a source>>=
def prelex(source: str, start: int = 0, end: int | None = None) -> Prelexed:
    """Pre-lex source[start:end] to code the grammar reads."""
    lexed = pairs(source, start, end)
    strict(source, lexed.code, lexed.origin)
    return lexed
```

The result is a `Prelexed`: the code, the origin of each of its
characters, and the strings that were taken out. `origin` holds one entry
more than `code` has characters, the offset of the end, so that a token
that ends where the code ends still has a place.

```python
<<Describe what pre-lexing produces>>=
@dataclass(frozen=True)
class Prelexed:
    """Code for the grammar, each character's origin, and the stash."""

    code: str
    origin: tuple[int, ...]
    stash: dict[int, Stashed]
```

The stash is keyed by the offset in the code of the placeholder that
stands for a string. It records where the string's interior lies in the
source, where the parser's reader of strings will read it.
`kind` is `str` for “ ”, which interpolates ⟨ ⟩, and `raw` for 「 」,
which does not. `depth` counts the tabs before the line the string opens
on: its continuation lines drop that many (S26).

```python
<<Describe a stashed string>>=
@dataclass(frozen=True)
class Stashed:
    """A string's interior, [start, end) in the source."""

    kind: Literal["str", "raw"]
    start: int
    end: int
    depth: int
```

one reader that runs after Lark: the affix pass's `shape`. The file
Python reads lists the definitions in the order Python needs, which is
not this one; `Stashed` has to exist before `Prelexed` names it.

## Places

An offset is what the counter works with; a line and a column is what an
author reads. `Lines` keeps the offset at which each line starts, and
finds a line by bisection. Columns count from 1, as an editor shows them.

```python
<<Turn offsets into lines and columns>>=
class Lines:
    """Offsets into a source as an editor's 1-based line and column."""

    def __init__(self, source: str) -> None:
        self.starts = [0] + [
            n + 1 for n, char in enumerate(source) if char == "\n"
        ]

    def span(self, offset: int) -> Span:
        """The line and column of a source offset."""
        line = bisect_right(self.starts, offset)
        return Span(line, offset - self.starts[line - 1] + 1)
```

An offset just past the last character still has a line, the last one;
that is the place of an error such as a pair never closed.

## Strings and comments

The three pairs, each opener with its closer:

```python
<<Name the characters of the pairs>>=
PAIRS = {"“": "”", "「": "」", "⟦": "⟧"}
```

Counting a pair is counting its own opener and closer and nothing else.
That is the whole of the nesting rule: a 「 inside “ ” is not seen, so
pairs of different kinds cannot overlap, and a string can hold any
character but its own closer unbalanced. The [fon](../01.01-boundary/01.01.02-fon.md)
reader and the parser's ⟨ ⟩ islands count their pairs with the same
function.

```python
<<Count one pair>>=
def counted(text: str, at: int, close: str, end: int) -> int | None:
    """The offset past the closer balancing text[at], or None."""
    opener, depth, j = text[at], 1, at + 1
    while j < end and depth:
        depth += (text[j] == opener) - (text[j] == close)
        j += 1
    return None if depth else j
```

The counter copies code until the next character that starts something
it must handle, an opener, a closer, or a line comment, `;` or `⍝`. One
regular expression finds the next of them. A string is replaced in the
code by a placeholder, `¶`, which the grammar reads as one token.

```python
<<Name the marks the counter looks for>>=
PLACEHOLDER = "¶"
SPECIAL = re.compile(r"[“「⟦”」⟧;⍝]")
```

The loop is then short. Everything between two special characters goes
into the code as it stands; what a special character starts is written by
`_special`, which says where copying resumes. The code always ends in a
newline, placed at the end of the source.

```python
<<Stash the strings and drop the block comments>>=
def pairs(
    source: str,
    start: int = 0,
    end: int | None = None,
    special: re.Pattern[str] = SPECIAL,
) -> Prelexed:
    """Stash strings and drop block comments of source[start:end]."""
    stop = len(source) if end is None else end
    code, at = _Code(), start
    while at < stop:
        found = special.search(source, at, stop)
        upto = found.start() if found else stop
        code.put(source[at:upto], at)
        at = _special(source, upto, stop, code) if found else stop
    code.put("\n", stop)
    return Prelexed("".join(code.chars), (*code.origin, stop), code.stash)
```

`special` is a parameter for one reader: fon has no line comments, and
passes a pattern of the pairs alone.

The code is written into a `_Code`, which keeps beside each character the
offset it came from. Most text is copied, and then each character keeps
its own offset. A pad or a placeholder is not in the source; every
character of it gets the offset of the thing it stands for.

```python
<<Write code that remembers its origin>>=
class _Code:
    """The code being written, each character with its source offset."""

    def __init__(self) -> None:
        self.chars: list[str] = []
        self.origin: list[int] = []
        self.stash: dict[int, Stashed] = {}

    def put(self, text: str, at: int, verbatim: bool = True) -> None:
        """Append text from source offset `at`."""
        self.chars.extend(text)
        self.origin.extend(
            at + k if verbatim else at for k in range(len(text))
        )

    <<Tell whether the code is at the start of a line>>
```

A block comment that is the first thing on its line must vanish without
leaving a space, or the line's indentation would change. So the code
answers whether nothing but tabs was written since the last newline.

```python
<<Tell whether the code is at the start of a line>>=
def at_line_start(self) -> bool:
    """Nothing but tabs written since the last newline."""
    for char in reversed(self.chars):
        if char != "\t":
            return char == "\n"
    return True
```

A special character is one of three things. An opener starts a pair. A
closer found here closes nothing, because a balanced closer is consumed
with its opener. Anything else is a line comment, which is copied up to
the end of its line: the grammar reads it as a note or a doc, whose
meaning depends on where it stands, so it keeps its place.

```python
<<Write what a special character starts>>=
def _special(source: str, at: int, end: int, code: _Code) -> int:
    """Write what source[at] starts; return where copying resumes."""
    char = source[at]
    if char in PAIRS:
        return _pair(source, at, end, code)
    if char in CLOSERS:
        raise FplError(Lines(source).span(at), f"{char} closes nothing")
    newline = source.find("\n", at, end)
    after = end if newline < 0 else newline
    code.put(source[at:after], at)
    return after
```

A pair that never closes is refused at its opener. Otherwise a block
comment becomes nothing and a string becomes a placeholder.

```python
<<Write one pair>>=
def _pair(source: str, at: int, end: int, code: _Code) -> int:
    """Write the pair opening at `at`; return the offset after it."""
    opener = source[at]
    after = counted(source, at, PAIRS[opener], end)
    if after is None:
        raise FplError(Lines(source).span(at), f"{opener} never closed")
    if opener == "⟦":
        <<Drop the block comment>>
    <<Stash the string behind a placeholder>>
```

A block comment at the start of a line takes the spaces after it with
it, so that what follows starts the line at the comment's indentation.
Anywhere else it leaves one space, so that the words on either side of
it do not run together.

```python
<<Drop the block comment>>=
if code.at_line_start():
    return (
        len(source[after:end])
        - len(source[after:end].lstrip(" "))
        + after
    )
code.put(" ", at)
return after
```

A string is separated from the word before it by a space, so the
placeholder is a token of its own. Its depth is counted on the line it
opens on. The placeholder and the space after it both take the offset
of the opener.

```python
<<Stash the string behind a placeholder>>=
if code.chars and code.chars[-1] not in " \t\n":
    code.put(" ", at)
line = source.rfind("\n", 0, at) + 1
depth = len(source[line:at]) - len(source[line:at].lstrip("\t"))
code.stash[len(code.chars)] = Stashed(
    "str" if opener == "“" else "raw", at + 1, after - 1, depth
)
code.put(PLACEHOLDER + " ", at, verbatim=False)
return after
```

## Strict indentation

With the strings out, a bracket in the code is a bracket. The four kinds:

```python
<<Name the characters of the brackets>>=
BRACKETS = {"[": "]", "(": ")", "⟨": "⟩", "{": "}"}
CLOSERS = {close: opener for opener, close in (PAIRS | BRACKETS).items()}
```

`CLOSERS` maps every closer, of a pair or a bracket, back to its opener;
`_special` above uses it to refuse a lone closer of a pair.

The rules are checked on the code, but reported in the source. `strict`
does the translation: a refusal carries an offset in the code, and the
origin table turns it into a place the author sees.

```python
<<Hold the code to strict indentation>>=
def strict(source: str, code: str, origin: tuple[int, ...]) -> None:
    """Hold the code to strict indentation, refusing in the source."""
    lines = Lines(source)
    try:
        _lines(code, lambda offset: lines.span(origin[offset]).line)
    except _RefusalError as refusal:
        raise FplError(
            lines.span(origin[refusal.offset]), refusal.message
        ) from None
```

The refusal is an exception of this module only, because the checker
below knows offsets in the code and nothing of the source. It never
leaves `strict`.

```python
<<Carry a refusal to its place in the source>>=
class _RefusalError(Exception):
    """A refusal at a code offset, before it is placed in the source."""

    def __init__(self, offset: int, message: str) -> None:
        super().__init__(message)
        self.offset = offset
        self.message = message
```

The checker reads the code a line at a time. A line's depth is its
leading tabs. Two things are refused before the line's brackets are
counted, and one at the end.

```python
<<Refuse loose indentation, line by line>>=
def _lines(code: str, line_of: Callable[[int], int]) -> None:
    """Refuse spaces that indent, and a dedent past an open bracket."""
    open_: list[tuple[str, int, int]] = []
    base = 0
    for line in code.split("\n"):
        depth = len(line) - len(line.lstrip("\t"))
        <<Refuse a line indented with spaces>>
        <<Refuse a dedent below a bracket still open>>
        _brackets(line, base, depth, open_)
        base += len(line) + 1
    if open_:
        raise _RefusalError(open_[-1][1], f"{open_[-1][0]} never closed")
```

Inside brackets a line may be aligned as the author likes; outside them
indentation is tabs, and a space after the tabs is refused.

```python
<<Refuse a line indented with spaces>>=
if not open_ and line[depth : depth + 1] == " ":
    raise _RefusalError(base + depth, "indentation must be tabs")
```

A bracket opened on a line belongs to that line's block. A non-blank
line that dedents below it while it is open would leave the block with
the bracket still unclosed, so it is refused at the dedenting line, and
the message names the line of the opener.

```python
<<Refuse a dedent below a bracket still open>>=
if open_ and line.strip() and depth < open_[-1][2]:
    opener, opened, _ = open_[-1]
    message = (
        f"dedent below line {line_of(opened)}, "
        f"but its {opener} is still open"
    )
    raise _RefusalError(base + depth, message)
```

The brackets of one line are tracked on a stack of the open ones, each
with its offset and the depth of the line that opened it.

```python
<<Track the brackets of one line>>=
def _brackets(
    line: str, base: int, depth: int, open_: list[tuple[str, int, int]]
) -> None:
    """Track one line's brackets on the stack of open ones."""
    body = LINE_COMMENT.split(line, maxsplit=1)[0]
    for n, char in enumerate(body):
        if char in BRACKETS:
            open_.append((char, base + n, depth))
        elif char in CLOSERS and not open_:
            raise _RefusalError(base + n, f"{char} closes nothing")
        elif char in CLOSERS and open_[-1][0] != CLOSERS[char]:
            raise _RefusalError(
                base + n, f"{char} does not close {open_[-1][0]}"
            )
        elif char in CLOSERS:
            open_.pop()
```

A line comment is not code, so the brackets in it do not count:
`_brackets` cuts the line at the first comment mark, `;` or `⍝`,
which this pattern finds.

```python
<<Name the marks the counter looks for>>+=
LINE_COMMENT = re.compile(r"(;+|⍝)[^\n]*")
```

## The shape of a token

One reader belongs here although it runs after Lark: the affix pass of
the parser asks of each token what shape it has. A token is an optional
prefix sigil, a body, and modifiers that may stand only at its end.

```python
<<Name the characters of a token's shape>>=
MODS = "\u00b4`\u00a8\u02dc\u207c\u02d9"
SHAPE = re.compile(rf"(->|→|\$|#|&|\.\./|\.\.)?([^{MODS}]*?)([{MODS}]*)")
NUMBER = re.compile(r"-?(\d+(\.\d+)?|∞|π)")
```

The body decides the kind: nothing at all is a lone modifier, a number
is a number, a body with a `/` is a path whose segments are kept apart,
and anything else is a name. A modifier anywhere but at the end makes no
shape, and the parser refuses the token.

```python
<<Read a token's shape>>=
def shape(token: str) -> tuple[str, Kind, tuple[str, ...], str] | None:
    """A token's prefix, kind, body and modifiers, or None."""
    match = SHAPE.fullmatch(token)
    if match is None:
        return None
    prefix, body, mods = match.group(1) or "", match.group(2), match.group(3)
    kind: Kind = (
        "modifier"
        if not body
        else "number"
        if NUMBER.fullmatch(body)
        else "path"
        if "/" in body
        else "name"
    )
    return (
        prefix,
        kind,
        tuple(body.split("/")) if kind == "path" else (body,),
        mods,
    )
```
