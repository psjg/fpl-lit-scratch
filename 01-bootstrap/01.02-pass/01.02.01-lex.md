# 01.02.01 Lex

A grammar is a poor counter. Lark can say that a string opens with
`“` and closes with `”`, but it cannot say that the `”` it found is
the one that closes *this* `“` when the string itself holds a nested
pair, and it has no opinion at all on whether a line is indented by
tabs. FPL leans on both. So before [01.02.02 Parse](01.02.02-parse.md)
hands the text to its grammar, this pass reads it once by hand and does
the counting. What comes out is code the grammar can read without
counting, plus enough bookkeeping that every error, however late, can
still point at the character the author typed.

This page tangles to [fpl/lex.py](../fpl/lex.py).

The pass has two halves, and they are told here in the order they run.
The first half, *pairs*, finds the strings and the block comments. A
string's interior is taken out of the code and stashed, and a single
placeholder stands in its place; a block comment disappears. The second
half, *strict*, looks at what is left and refuses loose indentation.
After both, a small third piece, *shape*, is used later by the parser to
read a token's sigil and modifiers. Positions run through all three.

## 2. What counts as a pair

Three pairs are counted: the string `“ ”`, the raw string `「 」`, and
the block comment `⟦ ⟧`. Four brackets are tracked for indentation.
`CLOSERS` turns the two tables around, so that a closer found anywhere
can be traced back to the opener it expects. `SPECIAL` is the scanner's
whole alphabet: the characters at which it has to stop and think. Every
other character is copied through untouched, which is what makes the
scan cheap.

```python
#| id: name-the-pairs-and-brackets
PAIRS = {"“": "”", "「": "」", "⟦": "⟧"}
BRACKETS = {"[": "]", "(": ")", "⟨": "⟩", "{": "}"}
CLOSERS = {close: opener for opener, close in (PAIRS | BRACKETS).items()}
PLACEHOLDER = "¶"
SPECIAL = re.compile(r"[“「⟦”」⟧;⍝]")
LINE_COMMENT = re.compile(r"(;+|⍝)[^\n]*")
```

The placeholder `¶` is one character on purpose. A string of any length
becomes one token for the grammar, and the parser asks the stash, not
the code, what the string said.

## 3. The pass, from the top

Pre-lexing is the two halves in sequence. The first returns the code and
the origin of each of its characters; the second only judges, and either
returns nothing or raises.

```python
#| id: prelex-a-source
def prelex(source: str, start: int = 0, end: int | None = None) -> Prelexed:
    """
    Pre-lex source[start:end] (all of it by default) to code the grammar
    reads, ending in a newline. Refuses a pair never closed, a closer
    with no opener, and loose indentation.
    """
    lexed = pairs(source, start, end)
    strict(source, lexed.code, lexed.origin)
    return lexed
```

The `start` and `end` arguments exist for the string reader: an
interpolated `⟨ ⟩` inside a string is code again, and is pre-lexed as a
slice of the same source, so its offsets need no translation.

## 4. Counting one pair

Here is the counting the grammar cannot do. Only the opener's own pair
moves the depth; a `「` inside a `“ ”` string is just a character. That
is the whole reason strings and comments cannot overlap: each is closed
by its own closer and blind to the others.

```python
#| id: count-one-pair
def counted(text: str, at: int, close: str, end: int) -> int | None:
    """
    The offset just past the closer that balances the opener at `at`, or
    None if none does before `end`. Only the opener's own pair is
    counted.
    """
    opener, depth, j = text[at], 1, at + 1
    while j < end and depth:
        depth += (text[j] == opener) - (text[j] == close)
        j += 1
    return None if depth else j
```

## 5. Code that remembers where it came from

The output of the first half is not a string but a string with a
shadow. Every character written gets the source offset it came from,
and the list of offsets is one longer than the code, so that the end of
the code has an origin too. A placeholder or a pad has no source
character of its own; it borrows the offset of the opener it replaces.

```python
#| id: write-code-with-origins
class _Code:
    """
    The code being written, each character with its source offset.
    """

    def __init__(self) -> None:
        self.chars: list[str] = []
        self.origin: list[int] = []
        self.stash: dict[int, Stashed] = {}

    def put(self, text: str, at: int, verbatim: bool = True) -> None:
        """
        Append text from source offset `at`; a pad or placeholder keeps
        `at` for every char.
        """
        self.chars.extend(text)
        self.origin.extend(
            at + k if verbatim else at for k in range(len(text))
        )

    def at_line_start(self) -> bool:
        """
        Nothing but tabs written since the last newline.
        """
        for char in reversed(self.chars):
            if char != "\t":
                return char == "\n"
        return True
```

What a placeholder stands for is kept beside the code, keyed by the
placeholder's offset in it. The stash records the interior as a range
of the source, not as a copy, and remembers how deep the line was
indented, because a string's continuation lines drop that many tabs.

```python
#| id: record-a-stashed-string
@dataclass(frozen=True)
class Stashed:
    """
    A string's interior, [start, end) in the source: `str` interpolates
    ⟨ ⟩, `raw` does not. depth is the tabs before the line it opens on,
    which its continuation lines drop (S26).
    """

    kind: Literal["str", "raw"]
    start: int
    end: int
    depth: int
```

When the scan is done, the three lists are frozen into the record the
rest of the walker reads.

```python
#| id: record-the-prelexed-code
@dataclass(frozen=True)
class Prelexed:
    """
    Code for the grammar, the source offset of each of its characters
    and of its end, and the string each placeholder stands for, by the
    placeholder's offset in the code.
    """

    code: str
    origin: tuple[int, ...]
    stash: dict[int, Stashed]
```

## 6. The scan

The scan jumps from one special character to the next. What lies
between is copied with its origins; what starts at the special
character is handed to the next chunk.
The code always ends in a newline, whose origin is the end of the
slice.

```python
#| id: scan-for-pairs
def pairs(
    source: str,
    start: int = 0,
    end: int | None = None,
    special: re.Pattern[str] = SPECIAL,
) -> Prelexed:
    """
    Stash the strings and drop the block comments of source[start:end],
    ending the code in a newline; `special` names the characters that
    open or close a pair or a line comment. Refuses a pair never closed
    and a closer with no opener; indentation is not looked at.
    """
    stop = len(source) if end is None else end
    code, at = _Code(), start
    while at < stop:
        found = special.search(source, at, stop)
        upto = found.start() if found else stop
        code.put(source[at:upto], at)
        at = _special(source, upto, stop, code) if found else stop
    code.put("\n", stop)
    return Prelexed("".join(code.chars), (*code.origin, stop), code.stash)
```

A special character is one of three things. An opener starts a pair. A
closer found here closes nothing, since a balanced closer is consumed
by its opener and never seen by the scan; that is an error. Anything
else is a line comment, copied to the end of its line so that the
grammar can still see it.

```python
#| id: write-a-special-character
def _special(source: str, at: int, end: int, code: _Code) -> int:
    """
    Write what starts with a special character at `at`; return where the
    next write starts.
    """
    char = source[at]
    if char in PAIRS:
        return _pair(source, at, end, code)
    if char in CLOSERS:
        raise FplError(Lines(source).span(at), f"{char} closes nothing")
    newline = source.find("\n", at, end)
    after = end if newline < 0 else newline
    code.put(source[at:after], at)
    return after
```

A pair is where the two kinds part ways. A block comment that opens a
line vanishes together with the spaces after it, so that it cannot
leave a space where the indentation rule expects a tab; anywhere else it
leaves one space, so that the tokens on either side stay apart. A string
gets a space in front if it touches the previous token, a stash entry,
and the placeholder.

```python
#| id: write-a-pair
def _pair(source: str, at: int, end: int, code: _Code) -> int:
    """
    Write the string or comment opening at `at`; return the offset after
    its closer.
    """
    opener = source[at]
    after = counted(source, at, PAIRS[opener], end)
    if after is None:
        raise FplError(Lines(source).span(at), f"{opener} never closed")
    if opener == "⟦":
        if code.at_line_start():
            return (
                len(source[after:end])
                - len(source[after:end].lstrip(" "))
                + after
            )
        code.put(" ", at)
        return after
    if code.chars and code.chars[-1] not in " \t\n":
        code.put(" ", at)
    line = source.rfind("\n", 0, at) + 1
    depth = len(source[line:at]) - len(source[line:at].lstrip("\t"))
    code.stash[len(code.chars)] = Stashed(
        "str" if opener == "“" else "raw", at + 1, after - 1, depth
    )
    code.put(PLACEHOLDER + " ", at, verbatim=False)
    return after
```

## 7. Holding indentation strict

The second half reads the code line by line, and it reads code, not
source: by now no string can hide a bracket and no comment can hide a
tab. Two rules hold. Outside brackets, a line may be indented only by
tabs. Inside brackets, a line may wrap as it likes, but it may not
dedent below the line that opened the bracket, because then the eye
and the grammar would disagree about where the block ends.

The rules are checked in code offsets, and an error has to be reported
in source positions. Rather than thread the translation through every
check, a refusal is raised as a code offset and placed in the source
once, at the top.

```python
#| id: carry-a-refusal
class _RefusalError(Exception):
    """
    A strictness refusal at a code offset, before it is placed in the
    source.
    """

    def __init__(self, offset: int, message: str) -> None:
        super().__init__(message)
        self.offset = offset
        self.message = message
```

The entry of the second half is the one place that translates. It
builds the line table once, gives `_lines` a way to name the source line
of a code offset, and turns a refusal into the error the author sees.

```python
#| id: hold-the-code-strict
def strict(source: str, code: str, origin: tuple[int, ...]) -> None:
    """
    Hold the code to strict indentation, reporting a refusal at its
    place in the source.
    """
    lines = Lines(source)
    try:
        _lines(code, lambda offset: lines.span(origin[offset]).line)
    except _RefusalError as refusal:
        raise FplError(
            lines.span(origin[refusal.offset]), refusal.message
        ) from None
```

Each line is measured, held to the two rules, and then its brackets are
pushed and popped. The stack remembers, for every open bracket, the
depth of the line that opened it; that depth is the floor for every
line until the bracket closes. A bracket still open at the end of the
code is the last refusal.

```python
#| id: refuse-loose-lines
def _lines(code: str, line_of: Callable[[int], int]) -> None:
    """
    Refuse leading spaces outside brackets, and a dedent below the line
    of a bracket still open; the dedent is reported at the dedenting
    line and names the opener's line.
    """
    open_: list[tuple[str, int, int]] = []
    base = 0
    for line in code.split("\n"):
        depth = len(line) - len(line.lstrip("\t"))
        if not open_ and line[depth : depth + 1] == " ":
            raise _RefusalError(base + depth, "indentation must be tabs")
        if open_ and line.strip() and depth < open_[-1][2]:
            opener, opened, _ = open_[-1]
            message = (
                f"dedent below line {line_of(opened)}, "
                f"but its {opener} is still open"
            )
            raise _RefusalError(base + depth, message)
        _brackets(line, base, depth, open_)
        base += len(line) + 1
    if open_:
        raise _RefusalError(open_[-1][1], f"{open_[-1][0]} never closed")
```

A line comment may say anything, brackets included, so it is cut off
before the brackets are counted.

```python
#| id: track-the-brackets-of-a-line
def _brackets(
    line: str, base: int, depth: int, open_: list[tuple[str, int, int]]
) -> None:
    """
    Track the brackets of one code line, its line comment aside, on the
    stack of open ones; refuse a closer that closes nothing or not the
    latest opener. Offsets are into the code.
    """
    body = LINE_COMMENT.split(line, maxsplit=1)[0]
    for n, char in enumerate(body):
        if char in BRACKETS:
            open_.append((char, base + n, depth))
        elif char in CLOSERS and not open_:
            raise _RefusalError(base + n, f"{char} closes nothing")
        elif char in CLOSERS and open_[-1][0] != CLOSERS[char]:
            raise _RefusalError(
                base + n, f"{char} does not close {open_[-1][0]}"
            )
        elif char in CLOSERS:
            open_.pop()
```

## 8. Where an offset is

Every error so far has needed one thing: a source offset turned into
the line and column an editor shows. The line starts are found once,
and each lookup is a binary search.

```python
#| id: place-an-offset
class Lines:
    """
    Offsets into a source as the 1-based line and column an editor
    shows.
    """

    def __init__(self, source: str) -> None:
        self.starts = [0] + [
            n + 1 for n, char in enumerate(source) if char == "\n"
        ]

    def span(self, offset: int) -> Span:
        """
        The line and column of a source offset; the end is just past the
        last line.
        """
        line = bisect_right(self.starts, offset)
        return Span(line, offset - self.starts[line - 1] + 1)
```

## 9. A token's shape

The last piece runs after lexing, when the parser holds a token and
wants to know what kind of word it is. A token is an optional prefix
sigil, a body, and a tail of modifier marks. The marks are combining
accents written as separate characters, and they may only stand at the
end.

```python
#| id: name-the-shape-of-a-token
MODS = "\u00b4`\u00a8\u02dc\u207c\u02d9"
SHAPE = re.compile(rf"(->|→|\$|#|&|\.\./|\.\.)?([^{MODS}]*?)([{MODS}]*)")
NUMBER = re.compile(r"-?(\d+(\.\d+)?|∞|π)")
```

The body decides the kind: nothing at all is a bare modifier, a numeral
is a number, a slash makes a path, and anything else is a name.

```python
#| id: read-the-shape-of-a-token
def shape(token: str) -> tuple[str, Kind, tuple[str, ...], str] | None:
    """
    A token's prefix sigil, kind, body (a path's segments) and suffix
    modifiers, or None when a modifier stands anywhere but at the end.
    """
    match = SHAPE.fullmatch(token)
    if match is None:
        return None
    prefix, body, mods = match.group(1) or "", match.group(2), match.group(3)
    kind: Kind = (
        "modifier"
        if not body
        else "number"
        if NUMBER.fullmatch(body)
        else "path"
        if "/" in body
        else "name"
    )
    return (
        prefix,
        kind,
        tuple(body.split("/")) if kind == "path" else (body,),
        mods,
    )
```

```python
the text.

token, its interior left in the source for the pair's reader; a block
comment becomes nothing. Indentation is then held strict: tabs only, and
no bracket left open across a dedent below the line that opened it. The
affix pass reads a token's shape after lexing. Positions stay in the
source: every code character keeps its origin.
"""
```
