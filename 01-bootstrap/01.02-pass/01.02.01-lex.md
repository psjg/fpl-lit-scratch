# 01.02.01 Lex

A grammar reads tokens. It does not count. FPL asks for two kinds of
counting that Lark's lexer cannot do. Strings and block comments nest,
each by its own pair only: `“a “b” c”` is one string, and a `”` inside
`「 」` is text. Indentation is strict: a line is indented by tabs, and a
bracket left open may not be followed by a dedent below the line that
opened it. So a counter written by hand runs first. It reads the source
once, writes the code the grammar will read, and remembers for every
character it writes where in the source that character came from.
[01.02.02-parse](01.02.02-parse.md) starts from that code.

The file `fpl/lex.py` is tangled from this page. The order below is the
reader's; the plan in the first section puts the pieces in the order
Python needs.

## Two phases

Pre-lexing is two passes over the text. The first, `pairs`, stashes the
strings and drops the block comments. The second, `strict`, holds what
is left to strict indentation. The order matters: a tab or a bracket
inside `“ ”` is text, so the second pass must never see the inside of a
string.

```python
<<Functions of the pre-lexer>>=
def prelex(source: str, start: int = 0, end: int | None = None) -> Prelexed:
    """
    Pre-lex source[start:end] (all of it by default) to code the grammar
    reads, ending in a newline. Refuses a pair never closed, a closer
    with no opener, and loose indentation.
    """
    lexed = pairs(source, start, end)
    strict(source, lexed.code, lexed.origin)
    return lexed
```

What comes out is three things. `code` is the text the grammar reads.
`origin` holds one source offset for every character of `code`, and one
more for its end, so an error the parser finds at code offset `k` is
reported at `origin[k]` in the source. `stash` maps the offset of each
placeholder in `code` to the string it stands for.

A stashed string is not copied. Its interior stays in the source, and
the stash keeps only where it starts and ends, so the parser reads it
there with the rules of its own pair: `“ ”` interpolates `⟨ ⟩`, `「 」`
does not. `depth` is the number of tabs before the line the string
opens on; a string that runs over several lines drops that many tabs
from each continuation line. For `“a” 「b」` the stash is
`{0: Stashed("str", 1, 2, 0), 3: Stashed("raw", 5, 6, 0)}`.

```python
<<Types of the pre-lexer>>=
@dataclass(frozen=True)
class Stashed:
    """
    A string's interior, [start, end) in the source: `str` interpolates
    ⟨ ⟩, `raw` does not. depth is the tabs before the line it opens on,
    which its continuation lines drop (S26).
    """

    kind: Literal["str", "raw"]
    start: int
    end: int
    depth: int
```

The whole is defined after its part, because Python reads the
annotation `dict[int, Stashed]` when the class is made.

```python
<<Types of the pre-lexer>>+=

class Prelexed:
    """
    Code for the grammar, the source offset of each of its characters
    and of its end, and the string each placeholder stands for, by the
    placeholder's offset in the code.
    """

    origin: tuple[int, ...]
    stash: dict[int, Stashed]
```

## Places in the source

An error names a line and a column, as an editor shows them. The
pre-lexer works in offsets. `Lines` keeps the offset where each line
starts; the line of an offset is then one binary search away.

```python
<<Types of the pre-lexer>>+=
class Lines:
    """
    Offsets into a source as the 1-based line and column an editor
    shows.
    """

    def __init__(self, source: str) -> None:
        self.starts = [0] + [
            n + 1 for n, char in enumerate(source) if char == "\n"
        ]

    def span(self, offset: int) -> Span:
        """
        The line and column of a source offset; the end is just past the
        last line.
        """
        line = bisect_right(self.starts, offset)
        return Span(line, offset - self.starts[line - 1] + 1)
```

## Pairs

Three pairs are counted here, each against itself alone. Brackets are
pairs too, but they are counted later, by `strict`, once strings can no
longer hide them. Every closer, of a pair or a bracket, maps back to its
opener, so that a stray one can be named.

```python
<<Characters the pre-lexer knows>>=
PAIRS = {"“": "”", "「": "」", "⟦": "⟧"}
BRACKETS = {"[": "]", "(": ")", "⟨": "⟩", "{": "}"}
CLOSERS = {close: opener for opener, close in (PAIRS | BRACKETS).items()}
```

The scan looks only for the characters that start or end something: the
openers and closers of the three pairs, and the two line comments, `;`
and `⍝`. A line comment matters because a `“` inside it opens nothing.

```python
<<Characters the pre-lexer knows>>+=
SPECIAL = re.compile(r"[“「⟦”」⟧;⍝]")
```

The scan itself is a loop. Copy the plain run up to the next special
character as it is, let `_special` write whatever starts there, and go
on from where it says. At the end comes a newline whose origin is the
end of the text, so the grammar always sees a final newline and an
error at the very end still has a place.

```python
<<Functions of the pre-lexer>>+=
def pairs(
    source: str,
    start: int = 0,
    end: int | None = None,
    special: re.Pattern[str] = SPECIAL,
) -> Prelexed:
    """
    Stash the strings and drop the block comments of source[start:end],
    ending the code in a newline; `special` names the characters that
    open or close a pair or a line comment. Refuses a pair never closed
    and a closer with no opener; indentation is not looked at.
    """
    stop = len(source) if end is None else end
    code, at = _Code(), start
    while at < stop:
        found = special.search(source, at, stop)
        upto = found.start() if found else stop
        code.put(source[at:upto], at)
        at = _special(source, upto, stop, code) if found else stop
    code.put("\n", stop)
    return Prelexed("".join(code.chars), (*code.origin, stop), code.stash)
```

The code is written into two lists that grow together, one character
and one origin at a time. Copied text keeps consecutive offsets. A pad
or a placeholder is not in the source, so each of its characters takes
the offset of the opener that caused it. The test that every character
of `code` either equals the source at its origin or is such a pad lives
in `tests/test_lex.py`.

```python
<<Types of the pre-lexer>>+=
class _Code:
    """
    The code being written, each character with its source offset.
    """

    def __init__(self) -> None:
        self.chars: list[str] = []
        self.origin: list[int] = []
        self.stash: dict[int, Stashed] = {}

    def put(self, text: str, at: int, verbatim: bool = True) -> None:
        """
        Append text from source offset `at`; a pad or placeholder keeps
        `at` for every char.
        """
        self.chars.extend(text)
        self.origin.extend(
            at + k if verbatim else at for k in range(len(text))
        )

    def at_line_start(self) -> bool:
        """
        Nothing but tabs written since the last newline.
        """
        for char in reversed(self.chars):
            if char != "\t":
                return char == "\n"
        return True
```

A special character starts one of three things. An opener starts a pair,
which `_pair` writes. A closer here has no opener, since a pair's own
closer is consumed with it, and is refused. Anything else is a line
comment, copied as it is to the end of its line. The grammar keeps
comments as tokens (`NOTE` and `DOC` in `fpl/grammar.lark`), so they
must reach it whole and in place.

```python
<<Functions of the pre-lexer>>+=
def _special(source: str, at: int, end: int, code: _Code) -> int:
    """
    Write what starts with a special character at `at`; return where the
    next write starts.
    """
    char = source[at]
    if char in PAIRS:
        return _pair(source, at, end, code)
    if char in CLOSERS:
        raise FplError(Lines(source).span(at), f"{char} closes nothing")
    newline = source.find("\n", at, end)
    after = end if newline < 0 else newline
    code.put(source[at:after], at)
    return after
```

Counting one pair is the whole nesting rule. The depth goes up on the
opener and down on its own closer; no other character counts. For
`“a “b” c”` the depth runs 1, 2, 1, 0, and the string ends at the last
`”`. A pair that never balances before `end` gives `None`.

```python
<<Functions of the pre-lexer>>+=
def counted(text: str, at: int, close: str, end: int) -> int | None:
    """
    The offset just past the closer that balances the opener at `at`, or
    None if none does before `end`. Only the opener's own pair is
    counted.
    """
    opener, depth, j = text[at], 1, at + 1
    while j < end and depth:
        depth += (text[j] == opener) - (text[j] == close)
        j += 1
    return None if depth else j
```

A pair is first counted to its closer; one that never closes is refused
at its opener. What is written then depends on the opener: a block
comment leaves almost nothing, a string leaves a placeholder.

```python
<<Functions of the pre-lexer>>+=
def _pair(source: str, at: int, end: int, code: _Code) -> int:
    """
    Write the string or comment opening at `at`; return the offset after
    its closer.
    """
    opener = source[at]
    after = counted(source, at, PAIRS[opener], end)
    if after is None:
        raise FplError(Lines(source).span(at), f"{opener} never closed")
    if opener == "⟦":

    <<Stash a string>>
```

A block comment that opens a line takes the spaces after it along, so
the line reads as if the comment had never been there and its
indentation is still the tabs before it. Anywhere else it becomes one
space, so that `a⟦x⟧b` stays two tokens.

```python
<<Drop a block comment>>=
if code.at_line_start():
    return (
        len(source[after:end])
        - len(source[after:end].lstrip(" "))
        + after
    )
code.put(" ", at)
return after
```

A string becomes one placeholder token followed by a space. A space is
put before it too when the code so far ends in something else, so the
placeholder never fuses with a neighbour. The stash entry is keyed by the
placeholder's offset in the code, which is the length of the code just
before it is written.

```python
<<Stash a string>>=
if code.chars and code.chars[-1] not in " \t\n":
    code.put(" ", at)
line = source.rfind("\n", 0, at) + 1
depth = len(source[line:at]) - len(source[line:at].lstrip("\t"))
code.stash[len(code.chars)] = Stashed(
    "str" if opener == "“" else "raw", at + 1, after - 1, depth
)
code.put(PLACEHOLDER + " ", at, verbatim=False)
return after
```

The placeholder is one character. The pads around it make it a token
of its own.

## Strict indentation

With the strings gone, every tab and every bracket left in the code is
real. The checks run on the code, where they are simple, and find their
refusals as code offsets; `strict` places each refusal back in the source
through `origin`, so the message points at what the author wrote.

```python
<<Functions of the pre-lexer>>+=
def strict(source: str, code: str, origin: tuple[int, ...]) -> None:
    """
    Hold the code to strict indentation, reporting a refusal at its
    place in the source.
    """
    lines = Lines(source)
    try:
        _lines(code, lambda offset: lines.span(origin[offset]).line)
    except _RefusalError as refusal:
        raise FplError(
            lines.span(origin[refusal.offset]), refusal.message
        ) from None
```

A refusal in flight carries only its code offset and its message.

```python
<<Types of the pre-lexer>>+=
class _RefusalError(Exception):
    """
    A strictness refusal at a code offset, before it is placed in the
    source.
    """

    def __init__(self, offset: int, message: str) -> None:
        super().__init__(message)
        self.offset = offset
        self.message = message
```

The code is read line by line, with a stack of the brackets still open.
Each entry is the opener, its code offset, and the depth of the line it
opened on. Two refusals are about the line itself; the brackets on it
are then pushed and popped. A bracket still open at the end is refused at
its opener.

```python
<<Functions of the pre-lexer>>+=
def _lines(code: str, line_of: Callable[[int], int]) -> None:
    """
    Refuse leading spaces outside brackets, and a dedent below the line
    of a bracket still open; the dedent is reported at the dedenting
    line and names the opener's line.
    """
    open_: list[tuple[str, int, int]] = []
    base = 0
    for line in code.split("\n"):
        depth = len(line) - len(line.lstrip("\t"))
        <<Refuse a space where a tab belongs>>
        <<Refuse a dedent below an open bracket>>
        _brackets(line, base, depth, open_)
        base += len(line) + 1
    if open_:
        raise _RefusalError(open_[-1][1], f"{open_[-1][0]} never closed")
```

Outside brackets a line is indented by tabs only. Inside them the author
may align with spaces, since the line continues an expression.

```python
<<Refuse a space where a tab belongs>>=
if not open_ and line[depth : depth + 1] == " ":
    raise _RefusalError(base + depth, "indentation must be tabs")
```

Inside an open bracket a line may indent further, but not dedent below
the line that opened the bracket: that would close a block the bracket
is still part of. The refusal is reported at the dedenting line and
names the opener's line, which is the one to fix.

```python
<<Refuse a dedent below an open bracket>>=
if open_ and line.strip() and depth < open_[-1][2]:
    opener, opened, _ = open_[-1]
    message = (
        f"dedent below line {line_of(opened)}, "
        f"but its {opener} is still open"
    )
    raise _RefusalError(base + depth, message)
```

The brackets of a line are tracked on everything before its line
comment. A closer must close the latest opener; any other closer is
named with the opener it fails to close.

```python
<<Functions of the pre-lexer>>+=
def _brackets(
    line: str, base: int, depth: int, open_: list[tuple[str, int, int]]
) -> None:
    """
    Track the brackets of one code line, its line comment aside, on the
    stack of open ones; refuse a closer that closes nothing or not the
    latest opener. Offsets are into the code.
    """
    body = LINE_COMMENT.split(line, maxsplit=1)[0]
    for n, char in enumerate(body):
        if char in BRACKETS:
            open_.append((char, base + n, depth))
        elif char in CLOSERS and not open_:
            raise _RefusalError(base + n, f"{char} closes nothing")
        elif char in CLOSERS and open_[-1][0] != CLOSERS[char]:
            raise _RefusalError(
                base + n, f"{char} does not close {open_[-1][0]}"
            )
        elif char in CLOSERS:
            open_.pop()
```

A line comment runs from a run of `;` or from `⍝` to the end of the
line.

```python
<<Characters the pre-lexer knows>>+=
LINE_COMMENT = re.compile(r"(;+|⍝)[^\n]*")
```

## Shapes

The affix pass, after lexing, asks what a token is made of. A token is
an optional prefix sigil, a body, and a tail of modifier marks. The body
is a number, a path when it holds a `/`, a name otherwise, or nothing at
all, in which case the token is a bare modifier.

```python
<<Characters the pre-lexer knows>>+=
MODS = "\u00b4`\u00a8\u02dc\u207c\u02d9"
SHAPE = re.compile(rf"(->|→|\$|#|&|\.\./|\.\.)?([^{MODS}]*?)([{MODS}]*)")
NUMBER = re.compile(r"-?(\d+(\.\d+)?|∞|π)")
```

A modifier anywhere but at the end makes the token shapeless, and
`shape` says so with `None`.

```python
<<Functions of the pre-lexer>>+=
def shape(token: str) -> tuple[str, Kind, tuple[str, ...], str] | None:
    """
    A token's prefix sigil, kind, body (a path's segments) and suffix
    modifiers, or None when a modifier stands anywhere but at the end.
    """
    match = SHAPE.fullmatch(token)
    if match is None:
        return None
    prefix, body, mods = match.group(1) or "", match.group(2), match.group(3)
    kind: Kind = (
        "modifier"
        if not body
        else "number"
        if NUMBER.fullmatch(body)
        else "path"
        if "/" in body
        else "name"
    )
    return (
        prefix,
        kind,
        tuple(body.split("/")) if kind == "path" else (body,),
        mods,
    )
```
